# Changelog

Everything a user of Anything2MCP would notice, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) as [RELEASING.md](RELEASING.md) applies it.

The design's own history is in the [decision records](docs/decisions/README.md), and the work session by session is in the [journal](docs/journal/README.md).

## [Unreleased]

### Added

- On Windows, the desktop pack starts the application a desktop surface allows (`start: true`), by its declared path with its digest checked, when none of it runs, and waits for its window by the system's event of a window shown; one that shows no window by the deadline is stopped. On macOS a start still stops as `start_not_built` ([decision 0480](docs/decisions/0480-the-desktop-pack-starts-an-application-on-windows-by-the-event-of-a-window-shown-and-not-yet-on-macos.md)).
- A run's step trace now ends with its time marks: the whole attempt, and the calls the engine made to the policy engine, the scheduler, the session keeper, the ledger, and the loading of the compiled target, with their time. They are an optional entry, `marks`, of the trace's end line; the schema stays at version 1, a trace written before reads as before, and the marks are not in the signature. `trace export` writes them with the trace. The benchmark gains `call_overhead`, `warm_tab`, and `call_outside_run`, read from these marks.
- A canary can now run on a schedule of its own, apart from a watch. `anything2mcp canary create example_order_get --input '{"order_id": "A-100"}' --interval-seconds 3600 --ends-at ...` (`canary.create`) asks for one: one published read with a fixed input, at an interval, until an end. It sends nothing until its person confirms it on the engine's page (`canary.confirm`, a person's act). Each check is a read and never writes; when one finds that the system no longer matches what the target knows, every tool relying on the same knowledge stops before it sends anything, and a later check that passes lifts that. A canary goes on after a drift, ends when another version of its target is published, and is held to the limits and the budget share of watches. `canary get`, `canary list`, and `canary end` show and end them ([decision 0482](docs/decisions/0482-a-canary-runs-on-a-schedule-its-person-confirmed-and-sends-only-a-published-read.md)).

## [0.1.0] - 2026-11-25

The first published version, a **preview**, before version 1.0 ([decision 0476](docs/decisions/0476-version-0-1-is-a-preview-and-the-checks-a-person-makes-move-to-before-1-0.md)). Built and tested against the built-in test stands on Windows, macOS, and Linux. Until 1.0 a minor version may break. What this preview has not had yet:

- The presence prompt and the approval page have been passed by a person on Linux only. On macOS and Windows they are built and tested in CI with a stand-in for the person, and fail closed: an act that needs a person is not done when no prompt can be shown.
- The first hour, from an empty folder to a published tool an agent calls, is measured as machine time, not with a person at the keyboard.
- No copy test has been run from a Windows or a macOS machine, and nothing has been tried against a real business application.
- Not built: a shared server, plug-ins, MCP over HTTP, remote runners, ten of the twelve publish gates, and the drafting of writes.

### Added

- An agent can now be told when a watch records a change. Each watch is an MCP resource, `a2m://watches/{watch_id}/changes`, named as `resource` in every `watch.*` result: `resources/read` gives its changes after the URI's `after`, and in revision 2026-07-28 `subscriptions/listen` with the URI in `resourceSubscriptions` sends `notifications/resources/updated` each time the watch records one. `resources/templates/list` lists the template. Over REST, `GET /api/v1/watches/{watch_id}/changes` gives a page, or a stream of server-sent events that resumes from `Last-Event-ID` and stays open while the watch lasts. A watch of a read of a data store's file now reads it: the project folder of the ask is kept for its checks, which before stopped as `project_folder_missing`. A removed record is named by its key.
- A read whose page asks for its data by `POST`, which a person asserted with `read_asserted: true`, can now be tried, recorded, and made ready before its first publish. `anything2mcp assertion confirm example` (`assertion.confirm`) asks the person on the engine's page, past the computer's own prompt, to confirm each asserted request as the page shows it; after that, `draft try`, `fixture record`, and `draft ready` let that request through in an environment of kind `test`, and no other. An agent can only ask, and a change to the request's method, path, body, or address undoes the confirmation. No fixture or `status: verified` is written by hand any more on the way to a publish.
- A watch can compare a list record by record. A read declares its records over its list outputs with `records: {key: [order_id, item_code]}` in its operation file: each list output is a column, and the key names the columns that make a record's key. A watch of it reports `added`, `changed` with the outputs that differ, `unseen` once when a record leaves the view, and now `removed`, only between two checks whose driver stated it returned every record, which the data pack's list reads do from the row they ask for past their limit. An empty answer after records were seen removes nothing. `watch get` shows `compared: records` for such a watch ([decision 0472](docs/decisions/0472-a-read-declares-its-records-over-its-list-outputs-and-a-driver-states-whether-it-returned-every-record.md)).
- A capture of a person's use of pages drawn on the server now drafts more of what they show, each draft held with a question that says why: a list with no name whose items repeat one shape, read as its items; a record whose pages show their value as their one heading, read as that heading and the paragraphs below it in order; and a table with no name, by its headings, each read as a person reads it, without a table library's sort sentence. A request whose body only adds, on every visit after the first, what the page kept in the browser is counted in one shape, so its held page request is drafted. Screens gain a locator `heading: N` and `rows` read as `items: listitem` or `items: paragraph`; a list whose items differ in shape, and a heading with no words left once the sort words are off, are said by name as not drafted.
- Four actions that answered `action_not_built` are built. `anything2mcp rollback example --version 1.0.0` (`version.rollback`) makes another published version of a target the one that runs, earlier or later. It is a person's act: an agent's call goes to the person's page, and a call at a terminal raises the presence prompt. The audit records it, and the answer says the version is current only after the store is read back. Naming the version that already runs changes nothing and says so ([decision 0470](docs/decisions/0470-a-rollback-is-a-persons-act-and-moves-to-any-version-a-person-published.md)). `run trace` gives the run's own person a summary of its trace: each step's kind, outcome, and time, and each kept capture by its reference, with no value. `trace export` writes one run's evidence to `.anything2mcp/exports/<run>.json` in the project: its events, its step trace, and its text captures, with a manifest. An image, and any piece that still holds a registered secret, is left out and named there ([decision 0469](docs/decisions/0469-a-runs-trace-is-summarized-for-its-person-and-exported-as-one-file-in-the-working-folder.md)). `component list` shows each outside program an installed provider needs: where it was found, its digest, and whether the digest is one the manifest knows, or that it is missing, with what to do. The 22 actions still unbuilt each say what they wait on ([decision 0468](docs/decisions/0468-which-actions-with-no-handler-serve-one-machine-and-what-each-waits-on.md)).
- The Node client now works on Windows. It reaches the engine through the new process command `anything2mcp channel`, which opens the engine's pipe after the same check of its owner every command makes and then carries the client's bytes without reading them. Before this, `connect` refused there with `client_not_built`. The options `verifyPipeServer` and `sid`, and the exports `pipeName` and `windowsRuntimeDir`, are removed; `greet` is added ([decision 0466](docs/decisions/0466-the-node-client-on-windows-reaches-the-engine-through-the-channel-command.md)).
- A desktop surface may state `start: true`: on Linux, when none of its program runs, the desktop pack starts it in a run, by the path the target declares with its digest checked, waits for its window, and stops it if none appears; the publish page names the program it starts. A screen's action may state `key: enter` or `key: escape`, done on Linux as the element's own action bound to that key, never as a key sent to the screen. The scout's `desktop_probe` says, on all three systems, which program a desktop surface is, the digest of its file, how many of its controls have no name, and a support tier. On Windows and macOS a start and a key stop by name and do nothing ([decision 0467](docs/decisions/0467-the-desktop-pack-starts-an-application-a-surface-allows-does-an-action-by-a-key-the-element-binds-and-probes-its-reach.md)).
- Every package built for people to install now carries `THIRD-PARTY-NOTICES.txt`, the licence texts of every third-party crate compiled into the program: the wheel (beside `LICENSE` in its metadata), each npm platform package, and each standalone archive. The release workflow also builds a standalone archive per platform (`.tar.gz` for Linux and macOS, `.zip` for Windows) holding the same binary as that platform's wheel, with `a2m`, and gathers every file of a release with a CycloneDX bill of materials per platform and `SHA256SUMS`. When it publishes, it attests the build provenance of every file (check one with `gh attestation verify FILE --repo MHughesDev/anything2mcp`) and makes the release page before PyPI and npm. Nothing has been published yet ([decision 0464](docs/decisions/0464-the-release-carries-archives-a-notices-file-and-attested-provenance-and-a-check-holds-the-workflow-to-every-piece.md)).
- The action catalog now marks each of the 26 actions that have no handler `not built`, beside its phase, so a reader can tell which actions answer `action_not_built` without calling them. `trace.show` and `trace.export` have a row each, since only the first is built. A test names each unbuilt action with its reason, and fails when one gains or loses a handler without the list changing.
- An agent can now pin a published tool and tell the system's words from instructions. Each published tool in an MCP tool list carries `anything2mcp/digest` in its `_meta`, and `tool describe` gives it as `digest`: the SHA-256 of the tool's name, description, input schema, output schema, and annotations in canonical JSON. It changes when, and only when, one of those changes, not when the same files are published under another version. In the output schema `tool describe` returns, each output of an untrusted field type, the system's own free text, carries `x-anything2mcp-untrusted: true`, and no other output carries the key ([decision 0460](docs/decisions/0460-a-tools-digest-is-of-its-definition-as-published-and-the-untrusted-mark-sits-on-the-output-field.md)).
- The desktop pack reads a desktop application's windows as a GTK 3 dialog program shows them. A table whose column headers and cells are its own children, with no row between, is read by the column count the table states on Linux (AT-SPI's `Table` interface), and is never read when it states none: the read stops as `fingerprint_mismatch` and says why. A table with no name is drafted and found by its headings: its screen's `rows` has no `locate`. A labelled spin button that gives its value as text is drafted beside the window's other values. Windows of one shape whose titles differ in one word, such as `Order 1001` and `Order 1002`, are drafted as one screen reached by `Order {order_id}`, whose reads take `order_id` as their input and key, such as `orders_order_get`; one window's title never becomes a pattern, and a read over a title with a number in it says how to get one. A screen whose title holds a placeholder is read only (`desktop.title_write`). Every window the drafting rules draft nothing from is listed with a reason ([decision 0462](docs/decisions/0462-a-desktop-table-of-cells-is-read-by-the-column-count-it-states-and-a-title-two-windows-show-to-differ-becomes-a-pattern.md)).
- Every finding the web pack's drafting rules cover and draft nothing from now says why, in plain words, with what a person could do instead. The scout report's "not drafted" list shows, for the page a tab was sent to, such as `GET /orders`, that it was not made by a page by itself and that a screen read covers it, in place of the report's own fallback sentence; a request answered with another status or not in JSON, a write found by exploring, a request to an origin that is not the target's one `web` surface, an answer with no plain value, and a page with nothing a screen could locate each give their own reason.
- The faults of the first hour's second measurement are closed. An authoring or admin action that did its part and waits for a person's act, such as `ready` with every gate passed or `publish request`, is now `ok: true`, still with exit code 3 and the result's `state`; a write waiting for its approval, and any run resting on a person, stays `ok: false`, as does a refusal for want of a person ([decision 0458](docs/decisions/0458-an-answer-that-did-its-part-and-waits-for-a-person-is-ok.md)). `ready`'s text then starts `Succeeded:`. `ready --tools <name>` publishes only the reads named, and its `publish.tools` says what the version holds; `publish request`, `version publish`, and `test run` take `--tools` too, and the other drafts stay in the folder ([decision 0457](docs/decisions/0457-a-publish-of-named-tools-compiles-only-their-files.md)). The scout report lists a finding not drafted once, with a reason. The guidance lists the report's part names and says to run `init` first, and `init --help` says what it writes.
- A publish now names each breaking change of a tool. When a version is in force, the page a person publishes from shows "What breaks" right after where it leads and before the sign-ins and the tools: each tool whose change breaks an agent that calls it as it was (a tool gone, an input gone or now required, a type changed or its words narrowed, an output gone or now possibly absent, the effect risen, the hazard added or changed, the record's key changed), with why. The answer of `publish.request` carries the same under `breaking`, with `compared_with`, and a warning. The publish is not refused. `anything2mcp diff example --from 1.0.0 --to 2.0.0` (`version.diff`) classifies every tool of any two published versions the same way ([decision 0439](docs/decisions/0439-a-tools-name-carries-no-version-and-a-breaking-change-is-named-at-publish.md), [decision 0454](docs/decisions/0454-what-breaks-follows-where-it-leads-on-the-publish-page-and-is-named-in-the-answer-too.md)).

- A capture now ends as a scout does. `capture.stop`, once the capture has ended, drafts from what it found by each pack's rules, tries the drafted reads in the sandbox, and stores a scout's report, stage by stage; it answers with `report`, the report's reference, and `scout report --scout <id>` reads it. The report says it came from a capture, how it ended, the bounds it hit, and what it saw by kind, and that it covers only what the person used. - The faults of the first hour that three agents met are closed. A list flag takes a JSON array of text as well as the repeated flag, and its help says both; `draft delete` refuses a name with a comma with how a list is written. The web scout takes a page it was redirected to as that page, so the test application's order list is drafted at `/orders` and no longer at `/{key}`, and it tries a read by key on a key read off a list's column of the record's name, such as `order` for `order_id`. After `test run`, `next` names `binding promote` while the binding that would act is a draft. - On the passphrase route, the vault's salt file now records the derivation its root was made with: the algorithm, its version, the memory, the passes, and the lanes, on one line beside the salt. - What a release publishes is now held for every later release: each release keeps its API description, failure codes, closed and open vocabularies, the settings that are built with their types (every pack's among them; a setting marked not built is kept once its part is built, [decision 0455](docs/decisions/0455-a-release-keeps-only-the-settings-it-built-and-the-failure-codes-something-raises.md)), and a compiled target in `contracts/<version>/`, and a build that removes, renames, or changes one of them, or adds a member to a closed vocabulary, fails its checks unless the break is listed with its decision record; such a break is named in this changelog. No release is kept yet.
- `ready <target>`, the action `draft.ready`, takes every drafted read that was tried to a publish a person carries out. For each read the newest scout proved, or the agent tried with `draft.try` since, it records the offline test and fixture, promotes the read's first binding on that fixture's own trial, runs the publish gates, and asks a person to publish, answering `needs_person` with the page's link; each step is the existing action, for the same caller. A write, a pipeline, and a read no trial read through are listed as left alone, each with its reason and the call that moves it on; named in `tools`, one is refused before anything is done, as `not_made_ready_not_a_read` or `not_made_ready_untried`. Where the gates fail only for drafts left alone, `next` is their removal. A read-only tool is now `add`, `ready`, and a person's press ([decision 0443](docs/decisions/0443-draft-ready-asks-for-the-publish-and-takes-the-callers-own-trial.md)).
- A broker that asks for no sign-in can now be reached at any address, on another machine or in a container of its own, by IP address or by name: a connection that carries no credential goes to the surface's address. One that carries a credential still goes in plain text only to this machine's loopback address, and a broker that asks for TLS is still refused, as `transport_refused` ([decision 0435](docs/decisions/0435-a-plain-link-that-carries-no-credential-goes-to-the-surfaces-address.md)).
- A channel file can take a message's key from the subject it is published on, `key: {from: subject}`. The scout writes it for a stream that keys by subject, so a stream that keeps the latest value per subject is drafted with its list and no open question; it asks the key only of a stream that names neither a field nor the subject ([decision 0434](docs/decisions/0434-a-broker-that-keys-by-subject-gives-the-subject-as-a-channels-key.md)).
- A command now finds the running engine when its environment lacks the variable that named the engine's runtime folder. On macOS the runtime folder is `run` in the data folder, whatever `TMPDIR` says, so the system's cleaning of temporary folders no longer removes the engine's socket; an engine of an earlier version, whose socket is in the temporary folder, is not found until it stops. On Linux without `XDG_RUNTIME_DIR` the runtime folder is `/run/user/<uid>/anything2mcp` when that folder is the user's and closed. A command that still reaches another runtime folder than the engine's is refused `busy`/`engine_running` at once, with the engine's runtime folder, and on Linux the `XDG_RUNTIME_DIR` that leads there, named in the fix. A client profile named as a Windows device, such as `con`, is now refused as other names are.
- A capture a person begins now records their use of a web application: the web pack opens a window of the engine's own browser on the surface's address, sends nothing in it, and keeps the structure of each request the pages send, every method, and of each screen the person comes to, never a value. What it saw at least twice in one shape is drafted into the holding folder: a read by `GET` as a page request and a read, and a request by a method that may write, such as a search behind `POST`, as a page request whose effect is a question for the person, with its body's fields closed and no read. A request seen once, such as a save, is drafted as nothing, and the drafter says why.
- A target, an environment, or any other name that is one Windows keeps for a device (`con`, `prn`, `aux`, `nul`, `com0` to `com9`, `lpt0` to `lpt9`) is now refused on every system, and a dotted name with one as a part: the compiler stops with `kernel.name_malformed`, saying that Windows keeps the name for a device and suggesting another, such as `con_main`. Such a name compiled on Linux and macOS and could not become a folder on Windows ([decision 0431](docs/decisions/0431-a-name-that-windows-keeps-for-a-device-is-refused-on-every-system.md)).
- `capture.start` and `capture.stop` are built. An agent asks for a capture of its person's own use of a surface, and nothing records until the person begins it on the engine's page, past the presence prompt, where they are told that only structure is kept, never a value. The person ends it there with Stop recording, the agent ends it with `capture.stop`, or it ends at the bound its pack declares; `capture.stop` says which, and what was found is listed by `finding.list`. A press of a person's act whose prompt is not passed now names `presence_failed` in its answer ([decision 0433](docs/decisions/0433-a-capture-is-asked-for-by-capture-start-begun-by-its-person-on-the-page-and-held-in-the-engines-memory.md)).
- The file pack now refuses, by name, a file whose bytes are not on this machine, as a sync program leaves one: on Windows a cloud placeholder or a file marked offline, on macOS a dataless file. A read, a save, and a folder's read of its content stop with `policy`/`file_not_on_this_machine` before anything is opened, so the system never fetches the file through the sync program; a folder's list names it with the kind `not_on_this_machine`, its size, and its time, and no digest. Making the file kept on this machine, in the sync program's settings, lets it be read and written as any other ([decision 0430](docs/decisions/0430-a-file-whose-bytes-are-not-on-this-machine-is-refused-by-name-and-never-fetched.md)).
- `lint`, and the schema and lint gate of `test` and `version publish`, now warn of an operation of which every binding is `draft` or `retired`, as a binding is when it states no `status`, as `kernel.no_binding_may_act`: no call of its tool can run once published. Such a call now fails as `policy`/`no_binding_may_act` and offers no resume, where it stopped as `busy`/`no_binding` and told the agent to resume a run nothing would let go on ([decision 0440](docs/decisions/0440-an-operation-no-binding-of-which-may-act-is-warned-of-and-a-call-of-one-fails-for-good.md)).
- The scout no longer drafts an empty register map from a device's identification; its report says that a map comes from the device's published register map. A read drafted from a published map of a scaled register says in its description the places its scale gives, and the file formats reference gives the order of the twelve answers a device update's offline test takes ([decision 0441](docs/decisions/0441-a-device-draft-states-its-places-drafts-no-empty-map-and-its-update-fixture-is-documented.md)).
- The engine now watches the memory its browsers hold, counting every process each browser names as its own. A browser past 2 GiB is started afresh at the start of the next run, never during one; and while the browsers together hold 4 GiB or more, a call that needs to begin browser work starts nothing and answers `busy`/`memory_short`, with a wait of 30 seconds before asking again. Both limits are drafts until measured on long runs ([decision 0425](docs/decisions/0425-a-browsers-memory-is-measured-from-its-own-list-of-its-processes-and-past-a-ceiling-no-new-browser-work-starts.md)).
- A read made from inside a web page with the page's own data request (the `page_http` mode) now goes on when its browser is lost, as a read of the page's screens does: a new browser is started from the same profile, the run's session is placed into it, and the page is loaded again before the request, so no new sign-in is made. A write's request is never sent again this way ([decision 0428](docs/decisions/0428-a-page-request-read-whose-browser-is-lost-goes-on-as-a-ui-read-does.md)).
- A read through a web page whose browser is lost, because its process ended, now goes on: the next try of the step starts a new browser from the same profile, places the run's session into it, and reaches the page again by the read's own steps, so the sign-in holds and no new sign-in is made. - The lint that suspects a credential no longer warns about a path into an answer, such as `*.pin_order`, under a key that holds a secret's name as a word; it now also sees that word in a key written in camel case.
- `anything2mcp lint` (`draft.lint`) now fails with `lint_failed` when it lists a problem at the level of an error, as `try` already did; the problems are still in the result. A lint with warnings only still answers ok.
- The scout's text summary gives, for a discoverer that failed, the failure's code and its fix.

The stored report and its hash are unchanged.
- A page the engine only observes can no longer open a peer connection under the browser's older prefixed name; both names are refused.

- A web sign-in or step on a slow machine no longer stops with `unexpected_page` because the browser took over a quarter of a second to say what the page shows; the page is asked once and its answer is waited for within the step's own time ([decision 0288](docs/decisions/0288-whether-a-page-shows-a-sign-now-is-the-pages-own-answer-and-a-slow-answer-is-never-a-no.md)).

### Safety fixes

A safety review read each crate against its design and the ten rules, and every finding was confirmed with a test. These are the ones a user would see.

- A web tab being closed now fails every request its page still makes until the browser has let it go, and the page's own handlers of its leaving no longer run. Before, a request the page made as its tab closed, or a load still on its way, could reach an origin the tool does not declare: the browser sends unchanged every request it still holds for a tab it lets go ([decision 0461](docs/decisions/0461-a-tab-being-closed-fails-every-request-until-the-browser-detaches-it.md)).
- An observing tab now fails a `GET`, `HEAD`, or `OPTIONS` that carries a header overriding its method (`X-HTTP-Method-Override`, `X-HTTP-Method`, or `X-Method-Override`, in any letter case), before it leaves the browser, and reports it as it reports any request that may write. Before, such a request passed as a read, and a system that honours the header could have written ([decision 0270](docs/decisions/0270-the-http-pack-sends-an-asserted-read-only-from-a-published-version-and-bounds-what-it-leaves-running.md)).
- An observing tab now also fails a read whose address's query carries a `_method` entry (any letter case, percent-encoded, in any position, with any value or none), before it leaves the browser: a server may take its method from the query, and a `GET` to `/items/7?_method=DELETE` may delete ([decision 0270](docs/decisions/0270-the-http-pack-sends-an-asserted-read-only-from-a-published-version-and-bounds-what-it-leaves-running.md)).
- A session signed in under a target's drafts is no longer renewed without its person after the engine restarts: the session's record now says whether its sign-in was declared by drafts or by a published version, and a session kept before this change counts as made under drafts, so its person signs in once more ([decision 0374](docs/decisions/0374-a-sessions-mark-that-it-was-made-under-drafts-is-kept-in-its-record.md)).
- A jump of the machine's clock no longer stops running work: a lease is measured on the steady clock, so a clock set forward no longer declares every runner lost, and one set back no longer keeps a dead runner's job ([decision 0360](docs/decisions/0360-a-lease-is-measured-on-the-steady-clock-and-another-persons-run-is-not-found.md)).
- A run killed after its write was verified and before it completed is now completed by a resume, which hands back the outputs the read-back showed; before, every resume stopped with `output_unexpected`, and the run went on showing `runner_lost`. A stopped run now shows the failure that stopped it last. The engine refuses to open a half-migrated store, one that holds a later migration without an earlier one or what a migration makes without its record, with `store_version_unsupported` ([decision 0352](docs/decisions/0352-the-faults-of-the-kernels-own-parts-as-proven-and-what-a-verified-record-keeps.md)).
- A drafter leaves out a field whose name perhaps names a secret (`api_token`, `accessToken`), not only one it names for certain.
- The vault: a passphrase of fewer than 16 bytes is refused (`vault_passphrase_too_short`). Two engines starting together on a fresh installation make one root key. A session that was revoked cannot be brought back by a restore that arrives late ([decision 0138](docs/decisions/0138-the-vault-and-the-session-keeper-after-their-safety-audit.md)).
- The redactor finds a secret across the pieces of a stream, in hexadecimal in either letter case, in base64 with line breaks, in character references, and as a number. A number that holds a secret is shown as `[redacted]`.
- The engine: a write that was sent stays in doubt until it is read back, whatever failed after it, and is reconciled and never sent again. A value that holds the redaction mark is never sent (`argument_masked`), and a write whose values hold a registered secret is refused. The lease is checked at the commit point ([decision 0147](docs/decisions/0147-the-engine-after-its-safety-audit.md)).
- Runs: a run is its person's alone, and anyone else is told there is no such run. A run whose stored call cannot be read is not run (`run_call_unreadable`). A proof of presence older than two minutes is refused.
- The provider contract: a file is written under a random name, only where nothing stands, and never through a link. A program's digest is checked at every start, and on Linux the file that was checked is the file started. A pack's manifest may not name a program by a relative path.
- The HTTP pack: a write answered by a redirect to another origin, by an answer too large to read, or by one that cannot be read is in doubt and reconciled, and was settled as unsent before. A write that sends a version is refused when the version was not read (`stale`, `version_not_read`). An API description is read within bounds, and one past them is refused (`description_too_large`). A body that is not JSON is `drift` ([decision 0139](docs/decisions/0139-a-write-that-was-sent-is-never-settled-by-an-answer-that-is-not-the-applications-verdict.md)).
- The command pack: a program a group can write, or reached through a folder or link another user can write, is refused. A value that begins with `@`, and every form of a flag that runs its value, are refused. The new lint rules `command.secret_variable`, `command.secret_literal`, and `command.secret_argument` refuse a credential written into a command file ([decision 0140](docs/decisions/0140-the-command-pack-after-its-safety-audit.md)).
- The data pack: a statement is one plain read or one keyed write, and `ATTACH`, `PRAGMA`, `VACUUM`, and the like are refused. A read-back must be written `effect: read` with `form: table`; a target whose read-back was a hand-written read does not compile until it is. A write that cannot know what it reaches stops ([decision 0141](docs/decisions/0141-the-data-pack-holds-a-statement-to-one-read-or-one-keyed-write-and-a-connection-to-one-file.md)).
- The file pack: a document that a binding writes must state `may_be_open`. A text value for delimited text that begins with `=`, `+`, `-`, or `@` is refused (`value_begins_formula`) unless its field says `may_begin_formula: true`. A link at a document's name is refused, and a file left by a killed save is never used or removed ([decision 0149](docs/decisions/0149-the-file-pack-after-its-safety-audit.md)).
- The stream pack: a take records the whole message before it acknowledges. An empty look is "absent" only where the log was fully covered. A refusal in words the protocol does not define leaves a write in doubt. A field of text from a message must be marked untrusted, or the target does not compile (`stream.untrusted_unmarked`) ([decision 0150](docs/decisions/0150-a-take-records-its-message-before-it-acknowledges-and-an-answer-with-no-rule-leaves-a-write-in-doubt.md)).
- The device pack: a device that reports another serial than the one declared is refused (`device_identity_mismatch`), a write frame is recorded before it is sent, and a run past its frame ceiling is refused (`frame_budget_exceeded`) ([decision 0137](docs/decisions/0137-a-device-is-held-to-its-serial-a-write-frame-is-recorded-before-it-is-sent-and-a-run-has-a-frame-ceiling.md)).
- The MCP pack: a tool that the mapping says runs free text is never called, and a tool whose whole input is one string and that nobody reviewed is refused. The tool list is read again before every write. A member of a result that the mapping does not list is not passed on, and an output that is text must be marked untrusted ([decision 0136](docs/decisions/0136-the-mcp-pack-refuses-free-text-reads-its-list-again-before-a-write-and-passes-on-only-listed-members.md)).
- The browser engine: a tab stays on the origins its compiled target declares, a move a page starts in an observing tab is ended, every download is denied, a window a page opens is closed, the profile folder is made private to the user, and a password field is masked in the accessibility tree ([decision 0143](docs/decisions/0143-the-browser-engine-after-its-safety-audit.md)).
- The compiler and the compiled target: an operation that writes must declare a commit point, a draft never writes, a code list in which one text stands for two choices does not compile, and a compiled target that breaks a rule of a write is refused when it is read ([decision 0153](docs/decisions/0153-what-the-compiler-the-plan-and-the-redactor-hold-by-themselves-after-the-safety-audit.md)).
- The browser engine refuses every permission a page asks for, and reports a download or a pop-up it refused ([decision 0143](docs/decisions/0143-the-browser-engine-after-its-safety-audit.md)).
- The `ui` driver does not click a write over a state the page showed before the click, and a `submit` through `ui` is `irreversible`. Discovery never visits an address that looks like an action ([decision 0144](docs/decisions/0144-the-web-drivers-and-discoverers-after-their-safety-audit.md)).
- An approval is checked whole when a write begins, the `cautious` and `ci` presets are in force, and an approval's window is at most one day ([decision 0145](docs/decisions/0145-only-the-policy-engine-clears-a-write-and-the-ledger-reads-the-whole-clearance.md)).
- An operation that writes can no longer compile as a read, in any pack ([decision 0154](docs/decisions/0154-the-http-command-and-mcp-packs-state-what-saves-what-writes-and-which-key-is-sent.md), [0155](docs/decisions/0155-four-packs-state-what-saves-what-writes-and-when-their-guard-lifts.md)).
- Telemetry: a trace that was altered is reported as broken and gives no signature, and a log file is private to the user on Linux and macOS.
- A command that runs the engine itself holds the engine lock, so two engines never share a store; a second command waits up to twenty seconds, then ends `engine_unreachable` ([decision 0158](docs/decisions/0158-the-product-crate-and-the-local-engine-after-their-safety-audit.md)).
- Every caller of the local channel is an agent, so a person's act through a running engine is refused (`person_required`) until a page for it is built. A person who needs one stops the engine and acts in one process at a terminal.
- Approval pages work in a real browser, which sent no usable origin before.
- Project files that another account can change are ignored or refused (`path_not_allowed`), and a folder is searched for one only where only you or the administrator can write.
- Terminal output shows control characters as text, such as `\u{1b}`, and does not obey them.
- Each installation has its own key-store entry, named by its data directory, and the passphrase variable is removed from the engine's own process at start.
- The npm launcher runs only its own platform package, checks its name and version, and passes `SIGINT`, `SIGTERM`, and `SIGHUP` on to the program ([decision 0159](docs/decisions/0159-a-lost-answer-is-a-write-in-doubt-at-the-doors-and-in-the-clients.md)).
- A program started by a pack is never handed a variable of the engine's own (any name starting with `A2M_`) or one named for a credential; a launch that names one is refused (`engine_variable_refused`) and the lint rule is `command.engine_variable`.
- The browser engine: a closed tab is taken off the browser's count every time, so a browser with no tab open reads idle. A closed tab could stay counted, its page left open, when two threads heard its end in one order.
- A provider's process group whose leader is still exiting is ended without a false report that it could not be; macOS showed it.
- The data pack never uses a kept connection that now leads to another database, and refuses control characters in a statement (`connection_leads_elsewhere`, `store_file_replaced`) ([decision 0184](docs/decisions/0184-the-data-and-stream-packs-after-their-second-safety-audit.md)).
- The stream pack: once a publish or an acknowledgement has left, any error from the server leaves the write in doubt, never a refused session. A message delivered before and possibly held by another record is not taken (`message_may_be_held`); after an engine restart it waits until a person settles it. A scan says "absent" only of a log it read whole (`scan_inconclusive`) ([decision 0184](docs/decisions/0184-the-data-and-stream-packs-after-their-second-safety-audit.md)).
- A write of a record with no key whose answer was lost is never sent again on one "absent": it stays in doubt unless the binding's lookup is declared authoritative and says absent twice. An approval binds the binding that writes, and a write through another binding is refused (`approval_stale`) ([decision 0185](docs/decisions/0185-a-record-with-no-key-is-never-proved-absent-by-one-look.md)).
- A web read never runs in a tab that can write, in any posture. A `page_http` read is drafted only from a request that can be made again exactly. A token in a page's address or query is never kept. A key that holds an action word is refused, so a key such as `PAY-100` cannot be read by key; this is a limit, and may be stricter than it needs to be ([decision 0195](docs/decisions/0195-a-read-never-runs-where-the-page-may-write-and-a-page-keeps-only-its-structure.md)).
- No client takes a proxy from the environment, and no proxy is built: a `network.proxy` that is set is refused when the engine starts. A broker over plain TCP must be written as a loopback IP address (`127.0.0.1` or `[::1]`), not `localhost`. No build of the product, the workspace build included, offers the test broker's protocol ([decision 0197](docs/decisions/0197-no-client-takes-a-proxy-from-the-environment-and-stand-only-protocols.md)).
- A person's resume is never lost while a reconcile of the same run is ending. The engine's browser is started so that it takes no proxy and runs no extension; a machine-wide browser policy set by an administrator still applies ([decision 0201](docs/decisions/0201-a-resume-is-never-lost-the-browser-takes-no-proxy-and-no-product-build-speaks-a-stands-protocol.md)).
- A protected setting is loosened only by an installation settings file that no account but an administrator can change. Under `A2M_HOME`, or on Windows for now, such a loosening or lock is refused by name (decision 0241).
- `policy.two_person_irreversible` is protected: once on, no user file, variable, or flag turns it off.
- The engine makes its data, configuration, and cache folders its user's alone; `doctor` names one that others can enter.
- An answer to a page write that quotes the page's anti-forgery token is withheld whole, and the write is treated as in doubt. A page's refusal of the values of a write is no longer settled as not written. The tab that writes passes the page's service worker by (decision 0245).
- The HTTP pack reads a hostile XML or JSON answer within bounded work and never on the engine's async threads. Outside a live run it sends no request that may write, unless it is a declared test record's commit or a read the endpoint asserts, against a test environment. An endpoint marked `read` with a method that is not safe now needs `read_asserted: true`. A bytes answer that holds a registered secret gives neither its length nor its digest (decision 0249).
- A shadow binding is promotable only on matches over distinct inputs, in each environment its evidence must come from, against the verified binding that acts. `shadow report` shows the distinct inputs, the environments, and what the shadow's reads cost in requests, and promoting from shadow asks for presence. All of a call's shadows share one budget of time, and a shadow never asks for a sign-in or takes a caller's share of a rate budget (decision 0251).
- The MCP pack refuses to start a local server that another user could change, or that is a shell, an interpreter, a batch file, or a script: before, it checked only the program's digest (decision 0250).
- A command or a local MCP server is no longer given a variable that makes it load other code, such as `LD_PRELOAD` or `NODE_OPTIONS`.
- A script a target keeps runs only through an interpreter in its one known form, and only from a run folder no other user can change.
- A sign-in sends a credential only to an address the target declares. A sign-in that only drafts declare always goes to the person's page, which shows every address first, and a stored credential is used only under a published version. Each credential belongs to the target it was stored for; one stored before this change must be stored again. A refused password a person asked to try is not tried again by a later run (decision 0248).
- A stored password is set into the field that was checked, never typed into whatever holds focus, and the sign-in page is proven again before each value and before the press; a sign-in page that holds a frame is a named stop. A sign-in in a browser refuses an entry that also covers a surface of another kind, so a web session's cookies go to no other surface. Cookies are placed only for the run's own origins (decision 0254).
- The network readers remove a proxy password whatever characters it holds, and leave out a proxy or bypass list that may hold one, saying why. An answer about the network that does not come from the system itself is dropped unread, and a read that gets no answer ends after five seconds (decision 0261).
- Promotion through shadow counts only comparisons kept from this version on: a binding may need new distinct matching inputs before it can be promoted. The watch halves hold every watch to its end whatever its state, check a surface's budget share inside the confirmation, and take each check's records from its run's own stored result; a record that leaves the view is never reported as removed until a read can say it returned every record (decision 0262).
- A refused or unanswered stored password is no longer sent again after the engine restarts, and a session that a system keeps ending is signed in again by itself at most four times an hour; after that it waits for you to sign in (decision 0269).
- On Windows, a file the file pack creates is now confirmed under its name; before, every create there was reported as a possible commit.
- A program the product starts is refused when it is a language launcher, package runner, container runner, or build tool, or does not begin as this system's programs do; more variables that make a program load other code are refused, and a `PATH` given to a program may name only folders no other user can change (decision 0271).
- A program with no working folder of its own runs in a private folder made for that start, not in the shared temporary folder, and the folder is removed when it ends.
- On macOS an access-list entry that allows anything refuses a program; on Windows a program on a mapped share or a substituted drive letter is refused (both written, first run in CI).
- The HTTP pack sends a search behind POST outside a live run only from a published version, judges a method-override header or `_method` entry as the method it names, refuses a read once too many earlier reads are still running past their deadline, bounds text patterns and the text they match, and checks bytes answers for secrets written in UTF-16. The HTTP and MCP packs never send a header whose name begins `a2m-` (decision 0270).
- On macOS an installation settings file that the administrators' group may write, or whose access list allows another account, no longer loosens a protected setting; the file is checked and read as one opened file. `version.publish` refuses the version 0.0.0, which belongs to the drafts. A draft that calls its environment a test environment no longer gets a test record's treatment (decision 0273).
- The file pack's folder writes can no longer be led outside the root by a folder swapped for a link; a file is deleted only while it still holds the bytes that were read; a growing file's line that is not text is reported and passed instead of stopping every later read (decision 0272).
- On macOS and Linux the engine opens its runtime folder without following a link, then checks the folder and makes it private through that open folder; a link put in the folder's place is refused.
