# Changelog

Everything a user of Anything2MCP would notice, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) as [RELEASING.md](RELEASING.md) applies it.

The design's own history is in the [decision records](docs/decisions/README.md), and the work session by session is in the [journal](docs/journal/README.md).

## [Unreleased]

Pre-alpha. Built and tested against the built-in test stands, on Windows, macOS, and Linux; nothing has been tried against a real system, and nothing is published to a package registry.

### Added

- A provider package installed with pip is found through an entry in the group `anything2mcp.providers`, which is read as text: no package code is run or imported, and the search says where it looked. `anything2mcp.provider_site_folders()` names the folders. The engine does not list one yet.

- Tests now check, through the real program, that a secret survives an engine restart, that a wrong passphrase stops with `vault_passphrase_mismatch`, and that no secret reaches a file.
- The network the machine is on can be told from the facts it already holds (the gateway's hardware address and address, the subnet, the DNS domains, the DHCP server), compared across reconnections, and a destination is placed `via_gateway` only where a reach the person named for that network names a gateway. The part that keeps and names a reach is not built yet.
- A tool in an MCP tool list names its target and version in its `_meta`, under `anything2mcp/target` and `anything2mcp/version`.
- The benchmark suite measures a read that gains a request binding through shadow: it runs about 12 times faster than through its interface binding, with identical results (`promotion_speedup`).

- The scout reads the plain facts of a binary it is handed under `binary` (`scout run --files`): its format, system, and processor, the libraries it needs, what it imports and exports, a Windows file's version resource and manifest, a macOS file's entitlements and signing identifier and team, and where a Windows file carries a signature. It reads bytes only and starts nothing; a file of no known kind, one cut short, one that leads back to itself, and one not well formed are four named stops. Who signed a Windows file is not read yet ([decision 0317](docs/decisions/0317-the-command-packs-scout-reads-the-plain-facts-of-a-binary-it-is-handed.md)).
- A Cargo workspace of 29 crates: a neutral kernel (`a2m-*`), packs that each know one kind of system (`a2m-pack-*`), and the product crate.
- The `anything2mcp` command, and `a2m` as a short name for it.
- The kernel's shared vocabulary in `a2m-core`: archetypes, effect classes, hazards, failure classes, evidence levels, and the states of runs, records, sessions, and bindings, with a secret type that cannot be printed or serialized.
- Findings in `a2m-core`: what discovery returns, with a subject that can be told apart from any other, a level that cannot exceed what its source supports, and an identifier that is a digest of its content.
- Expressions in target files: a typed subset of CEL with no floating-point numbers. A decimal is written `decimal("1.5")` and takes `+`, `-`, `*`, and comparisons; division is `div(a, b, places, rounding)`.
- The vault: saved state is sealed with an authenticated cipher under a key held in the operating system's key store, with a passphrase route for machines that have none. On Linux this build has no operating-system key store and uses the passphrase route ([decision 0123](docs/decisions/0123-the-linux-secret-service-back-end-is-left-out-until-its-store-crate-is-maintained.md)).
- The redactor masks registered secrets in their encoded forms as well as their plain form.
- Target files load, lint, and compile to a hashed plan. The `example` target shows every file kind the kernel owns.
- Source readers for `csv`, `json`, and `xlsx`, with exact decimals and template fingerprints: an input whose structure matches no known template version is refused.
- The policy engine: nothing is allowed unless a rule allows it, a write needs a person's approval unless a pre-approval rule covers it, and a kill switch stops everything, a workspace, a target, or an operation.
- Sessions: one renewer for each session, and built-in sign-in providers for keys, tokens, basic and digest credentials, client certificates, and OAuth.
- A test application with a web interface, a JSON interface, a control interface, and injectable faults.
- The engine loop: a tool runs as a read, or as a verified write that records its intent first and reads the value back. A resume reads before it writes, so a write whose answer was lost is never sent twice.
- The action registry: every action in the [action catalog](docs/reference/action-catalog.md) is defined; those with a handler are served, and the rest answer `action_not_built`. One dispatcher records a policy decision for every call. Settings load in layers, with presets; an unknown key is refused, and no layer above the installation can loosen a protected setting.
- The REST interface: every action at one route, five resource aliases, and a generated OpenAPI 3.1 document.
- The HTTP pack: tools over a JSON interface, with verified writes. An OpenAPI description can be imported to draft endpoint entries. HTTPS is in a build with the feature `tls`, which is on by default since decision 0181.
- The command pack: a program can be a target. Arguments are typed, and no shell is used.
- The data pack: the `sql` mode over an embedded database file.
- The file pack: named places in delimited text, JSON, and workbooks. A write replaces the whole file in one step.
- The stream pack: bounded reads, a look that takes nothing, and keyed publishes. It speaks the NATS client protocol with JetStream, as set out below.
- The device pack: points over a Modbus TCP link, with ranges enforced before a frame is sent.
- The MCP pack: an upstream MCP server is reached through a mapping file, and a changed upstream tool is detected as drift.
- The browser engine: it starts an installed Chrome, Edge, or Chromium over the debugging pipe, locates elements by role and name, and has an observing tab that cannot write.
- Continuous checks on Windows, macOS, and Linux: formatting, lints, build, tests, a closed list of dependency licences, and a documentation audit.
- A release workflow that builds the pip package repeatably and publishes it with short-lived credentials, from a version tag or a manual start. It now builds eight platform wheels and a source distribution, checks all nine together, and publishes them through one gated job. It has run on pull requests and has never published.
- `anything2mcp serve` starts the local engine. A second engine on the same data directory is refused by name before it opens the store. A command is a thin client of a running engine, and runs the engine inside itself when none runs; `--in-process` asks for the second way and is refused while an engine runs ([decision 0131](docs/decisions/0131-the-front-doors-joined-serve-the-thin-client-and-the-bridge.md)).
- `anything2mcp bridge` carries MCP over standard input and output to a running engine. While none runs it answers each request with the failure and the next step, and carries the next request as soon as one does. The Python and TypeScript reference client libraries connected through it in both protocol revisions.
- `engine.stop`, the terminal's interrupt, and an idle engine with nothing waiting all stop `serve`.
- The pip package is a wheel for each of eight platforms, holding the program, the short name `a2m`, and a small Python client, and the npm package is a launcher with eight platform packages ([decision 0135](docs/decisions/0135-the-wheel-carries-the-binary-and-a-thin-client-and-npm-uses-platform-packages.md)). Both are built and tested in CI on Windows, macOS, and Linux; neither is published.
- On Linux the approval of a write asks the operating system's own prompt, through polkit, after the person opens the approval page. `serve` says in one line what approvals need on this machine, and the approval page shows the stored change it will approve. Nothing can be approved on macOS or Windows until the prompts below are run there ([decision 0142](docs/decisions/0142-the-presence-prompt-interface-and-the-linux-prompt-as-built.md)).
- An engine with a run waiting for a person, or for a runner, is held open when idle.
- Approvals can use Touch ID or the account password on macOS, and Windows Hello on Windows. They are written and not yet run on those systems ([decision 0146](docs/decisions/0146-the-macos-and-windows-presence-prompts-as-built.md)).
- The Python client has a typed method for every action, the npm package has a Node client with the same methods, the Python client runs on Windows over the engine's pipe, and `a2m.cmd` is the short command on Windows ([decision 0156](docs/decisions/0156-the-clients-are-generated-from-the-served-document-and-reach-windows-by-the-pipe.md)). The Windows parts are not yet run.
- The HTTP and MCP packs reach HTTPS surfaces in a build with the feature `tls`, which is on by default since decision 0181 (`--no-default-features` turns it off), and name a failed certificate or handshake (`certificate_untrusted`, `certificate_name_mismatch`, `certificate_expired`, `certificate_not_verified`, `tls_handshake_failed`) ([decision 0157](docs/decisions/0157-tls-is-switched-on-with-the-provider-stated-in-each-client.md)).
- `secret set --stdin` reads the secret from standard input, so it is in no argument and no output.
- A pipeline's source file is given to `tool.call` as a path under the project's `sources/` folder, or as rows, and is stored with the run so that a resume reads the bytes it started with.
- A run's events can be followed over REST, as a page or as a stream, at `GET /api/v1/runs/{run_id}/events`, and an MCP caller that asks for progress gets one message for each step the run takes. The result of a call carries the following call as `next` in its structured content.
- `tool.search` can list tools in full, twenty to a page.
- A device's serial can be declared for each environment, and a write to a device that has none declared is refused.
- A call of `tool.call` may carry an idempotency key, and the same call made again with it gives back its run, finished or not, marked `repeated`; the same key with another call is refused (`idempotency_key_reused`) ([decision 0160](docs/decisions/0160-an-idempotency-key-gives-back-its-run-and-run-list-shows-a-callers-own-runs.md)).
- `run.list` lists your own runs, newest first, twenty to a page, and `anything2mcp run list` and `GET /api/v1/runs` serve it.
- When an answer is lost after a request may have reached the engine, the command line, the bridge, and both client libraries report `answer_lost` and say it is not safe to retry; they used to say to run it again ([decision 0159](docs/decisions/0159-a-lost-answer-is-a-write-in-doubt-at-the-doors-and-in-the-clients.md), [0158](docs/decisions/0158-the-product-crate-and-the-local-engine-after-their-safety-audit.md)).
- A failure shows what the system itself said, apart from the engine's own sentence and marked as the system's words, in the result, in the MCP error, and in the terminal, where control characters are shown as escapes ([decision 0161](docs/decisions/0161-the-plan-and-the-engine-after-the-packs-were-built.md), [decision 0176](docs/decisions/0176-the-action-registry-takes-up-the-kernels-second-pass.md)).
- A write that cannot be read back, such as a take from a queue, a publish with no read-back, or a device command, ends as "accepted by the system, not read back". It is never called verified, only an operation declared `irreversible` may end this way, and the approval page and the result count such records ([decision 0161](docs/decisions/0161-the-plan-and-the-engine-after-the-packs-were-built.md), [decision 0172](docs/decisions/0172-the-ledger-ends-a-record-on-an-acknowledgement-and-keeps-what-the-system-said.md), [decision 0176](docs/decisions/0176-the-action-registry-takes-up-the-kernels-second-pass.md)).
- A call that is given back an earlier run that has not finished (running, waiting for a person, or stopped and resumable) is marked `earlier_run`, with a warning that names the run's state ([decision 0176](docs/decisions/0176-the-action-registry-takes-up-the-kernels-second-pass.md)).
- A person's act that an agent asks for, such as publishing a version, is carried out on a page of the local person surface. The agent is told a person is needed and given the link, the page shows exactly what will be done, and the person's press and the operating system's prompt carry it out ([decision 0163](docs/decisions/0163-a-persons-act-an-agent-asks-for-is-carried-out-on-a-page-of-the-person-surface.md)).
- These authoring actions are served through a running engine, in any door: `target.list`, `target.status`, `draft.read`, `draft.write`, `draft.try` (drafted reads only), `discover.run`, `finding.list`, `finding.describe`, `unknown.list`, `test.run`, and `publish.request`. `init` is a command and writes `anything2mcp.toml`, `AGENTS.md`, `.gitignore`, and `targets/`, and keeps any that exist ([decision 0164](docs/decisions/0164-the-authoring-actions-served-through-the-engine.md)).
- `target.probe`, `auth.detect`, `scout.run`, and `scout.report`: the scout identifies each surface, discovers, drafts reads by each pack's rules, tries the drafted reads in the sandbox, and ends with a report. Each stage is stored, so a stopped scout continues. The report is hashed data, two scouts of the same state give the same hash, and every text the system gave is kept apart and marked ([decision 0170](docs/decisions/0170-the-scout-identifies-each-surface-with-one-discovery-job-and-stores-each-stage.md), [decision 0171](docs/decisions/0171-the-scouts-report-is-hashed-data-with-the-systems-words-kept-apart.md)). Proven against the test application; not yet shown against the shipped packs. The scout's budget and the comparison of each pack's own rule are not built.
- `anything2mcp engine start` starts the engine detached, and says whether it did. A command, or the bridge, that finds no engine starts one, passes it only a short list of environment variables, and passes a vault passphrase on a pipe, never in its arguments or environment. The log is `engine.log`, private to the user. The setting `engine.in_process` turns this off. Run on Linux; not yet run on Windows or macOS ([decision 0165](docs/decisions/0165-a-client-starts-the-engine-on-demand-detached-and-gives-it-the-passphrase-on-a-pipe.md)).
- The product reads the installation setting `network.trust_roots` when the engine opens, and every HTTP client of the workspace is made by one helper that states its TLS provider. HTTPS was off by default when this was written; decision 0181 turned it on, and `crates/anything2mcp/Cargo.toml` now has `default = ["tls"]`. The stripped release binary on Linux measures 31.4 MB without `tls` and 33.3 MB with it, over the 25 MB target ([decision 0166](docs/decisions/0166-https-in-the-product-trust-roots-at-engine-start-and-one-maker-of-clients.md)).
- The stream pack speaks the NATS client protocol with JetStream, through a client of its own, beside the test broker's protocol. A channel names its stream and subject, and a channel file may state the duplicate window. It is proven against the test stand, and the pack's own client is tested against a real NATS server with JetStream in a separate CI job ([decision 0167](docs/decisions/0167-the-stream-pack-speaks-nats-with-jetstream-through-a-client-of-its-own.md)).
- The data pack reaches a PostgreSQL server, with the same guarantees as the embedded file: one statement of the declared form, a row count checked before the commit, a lost answer to a commit is `possible_commit`, and the role may not be an administrator. The link must be to a loopback address; an encrypted link is not built. It is in a build of the pack with the feature `postgres`, which is off by default ([decision 0168](docs/decisions/0168-the-data-pack-reaches-a-server-database-with-the-guarantees-of-an-embedded-file.md)).
- The stream pack states `acknowledged` for a take and for a publish with no read-back, records a log's end before a publish and reads a take back by a look at its queue; the file pack keeps its own temporary file, names its codes `file_missing`, `file_protected`, `file_locked`, and `storage_full`, and treats a delete as `irreversible`; a project document is read below the run's project folder ([decision 0173](docs/decisions/0173-the-stream-and-file-packs-take-up-the-kernels-second-pass.md)). The data pack binds an assigned key from what was recorded and states `acknowledged` for an `irreversible` write with no identity, and the device pack's `submit` states it; a refused constraint shows only its name ([decision 0175](docs/decisions/0175-the-data-and-device-packs-take-up-the-second-pass-of-the-provider-contract.md)).
- An effect left as an open question is undecided, not a write: a drafter may leave one, and a file that holds one does not compile until a person answers ([decision 0178](docs/decisions/0178-an-effect-left-as-an-open-question-is-undecided-not-a-write.md)).
- A pack whose manifest is refused is listed by `provider.list` as `refused`, with its problem ([decision 0176](docs/decisions/0176-the-action-registry-takes-up-the-kernels-second-pass.md)).
- A target's offline tests of reads run in `test.run` against a replay of their fixtures, with nothing sent to any system; a step the fixture has no answer for stops the test (`fixture_no_answer`). A test of a write was listed as not run at first; decision 0180 runs it (below) ([decision 0177](docs/decisions/0177-a-targets-offline-tests-run-against-a-replay-of-their-fixtures.md)).
- A scout's drafts now include reads: one for each GET an OpenAPI description publishes, a read by key and a list for each keyed table of a database, and a pass-through read for each read-only tool of an MCP server. A drafted example is only one the system published about itself, and no test or fixture is drafted ([decision 0179](docs/decisions/0179-what-each-pack-drafts-so-that-a-scout-ends-with-reads-that-work.md)).
- Offline tests of writes run in `test.run`, against a replay of their fixtures and a ledger that lives in memory and is gone when the test ends. Nothing is published unless every operation has a passing offline test: a publish is refused with `publish_gates_not_passed`, and the publish page lists each gate and says which did not run. Two of the twelve gates are built ([decision 0180](docs/decisions/0180-a-targets-offline-tests-cover-writes-and-gate-the-publish.md)).
- The command line prints what an outside system said on a marked line of its own. The approval page says when a write will not be read back, and names the binding each write is bound to ([decision 0181](docs/decisions/0181-the-product-and-the-local-engine-take-up-what-the-kernel-now-offers.md), [decision 0192](docs/decisions/0192-a-served-engine-hands-no-root-of-the-project-that-started-it-and-clients-start-and-compare.md)).
- An engine whose data directory is removed stops by name (`data_directory_gone`). The output of an engine started for a command goes to `engine-output.log`, private to the user ([decision 0181](docs/decisions/0181-the-product-and-the-local-engine-take-up-what-the-kernel-now-offers.md)).
- HTTPS is on in the default build, so a build from source reaches `https` surfaces; `--no-default-features` builds without it ([decision 0181](docs/decisions/0181-the-product-and-the-local-engine-take-up-what-the-kernel-now-offers.md)).
- The file pack drafts a list read from what it observed, types workbook columns from what their cells hold, and saves through the kernel's temporary file. The data pack's list read returns each column as a list. A target cannot redefine a built-in field type (`kernel.built_in_type_redefined`) ([decision 0182](docs/decisions/0182-the-file-data-and-stream-packs-after-the-first-drafted-reads.md), [decision 0188](docs/decisions/0188-credentials-over-plain-links-drafted-workbooks-and-published-device-maps.md)).
- The stream pack's drafted reads return fields, a channel's `role` is optional, and the new setting `message_ceiling_bytes` bounds every message (8 MiB by default, at most 64 MiB) ([decision 0182](docs/decisions/0182-the-file-data-and-stream-packs-after-the-first-drafted-reads.md), [decision 0184](docs/decisions/0184-the-data-and-stream-packs-after-their-second-safety-audit.md)).
- A scout of a web application drafts a list read of each table a page shows, reads by key across the pages of one screen, reads of a page's labelled values, and `page_http` reads of a page's own JSON requests. A web read that may only look runs in a tab that cannot write. The names it makes hold the page's own words, and a person renames them ([decision 0183](docs/decisions/0183-the-web-pack-drafts-a-read-of-each-table-a-snapshot-names.md), [decision 0187](docs/decisions/0187-the-web-pack-matches-a-screen-by-its-address-and-reads-by-key.md), [decision 0190](docs/decisions/0190-the-page-http-mode-reads-from-inside-the-page-in-an-observing-tab.md)).
- The `page_http` mode reads a page's own JSON request from inside the page, with GET alone. Its entries are in `page_requests/`. A request that needs the page's anti-forgery header cannot be read yet, a write by this mode is described below, and a first measurement did not show it faster than the screen read ([decision 0190](docs/decisions/0190-the-page-http-mode-reads-from-inside-the-page-in-an-observing-tab.md)).
- A `ui` key that is not one plain path segment is refused (`address_value_refused`) and nothing is sent. It used to be percent-encoded ([decision 0187](docs/decisions/0187-the-web-pack-matches-a-screen-by-its-address-and-reads-by-key.md), [decision 0190](docs/decisions/0190-the-page-http-mode-reads-from-inside-the-page-in-an-observing-tab.md)).
- A credential is never sent over plain `http` to another machine, by the HTTP pack or the MCP pack, unless the surface declares `unencrypted_credentials: accepted` (`link_not_encrypted`) ([decision 0188](docs/decisions/0188-credentials-over-plain-links-drafted-workbooks-and-published-device-maps.md)).
- The device pack drafts reads from a published register map (a CSV file), and sends no frame to draft them ([decision 0188](docs/decisions/0188-credentials-over-plain-links-drafted-workbooks-and-published-device-maps.md)).
- The device pack updates a device's firmware through the device's own update sequence, as one irreversible operation with a declared recovery route, approved every run and never sent twice, and reads the device's version and its checksum back after it restarts; an update without a recovery route does not compile. An optional provider, off by default, reads a firmware image given as a file and says what it holds as inferred, without decrypting anything ([decision 0316](docs/decisions/0316-firmware-is-inspected-by-an-optional-provider-and-updated-by-one-operation-through-the-devices-own-sequence.md)).
- An identity service's endpoint over plain `http` must be a loopback IP address, so `http://localhost` is refused there; write `http://127.0.0.1:<port>` or use `https` ([decision 0192](docs/decisions/0192-a-served-engine-hands-no-root-of-the-project-that-started-it-and-clients-start-and-compare.md)).
- A `files` surface works again through a served engine, and each request reads its own project's files, never the project that started the engine ([decision 0194](docs/decisions/0194-the-packs-the-product-and-the-local-surface-take-up-the-kernels-second-pass.md); it replaces the limit that 0192 stated).
- A scout works on a target that declares only a surface, and its try stage ends. `binding.promote` makes a drafted first binding able to act once its offline tests pass and a scout proved it; the publish page lists what may act for the first time; `draft.delete` removes a draft file ([decision 0189](docs/decisions/0189-a-developers-first-hour-runs-without-hand-steps.md)).
- A read by key may be tried with a key from a list that the same scout read. The key is stored nowhere but the trial's own run ([decision 0189](docs/decisions/0189-a-developers-first-hour-runs-without-hand-steps.md)).
- The release build is about half the size, with the same speed on the commands measured. On Linux x86_64 the stripped binary went from 38,066,768 to 18,546,544 bytes, and its compressed size from 15,532,217 to 8,640,611 bytes. The other platforms are not measured yet ([decision 0191](docs/decisions/0191-the-release-profile-builds-one-code-unit-with-whole-program-optimisation-for-size.md)).
- What an outside system said is shown with every hiding or reordering character escaped. The scheduler waits longer each time before it reconciles the same run again, and a stop that needs a person waits for a person. A write ends as "accepted by the system, not read back" only where it cannot be read back ([decision 0193](docs/decisions/0193-the-core-the-contract-the-compiler-and-the-scheduler-after-the-second-pass.md)).
- On Windows the file save stops, unsent, instead of replacing a file whose access list cannot be kept. An MCP surface refuses an address that holds a user name or a password. The Python client runs only the program its own installed package put in place ([decision 0194](docs/decisions/0194-the-packs-the-product-and-the-local-surface-take-up-the-kernels-second-pass.md)).
- `fixture record` records a read's offline test and its fixture from one real read, with every value replaced by a made-up one of the same kind. Where it has no rule for a value it stops and writes nothing. A write's offline test needs a recorded request, and `expect: {sent: 0}` marks a test of the path where nothing is sent ([decision 0196](docs/decisions/0196-the-engine-and-the-registry-after-the-acknowledgement-and-the-first-hour.md)).
- A write whose binding cannot read the record is shown on the approval page as "cannot be read" for its current values, and ends as accepted, never verified ([decision 0196](docs/decisions/0196-the-engine-and-the-registry-after-the-acknowledgement-and-the-first-hour.md), [decision 0199](docs/decisions/0199-the-halves-left-for-each-other-are-joined.md)).
- `target add` takes `--kind` and an address and writes the surface and a test environment, so a new project needs no file written by hand. The publish page shows where each surface leads in each environment, its notices, and every lint warning. The new lint warning `kernel.acknowledged_with_lookup` says a lookup only tells whether a record landed; it is not a read-back ([decision 0199](docs/decisions/0199-the-halves-left-for-each-other-are-joined.md)).
- The desktop pack reads a running Linux application's windows through its accessibility tree, and drafts reads of what a window labels and of its tables. It never reads a password field. A desktop screen file names its control `desktop_text` ([decision 0198](docs/decisions/0198-the-desktop-pack-reads-linux-applications-through-a-look-only-back-end.md), [decision 0202](docs/decisions/0202-the-desktop-packs-control-has-a-name-of-its-own.md), [decision 0203](docs/decisions/0203-two-packs-may-each-draft-a-file-kind-of-one-name-for-their-own-surfaces.md)).
- The desktop pack reads a running Windows application's windows through UI Automation, with the same reads and the same refusal of a password field. It is written and linted and has not yet run on Windows ([decision 0209](docs/decisions/0209-the-desktop-pack-reads-windows-applications-through-ui-automation-on-a-thread-of-its-own.md)).
- A binding in shadow reads beside the verified one on a live read, and the two answers are compared output by output. The caller always gets the verified binding's answer. The actions that report the comparisons and promote a shadow binding are described below ([decision 0207](docs/decisions/0207-a-shadow-binding-reads-beside-the-verified-one-and-a-person-promotes-it-on-a-run-of-exact-matches.md)).
- A `page_http` binding can update a record from inside the page: the request is a PUT sent by the page itself with the page's own anti-forgery token, which never leaves the page, and the value is read back in a tab that cannot write ([decision 0206](docs/decisions/0206-the-page-http-mode-writes-by-put-with-the-pages-own-token-in-an-acting-tab.md)).

### Safety fixes

A safety review read each crate against its design and the ten rules, and every finding was confirmed with a test. These are the ones a user would see.

- The vault: a passphrase of fewer than 16 bytes is refused (`vault_passphrase_too_short`). Two engines starting together on a fresh installation make one root key. A session that was revoked cannot be brought back by a restore that arrives late ([decision 0138](docs/decisions/0138-the-vault-and-the-session-keeper-after-their-safety-audit.md)).
- The redactor finds a secret across the pieces of a stream, in hexadecimal in either letter case, in base64 with line breaks, in character references, and as a number. A number that holds a secret is shown as `[redacted]`.
- The engine: a write that was sent stays in doubt until it is read back, whatever failed after it, and is reconciled and never sent again. A value that holds the redaction mark is never sent (`argument_masked`), and a write whose values hold a registered secret is refused. The lease is checked at the commit point ([decision 0147](docs/decisions/0147-the-engine-after-its-safety-audit.md)).
- Runs: a run is its person's alone, and anyone else is told there is no such run. A run whose stored call cannot be read is not run (`run_call_unreadable`). A proof of presence older than two minutes is refused.
- The provider contract: a file is written under a random name, only where nothing stands, and never through a link. A program's digest is checked at every start, and on Linux the file that was checked is the file started. A pack's manifest may not name a program by a relative path.
- The HTTP pack: a write answered by a redirect to another origin, by an answer too large to read, or by one that cannot be read is in doubt and reconciled, and was settled as unsent before. A write that sends a version is refused when the version was not read (`stale`, `version_not_read`). An API description is read within bounds, and one past them is refused (`description_too_large`). A body that is not JSON is `drift` ([decision 0139](docs/decisions/0139-a-write-that-was-sent-is-never-settled-by-an-answer-that-is-not-the-applications-verdict.md)).
- The command pack: a program a group can write, or reached through a folder or link another user can write, is refused. A value that begins with `@`, and every form of a flag that runs its value, are refused. The new lint rules `command.secret_variable`, `command.secret_literal`, and `command.secret_argument` refuse a credential written into a command file ([decision 0140](docs/decisions/0140-the-command-pack-after-its-safety-audit.md)).
- The data pack: a statement is one plain read or one keyed write, and `ATTACH`, `PRAGMA`, `VACUUM`, and the like are refused. A read-back must be written `effect: read` with `form: table`; a target whose read-back was a hand-written read does not compile until it is. A write that cannot know what it reaches stops ([decision 0141](docs/decisions/0141-the-data-pack-holds-a-statement-to-one-read-or-one-keyed-write-and-a-connection-to-one-file.md)).
- The file pack: a document that a binding writes must state `may_be_open`. A text value for delimited text that begins with `=`, `+`, `-`, or `@` is refused (`value_begins_formula`) unless its field says `may_begin_formula: true`. A link at a document's name is refused, and a file left by a killed save is never used or removed ([decision 0149](docs/decisions/0149-the-file-pack-after-its-safety-audit.md)).
- The stream pack: a take records the whole message before it acknowledges. An empty look is "absent" only where the log was fully covered. A refusal in words the protocol does not define leaves a write in doubt. A field of text from a message must be marked untrusted, or the target does not compile (`stream.untrusted_unmarked`) ([decision 0150](docs/decisions/0150-a-take-records-its-message-before-it-acknowledges-and-an-answer-with-no-rule-leaves-a-write-in-doubt.md)).
- The device pack: a device that reports another serial than the one declared is refused (`device_identity_mismatch`), a write frame is recorded before it is sent, and a run past its frame ceiling is refused (`frame_budget_exceeded`) ([decision 0137](docs/decisions/0137-a-device-is-held-to-its-serial-a-write-frame-is-recorded-before-it-is-sent-and-a-run-has-a-frame-ceiling.md)).
- The MCP pack: a tool that the mapping says runs free text is never called, and a tool whose whole input is one string and that nobody reviewed is refused. The tool list is read again before every write. A member of a result that the mapping does not list is not passed on, and an output that is text must be marked untrusted ([decision 0136](docs/decisions/0136-the-mcp-pack-refuses-free-text-reads-its-list-again-before-a-write-and-passes-on-only-listed-members.md)).
- The browser engine: a tab stays on the origins its plan declares, a move a page starts in an observing tab is ended, every download is denied, a window a page opens is closed, the profile folder is made private to the user, and a password field is masked in the accessibility tree ([decision 0143](docs/decisions/0143-the-browser-engine-after-its-safety-audit.md)).
- The compiler and the plan: an operation that writes must declare a commit point, a draft never writes, a code list in which one text stands for two choices does not compile, and a plan that breaks a rule of a write is refused when it is read ([decision 0153](docs/decisions/0153-what-the-compiler-the-plan-and-the-redactor-hold-by-themselves-after-the-safety-audit.md)).
- The browser engine refuses every permission a page asks for, and reports a download or a pop-up it refused ([decision 0143](docs/decisions/0143-the-browser-engine-after-its-safety-audit.md)).
- The `ui` driver does not click a write over a state the page showed before the click, and a `submit` through `ui` is `irreversible`. Discovery never visits an address that looks like an action ([decision 0144](docs/decisions/0144-the-web-drivers-and-discoverers-after-their-safety-audit.md)).
- An approval is checked whole when a write begins, the `cautious` and `ci` presets are in force, and an approval's window is at most one day ([decision 0145](docs/decisions/0145-only-the-policy-engine-clears-a-write-and-the-ledger-reads-the-whole-clearance.md)).
- An operation that writes can no longer compile as a read, in any pack ([decision 0154](docs/decisions/0154-the-http-command-and-mcp-packs-state-what-saves-what-writes-and-which-key-is-sent.md), [0155](docs/decisions/0155-four-packs-state-what-saves-what-writes-and-when-their-guard-lifts.md)).
- Telemetry: a trace that was altered is reported as broken and gives no signature, and a log file is private to the user on Linux and macOS.
- A command that runs the engine itself holds the engine lock, so two engines never share a store; a second command waits up to twenty seconds, then ends `engine_unreachable` ([decision 0158](docs/decisions/0158-the-product-crate-and-the-local-engine-after-their-safety-audit.md)).
- Every caller of the local channel is an agent, so a person's act through a running engine is refused (`person_required`) until a page for it is built. A person who needs one stops the engine and acts in one process at a terminal.
- Approval pages work in a real browser, which sent no usable origin before.
- Project files that another account can change are ignored or refused (`path_not_allowed`), and a folder is searched for one only where only you or the administrator can write.
- Terminal output shows control characters as text, such as `\u{1b}`, and does not obey them.
- Each installation has its own key-store entry, named by its data directory, and the passphrase variable is removed from the engine's own process at start.
- The npm launcher runs only its own platform package, checks its name and version, and passes `SIGINT`, `SIGTERM`, and `SIGHUP` on to the program ([decision 0159](docs/decisions/0159-a-lost-answer-is-a-write-in-doubt-at-the-doors-and-in-the-clients.md)).
- A program started by a pack is never handed a variable of the engine's own (any name starting with `A2M_`) or one named for a credential; a launch that names one is refused (`engine_variable_refused`) and the lint rule is `command.engine_variable`.
- The browser engine: a closed tab is taken off the browser's count every time, so a browser with no tab open reads idle. A closed tab could stay counted, its page left open, when two threads heard its end in one order.
- A provider's process group whose leader is still exiting is ended without a false report that it could not be; macOS showed it.
- The data pack never uses a kept connection that now leads to another database, and refuses control characters in a statement (`connection_leads_elsewhere`, `store_file_replaced`) ([decision 0184](docs/decisions/0184-the-data-and-stream-packs-after-their-second-safety-audit.md)).
- The stream pack: once a publish or an acknowledgement has left, any error from the server leaves the write in doubt, never a refused session. A message delivered before and possibly held by another record is not taken (`message_may_be_held`); after an engine restart it waits until a person settles it. A scan says "absent" only of a log it read whole (`scan_inconclusive`) ([decision 0184](docs/decisions/0184-the-data-and-stream-packs-after-their-second-safety-audit.md)).
- A write of a record with no key whose answer was lost is never sent again on one "absent": it stays in doubt unless the binding's lookup is declared authoritative and says absent twice. An approval binds the binding that writes, and a write through another binding is refused (`approval_stale`) ([decision 0185](docs/decisions/0185-a-record-with-no-key-is-never-proved-absent-by-one-look.md)).
- A web read never runs in a tab that can write, in any posture. A `page_http` read is drafted only from a request that can be made again exactly. A token in a page's address or query is never kept. A key that holds an action word is refused, so a key such as `PAY-100` cannot be read by key; this is a limit, and may be stricter than it needs to be ([decision 0195](docs/decisions/0195-a-read-never-runs-where-the-page-may-write-and-a-page-keeps-only-its-structure.md)).
- No client takes a proxy from the environment, and no proxy is built: a `network.proxy` that is set is refused when the engine starts. A broker over plain TCP must be written as a loopback IP address (`127.0.0.1` or `[::1]`), not `localhost`. No build of the product, the workspace build included, offers the test broker's protocol ([decision 0197](docs/decisions/0197-no-client-takes-a-proxy-from-the-environment-and-stand-only-protocols.md)).
- A person's resume is never lost while a reconcile of the same run is ending. The engine's browser is started so that it takes no proxy and runs no extension; a machine-wide browser policy set by an administrator still applies ([decision 0201](docs/decisions/0201-a-resume-is-never-lost-the-browser-takes-no-proxy-and-no-product-build-speaks-a-stands-protocol.md)).
- A protected setting is loosened only by an installation settings file that no account but an administrator can change. Under `A2M_HOME`, or on Windows for now, such a loosening or lock is refused by name (decision 0241).
- `policy.two_person_irreversible` is protected: once on, no user file, variable, or flag turns it off.
- The engine makes its data, configuration, and cache folders its user's alone; `doctor` names one that others can enter.
- An answer to a page write that quotes the page's anti-forgery token is withheld whole, and the write is treated as in doubt. A page's refusal of the values of a write is no longer settled as not written. The tab that writes passes the page's service worker by (decision 0245).
- The HTTP pack reads a hostile XML or JSON answer within bounded work and never on the engine's async threads. Outside a live run it sends no request that may write, unless it is a declared test record's commit or a read the endpoint asserts, against a test environment. An endpoint marked `read` with a method that is not safe now needs `read_asserted: true`. A bytes answer that holds a registered secret gives neither its length nor its digest (decision 0249).
- A shadow binding is promotable only on matches over distinct inputs, in each environment its evidence must come from, against the verified binding that acts. `shadow report` shows the distinct inputs, the environments, and what the shadow's reads cost in requests, and promoting from shadow asks for presence. All of a call's shadows share one budget of time, and a shadow never asks for a sign-in or takes a caller's share of a rate budget (decision 0251).
- The MCP pack refuses to start a local server that another user could change, or that is a shell, an interpreter, a batch file, or a script: before, it checked only the program's digest (decision 0250).
- A command or a local MCP server is no longer given a variable that makes it load other code, such as `LD_PRELOAD` or `NODE_OPTIONS`.
- A script a target keeps runs only through an interpreter in its one known form, and only from a run folder no other user can change.
- A sign-in sends a credential only to an address the target declares. A sign-in that only drafts declare always goes to the person's page, which shows every address first, and a stored credential is used only under a published version. Each credential belongs to the target it was stored for; one stored before this change must be stored again. A refused password a person asked to try is not tried again by a later run (decision 0248).
- A stored password is set into the field that was checked, never typed into whatever holds focus, and the sign-in page is proven again before each value and before the press; a sign-in page that holds a frame is a named stop. A sign-in in a browser refuses an entry that also covers a surface of another kind, so a web session's cookies go to no other surface. Cookies are placed only for the run's own origins (decision 0254).
- The network readers remove a proxy password whatever characters it holds, and leave out a proxy or bypass list that may hold one, saying why. An answer about the network that does not come from the system itself is dropped unread, and a read that gets no answer ends after five seconds (decision 0261).
- Promotion through shadow counts only comparisons kept from this version on: a binding may need new distinct matching inputs before it can be promoted. The watch halves hold every watch to its end whatever its state, check a surface's budget share inside the confirmation, and take each check's records from its run's own stored result; a record that leaves the view is never reported as removed until a read can say it returned every record (decision 0262).
- A refused or unanswered stored password is no longer sent again after the engine restarts, and a session that a system keeps ending is signed in again by itself at most four times an hour; after that it waits for you to sign in (decision 0269).
- On Windows, a file the file pack creates is now confirmed under its name; before, every create there was reported as a possible commit.
- A program the product starts is refused when it is a language launcher, package runner, container runner, or build tool, or does not begin as this system's programs do; more variables that make a program load other code are refused, and a `PATH` given to a program may name only folders no other user can change (decision 0271).
- A program with no working folder of its own runs in a private folder made for that start, not in the shared temporary folder, and the folder is removed when it ends.
- On macOS an access-list entry that allows anything refuses a program; on Windows a program on a mapped share or a substituted drive letter is refused (both written, first run in CI).
- The HTTP pack sends a search behind POST outside a live run only from a published version, judges a method-override header or `_method` entry as the method it names, refuses a read once too many earlier reads are still running past their deadline, bounds text patterns and the text they match, and checks bytes answers for secrets written in UTF-16. The HTTP and MCP packs never send a header whose name begins `a2m-` (decision 0270).
- On macOS an installation settings file that the administrators' group may write, or whose access list allows another account, no longer loosens a protected setting; the file is checked and read as one opened file. `version.publish` refuses the version 0.0.0, which belongs to the drafts. A draft that calls its environment a test environment no longer gets a test record's treatment (decision 0273).
- The file pack's folder writes can no longer be led outside the root by a folder swapped for a link; a file is deleted only while it still holds the bytes that were read; a growing file's line that is not text is reported and passed instead of stopping every later read (decision 0272).
- On macOS and Linux the engine opens its runtime folder without following a link, then checks the folder and makes it private through that open folder; a link put in the folder's place is refused.
