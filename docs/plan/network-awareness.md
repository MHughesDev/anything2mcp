# Network awareness: a design proposal

**Status:** Proposal of the first design wave, 2026-11-18. Nothing here is in force. It answers [decision 0222](../decisions/0222-the-product-is-aware-of-the-network-its-machine-is-on.md), within [decision 0208](../decisions/0208-the-first-release-reaches-what-the-persons-machine-reaches-and-serves-on-that-machine-only.md) and the ten rules. Its choices are in Proposed records [0223](../decisions/0223-a-place-a-network-and-a-reach-are-kernel-words.md) to [0227](../decisions/0227-whether-network-findings-are-kept-and-for-how-long.md). The two research notes that should settle its assumptions (28, on how a network can be seen from one machine, and 29, on existing tools and the conduct of looking) did not exist when this was written or when it was finished; every fact that waits on them is marked **Assumption** with the note named. A second design wave reconciles this proposal with them.

## The question, in one paragraph

Today the kernel knows a target, its surfaces, and each surface's address as a string, and a driver sends only to an address in the run's `Destinations`, compared as written ([`a2m-provider` `Destinations`](../../crates/a2m-provider/src/driver.rs)). Nothing knows *where* an address is: on this machine, on the network the laptop is on today, or across the internet. Four rules already answer that question each in its own way, in its own crate: the origin guard of the browser ([decision 0143](../decisions/0143-the-browser-engine-after-its-safety-audit.md)), "a loopback address is an IP address written as one" ([decisions 0188](../decisions/0188-credentials-over-plain-links-drafted-workbooks-and-published-device-maps.md) and [0192](../decisions/0192-a-served-engine-hands-no-root-of-the-project-that-started-it-and-clients-start-and-compare.md)), "no proxy from the environment" ([decisions 0197](../decisions/0197-no-client-takes-a-proxy-from-the-environment-and-stand-only-protocols.md) and [0201](../decisions/0201-a-resume-is-never-lost-the-browser-takes-no-proxy-and-no-product-build-speaks-a-stands-protocol.md)), and the device pack's refusal of a host name ([decision 0214](../decisions/0214-ways-through-the-refusals-that-keep-a-person-from-their-own-machine.md) part 4). The owner asked for the network to be one general idea of which a website is an instance. This proposal makes it three small kernel words, a **place**, a **network**, and a **reach**, and one new pack that looks.

## What is built today, exactly

| Thing | As built | Where |
| --- | --- | --- |
| A surface's address | A string per surface, overridable per environment (`environments.<env>.surfaces.<name>`). The kernel does not parse it; the pack does | `a2m-files` `kernel.rs` (`SURFACE_KEYS` are `kind`, `same_session_as`, `rate`, `stands`); `a2m-engine` `run.rs` `address_of` |
| Where a run may send | `Destinations`: the target's surface addresses at the run's environment plus the operation's permission-manifest destinations, compared as written | `a2m-engine` `run.rs` `destinations_of`; `a2m-provider` `driver.rs` |
| "Is this on this machine" | Judged separately in at least five crates: `a2m-auth` `link.rs`, `a2m-pack-http` `link.rs`, `a2m-pack-mcp` `mapping.rs`, `a2m-pack-data`, `a2m-pack-stream` `wire.rs` (`plain_tcp_address`). All agree: an IP literal in `127.0.0.0/8` or `::1`, never a name | Those files |
| A device's address | A socket address literal; a name is refused | `a2m-pack-device` `modbus.rs` |
| A discoverer's input | A `DiscoveryScope` that holds one `SurfaceRef`. There is no discovery without a surface, so there is no place for "look at a network" | `a2m-provider` `discover.rs` |
| A finding's subject | A closed enum in `a2m-core`: `file`, `address` (origin and path), `process`, `session`, `device`, `unknown`. No host, no network | `a2m-core` `finding.rs` |
| Built-in tools | Actions in the registry's catalog, `noun.verb`, faces generated as `a2m_<noun>_<verb>`; the `use` and `build` toolsets list at most 12 and 15. A provider may add actions; a `ProviderAction` is given roots, the registry, the redactor, and checked paths, and no network handle | `a2m-actions` `catalog.rs`, `def.rs`; `a2m-provider` `action.rs` |
| Protected settings | Loosened only with the operating system's presence prompt through `config.set`; `network.allowed_hosts`, `network.proxy`, `network.trust_roots` are protected and installation-scoped; `network.proxy` is read by nothing | Section 226 |
