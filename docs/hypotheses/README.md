# Hypotheses

The design is a set of bets. This register lists the ones that matter most: what the design assumes, what else could be true, and how to find out. Testing these, and adding to them, is how the design gets better as the system is built.

## How to use the register

- **Before a slice,** find the hypotheses it can test. [Core first](../plan/roadmap.md) names them per slice.
- **While working,** add a hypothesis whenever something in the documents is assumed and not known, or a different design looks plausible.
- **After a test,** write the result as a file in this folder named for the hypothesis, such as `H-01-result.md`, using the [template](TEMPLATE.md). Set the status here. If a decision changes, add a decision record.
- A hypothesis is never deleted. A refuted one is the most useful kind.

**Status:** `open`, `supported`, `refuted`, or `changed` when the test led to a different design.

## Notes on open hypotheses

What the work has shown so far about a hypothesis that is still open. A note is not a result: the result file is written when the test in the register has been run.

- **H-01, 2026-11-17.** Partly supported by the browser spike ([research note 17](../research/17-browser-engine-base.md)): a direct client works, is small, and meets the budgets on Linux. No sidecar was compared, no memory figure was taken, and nothing ran on Windows or macOS.
- **H-01, 2026-11-17, the browser engine as built.** The direct client in `a2m-pack-web-browser` also does input, request interception, and requests made from inside the page, with no outside base library ([decision 0110](../decisions/0110-the-browser-engines-interface-as-building-it-settled-it.md)). Still no sidecar comparison, no long run, and no run on Windows.
- **H-02, 2026-11-17.** In the browser engine's tests, every field and action of the test application's form was found by role and name. Only the status line needed a selector.
- **H-03, 2026-11-17.** Supported on the late-element case, in the same spike. The re-render case was not measured.
- **H-03, 2026-11-17, the browser engine as built.** A late element is noticed by an in-page observer when it arrives, with no polling, and a wait under way survives a navigation: it is re-armed in the new document. No comparison with polling was measured, there was no long run, and Windows has not run it.
- **H-04, 2026-11-17.** The part of the bet that is one renewer is supported in one process and on one store: ten concurrent callers that meet an expired session cause one renewal, also on real threads, in the tests of `a2m-auth`. It is not shown across two processes, and no browser has shared tabs yet.
- **H-06, 2026-11-17.** The real product on Linux held up as far as it was tried: two commands shared one engine, a second engine on the same data directory was refused by name before it opened the store, and a stop left nothing behind, in `two_commands_share_one_engine_a_second_engine_is_refused_and_a_stop_leaves_nothing` ([decision 0131](../decisions/0131-the-front-doors-joined-serve-the-thin-client-and-the-bridge.md)). Not shown: a run on Windows or macOS, where the channel has never run, and an engine started on demand. A command that finds no engine still runs one inside itself without the engine lock, so two such commands on a fresh installation can race ([decision 0138](../decisions/0138-the-vault-and-the-session-keeper-after-their-safety-audit.md)).
- **H-09, 2026-11-17.** Both strategies are carried through the engine: a stamped token is handed to the lookup steps, and a `find` lookup reads the record and may report `ambiguous_match` ([decision 0091](../decisions/0091-the-engine-loop-as-its-first-two-passes-settled-it.md)). Only against the test application. No real application's creates were classified, which is what the bet needs.
- **H-11, 2026-11-17.** Research brief 31 was run ([decision 0082](../decisions/0082-the-decision-core-is-the-policy-crates-own-evaluator.md)). Cedar passes on speed, at 1.9 microseconds a decision. It fails on the closed licence list, and on size: 107 crates and 5.8 MB. The policy crate's own evaluator is used. The result file is still to be written.
- **H-12, 2026-11-17.** The Linux prompt is built, with polkit asked first without interaction so that a yes given with no one asked is refused ([decision 0142](../decisions/0142-the-presence-prompt-interface-and-the-linux-prompt-as-built.md)). Run: every verdict and fault against a made-up authority, and the real bus code against a real polkit with no policy file. Not run: any dialog on a desktop, anything with the policy file installed, and Windows or macOS. Whether a person finds it quick is not measured ([decision 0133](../decisions/0133-the-presence-prompt-on-each-operating-system-and-what-it-is-said-to-prove.md) narrows the claim to the engine and synthetic input).
- **H-12, 2026-11-17, the other two prompts.** The macOS prompt (Touch ID or the account password) and the Windows Hello prompt are written, so a prompt now exists for all three systems ([decision 0146](../decisions/0146-the-macos-and-windows-presence-prompts-as-built.md)). They were run only against a made-up system on Linux, and type-checked for their own targets. Nothing about timing, or about a real dialog on any system, is measured ([decision 0142](../decisions/0142-the-presence-prompt-interface-and-the-linux-prompt-as-built.md)).
- **H-15, 2026-11-17.** The latency of storing an intent is not measured. A durability setting changed per transaction, on one writer thread, is workable ([decision 0080](../decisions/0080-the-store-is-one-sqlite-file-and-a-crate-reaches-its-own-tables-through-the-transaction.md)).
- **H-16, 2026-11-17.** Five simulated runs with differing identifiers and timings gave one signature, in the tests of `a2m-telemetry`. Open until real runs on three operating systems.
- **H-20, 2026-11-17.** The test application's own time for a read is about 65 microseconds at the median on the build machine, by the harness in `bench/`. The budget for a request operation is about 75 times that. Nothing budgeted is measured yet.
- **H-19, 2026-11-17.** The OpenAPI import in `a2m-pack-http` drafts ordinary `endpoints/` entries. This is evidence that the `api` mode may be the `http` mode with another source of templates.
- **H-21, 2026-11-17.** The in-process runner loop uses the same hello, claim, heartbeat, and finish as a runner on another machine would, so the lease rules can now be measured. One cost was found: the 30-second default lease cannot carry a write whose steps each allow 30 seconds, so in one process the lease is at least 100 seconds ([decision 0095](../decisions/0095-the-settings-loader-and-the-in-process-runner-as-built.md)).
- **H-24, 2026-11-17.** Part of the bet failed: a key built from identity inputs alone cannot be worked out for a line that waits for its header's key, so such a record is keyed by its place in the run, as a record with no key input always was ([decision 0092](../decisions/0092-a-record-that-waits-for-an-earlier-record-is-planned-under-its-place-in-the-run.md)). The test in the register, two operations on one record started together, has not been run.
- **H-26, 2026-11-17.** So far supported: `a2m-core` names no mode, verb, or surface kind. A whole test pack registers a surface kind, a file kind, a mode, verbs, step kinds, a control, a lint rule, a drafting rule, a driver, a discoverer, and an auth provider with no kernel change. The first real packs are being built now. One kernel change so far that a pack forced: the plan gained a list of the programs a surface's driver may start ([decision 0124](../decisions/0124-the-plan-declares-a-surfaces-programs-and-a-schema-checks-run-time-values.md)). The test in the register is still to run.
- **H-26, 2026-11-17, seven packs.** Seven packs are built: HTTP, command, data, file, stream, device, and MCP. One kernel change was forced, [decision 0124](../decisions/0124-the-plan-declares-a-surfaces-programs-and-a-schema-checks-run-time-values.md). Each pack lists what the contract could not express, in decisions [0097](../decisions/0097-what-the-provider-contract-could-not-give-the-http-driver-and-what-the-pack-does-instead.md), [0099](../decisions/0099-the-command-pack-as-building-it-settled-it.md), [0100](../decisions/0100-the-mode-sql-and-the-data-packs-contract-as-building-it-settled-it.md), [0103](../decisions/0103-the-file-pack-as-building-it-settled-it.md), [0105](../decisions/0105-the-stream-mode-and-the-stream-pack-as-building-it-settled-it.md), and [0110](../decisions/0110-the-browser-engines-interface-as-building-it-settled-it.md). A second pass over the contract is planned, and the result file comes with it.
- **H-26, 2026-11-17, after the safety audits.** Reviews of the packs asked the contract and the compiler for additions that a pack could not make safely alone: `CheckedPath::entry_kind` and `create_dir`, `codes::KERNEL_ONLY`, `commit_steps` in a manifest ([decision 0148](../decisions/0148-the-provider-contract-and-the-scheduler-after-their-safety-audit.md)), and `Lowering::commits`, `Lowering::least_effect`, and `FileKind::writes` ([decision 0153](../decisions/0153-what-the-compiler-the-plan-and-the-redactor-hold-by-themselves-after-the-safety-audit.md)). Each is an addition with a default that changes nothing for a pack that has not answered, and none names a mode. They are counted in the result, which is still to be written.
- **H-26, 2026-11-17, what saves and what writes.** All seven non-web packs (HTTP, command, MCP, data, device, stream, file) now answer which of their step kinds save, the least effect of a binding, and which file kinds can describe a write, and the web drivers answer the same for the least effect ([decision 0154](../decisions/0154-the-http-command-and-mcp-packs-state-what-saves-what-writes-and-which-key-is-sent.md), [0155](../decisions/0155-four-packs-state-what-saves-what-writes-and-when-their-guard-lifts.md), [0144](../decisions/0144-the-web-drivers-and-discoverers-after-their-safety-audit.md)). The compiler refused an understated write in the tests of the data, device, stream, and file packs; no test of that name was found for the HTTP, command, and MCP packs. No kernel crate named a mode for it. The result file is still to be written.
- **H-28, 2026-11-17.** The first wheel is 10.5 MB, and the stripped binary in it is 25.1 MB, a little over the 25 MB target for the binary and well under it for the wheel ([research note 21](../research/21-wheel-and-npm-packaging.md), [decision 0135](../decisions/0135-the-wheel-carries-the-binary-and-a-thin-client-and-npm-uses-platform-packages.md)). One Linux target was measured; the eight-target build has never run.
- **H-28, 2026-11-17, with the packs and the engine as built.** The stripped release binary on Linux (x86_64) is 31,362,392 bytes without the feature `tls` and 33,250,136 bytes with it, so it is over the 25 MB target already without TLS, and TLS is not what decides it ([decision 0166](../decisions/0166-https-in-the-product-trust-roots-at-engine-start-and-one-maker-of-clients.md)). The wheel was not re-measured, so whether it stays under 25 MB compressed is not shown, and the bet has not been tested on the other platforms.
- **H-35, 2026-11-17.** One list was not enough: a lookup list finds a record by a stamp or a search, and a read-back list reads it by the key the system assigned, handed to it as the step's key; the lookup's read is the comparison and no second read follows ([decision 0091](../decisions/0091-the-engine-loop-as-its-first-two-passes-settled-it.md)). Both are carried out through the driver's ordinary `act`, so that half of the bet holds.
- **H-39, 2026-11-17.** Not met on npm: the launcher starts in about 43 ms against the 30 ms budget, of which Node itself is 32 ms. On pip the `a2m` script starts in 15.6 ms against 4.7 ms for the binary ([decision 0135](../decisions/0135-the-wheel-carries-the-binary-and-a-thin-client-and-npm-uses-platform-packages.md)). Only Linux was measured, and `a2m` from pip on Windows is not provided yet.
- **H-29, 2026-11-17.** Each built pack fitted its archetype's steps without a special case in the engine: `sql` the request archetype, `file` the artifact archetype with the file read in the open step, and `stream` the stream archetype.
- **H-40, 2026-11-17.** Supported for two reference client libraries in the MCP spike ([research note 18](../research/18-mcp-server-base.md)). Untested for other clients.
- **H-40, 2026-11-17, the real product.** The program's own `bridge` was started as a stdio server by the Python client library (`mcp` 2.3.0) and by the TypeScript one in both release lines (1.32.2 and 2.4.0). All seven runs connected, listed the tools, and called a published read by name, asking for either revision ([decision 0131](../decisions/0131-the-front-doors-joined-serve-the-thin-client-and-the-bridge.md)). The Python library warned that the tool it called was not in the listing, so it could not check the result against a schema. Other clients are untested.

## Adding a hypothesis

Give it the next number. State what the design assumes as a sentence that could be false, name a real alternative, and say how to test it with something that produces a number or a clear yes or no. A doubt with no test is a note for the journal, not a hypothesis.
