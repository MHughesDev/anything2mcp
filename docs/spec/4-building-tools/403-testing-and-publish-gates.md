# 403. Testing and publish gates

A version is published only when every gate passes, and the evidence is stored with the version. The determinism and equivalence gates compare trace signatures ([section 217](../2-kernel/217-traces-evidence-and-repair.md)); the schema and lint gate is the compiler ([section 206](../2-kernel/206-the-compiler-and-the-compiled-target.md)). Two gates are built, schema and lint and offline replay: a publish is refused unless both pass, and the evidence stored with the version, and shown on the page a person publishes from, names each gate that did not run ([decision 0180](../../decisions/0180-a-targets-offline-tests-cover-writes-and-gate-the-publish.md)). The offline replay passes for a write only by a test that sent its save and whose recorded request matched what was sent, and it tests the bytes the version is compiled from: the evidence names the compiled target and the digest of its sources ([decision 0196](../../decisions/0196-the-engine-and-the-registry-after-the-acknowledgement-and-the-first-hour.md)). Each offline test runs one binding of its operation, the one its file names or else the one that would act live, and its evidence names that binding and the digest of what it does; the offline replay passes only when every binding that may act in the version has a passing test that ran it, and, for a write, one whose save was sent through it and compared ([decision 0200](../../decisions/0200-evidence-names-its-binding-and-a-recorded-fixture-says-nothing-of-the-original.md)). The schema and lint gate warns of an operation of which every binding is `draft` or `retired`, the status a binding has when it states none: no call of it could run, and the engine fails one for good as `no_binding_may_act`. It is a warning, because the offline tests that promote a draft binding run on the same compile; refusing such a publish is the publish gate's, and is not built ([decision 0440](../../decisions/0440-an-operation-no-binding-of-which-may-act-is-warned-of-and-a-call-of-one-fails-for-good.md)). The other ten gates are not built.

| Gate | What it checks | Applies to |
| --- | --- | --- |
| Schema and lint | Every file validates; names are unique; no fixed sleeps; no undeclared surfaces | All |
| Offline replay | Operations run against recorded pages, responses, and traffic in `fixtures/` and produce the expected results | All |
| Contract | Every locator resolves uniquely and matches its fingerprint; every endpoint response matches its schema; every upstream tool still exists | All bindings |
| Determinism | Five live runs on the same input produce the same step trace | Reads, pipelines |
| Binding equivalence | For the same input, each verified binding returns the same normalized result; an HTTP write binding reproduces the request the UI sent, field for field, ignoring declared volatile values | Operations with more than one binding |
| Write round trip | On a test record: write, read back, compare, then restore the original values | Write operations |
| Idempotency | The same pipeline run twice; the second run changes nothing | Write pipelines |
| Resume | A run killed at a random step, then resumed, finishes with no duplicates | Write pipelines |
| Fault injection | Expired session, slow network, blocked surface, bad input, stale approval, and edge block each stop with the right class | All |
| Performance | Each operation meets its budget; no regression over 10% against the last version. Not built | All |
| Agent usability | A test agent with no prior knowledge completes scripted tasks using only the generated names, descriptions, and results | Each toolset |
| Human review | A person reads the generated description, schema, effect class, and permissions; and, from the review summary, what each tool starts (a program's path and digest, a kept script with the fixed sentence that its digest does not make it safe), every variable it sets or passes, every address it can send a request to by the kind of place, and for each sign-in the provider, the credentials by name, and every address a credential or token goes to; a pack that states none of this is shown as stating nothing ([decision 0252](../../decisions/0252-a-fixed-place-a-review-that-shows-what-runs-and-a-sign-in-before-its-probe.md)). The page a person publishes from lists where each surface leads first, with each address at a place no person registered for the target marked where it is listed ([decision 0418](../../decisions/0418-the-publish-page-lists-the-surfaces-first-and-marks-each-new-address-where-it-lists-it.md)); then it renders that summary: the sign-ins, with the addresses the session keeper gives for each environment; then each read a person asserted, a request by a method that may write marked `read_asserted: true`, with its method, path, and body's fields, and the fixed sentence that the person's word is the only evidence that it changes nothing ([decision 0426](../../decisions/0426-the-publish-page-names-each-asserted-read-after-the-sign-ins-from-what-each-file-kind-says-it-asserts.md)); then the tools, the most dangerous first; then the kernel's own lines and the checks' warnings. Every text passes the redactor and is escaped, and a secret variable is named and shown as secret, never valued. The command, HTTP, MCP, file, web, device, stream, and data packs state what their tools start and where they send; a web tool sends only to its surface and the destinations its operation declares, because its browser fails every other request of the page ([decision 0292](../../decisions/0292-a-web-tab-sends-only-to-its-surface-and-the-destinations-its-tool-declares.md)); the device, stream, and data packs start nothing and send only to their surface's address, and a store in a local file sends to none ([decision 0334](../../decisions/0334-the-device-stream-and-data-packs-state-where-their-tools-send.md)); the desktop pack states nothing yet ([decision 0264](../../decisions/0264-the-publish-page-renders-the-typed-review-sign-ins-first-from-one-keeper-call.md)) | All |

**Where writes are tested.** In order of preference: the system owner's sandbox or a test environment; a dedicated test record in production that the tests restore after use; otherwise the write operation stays unpublished. Anything2MCP never proves a write by performing it on live business data.

**After publishing.** Read-only canaries check a published read on a schedule, each one confirmed by the person it acts for and never started by the publish itself ([decision 0482](../../decisions/0482-a-canary-runs-on-a-schedule-its-person-confirmed-and-sends-only-a-published-read.md)). A drift marks the knowledge it was seen in, and every tool that relies on it is refused before anyone runs a write. Re-running the contract gate from a canary, and a schedule that follows how often a platform ships changes, are not built.

**Creates.** For an operation that creates records: the same create run twice leaves one record, and a run stopped between sending a create and recording it finds that record on resume ([section 209](../2-kernel/209-record-identity-and-dependent-records.md)).

**Testing Anything2MCP itself.** The [test application plan](../../plan/test-application.md) lists every case and the driver conformance suite. The repository ships a test application that imitates the hard cases of web and desktop interfaces: virtualized grids, postback forms, single-page apps, anti-forgery tokens, optimistic locking, and a desktop app. Each further pack brings its own test stand, which imitates the part of its kind of system that makes the kind hard. Every driver and widget driver is tested against its stand on Windows, macOS, and Linux in CI.
