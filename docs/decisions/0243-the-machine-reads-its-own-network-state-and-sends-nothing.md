# 0243. The machine reads its own network state, and sends nothing

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-18

**Changes:** adds the crate `a2m-netstate` and [its design](../architecture/crates/a2m-netstate.md); one row of the layering table in the [technical reference](../reference/technical-reference.md#crate-layering); one line of the layout in [section 605](../spec/6-running-it/605-packaging-and-release.md). Accepts in part Proposed [decision 0223](0223-a-network-is-a-place-a-recognized-network-and-a-reach.md): its rung 0, slice N1 of the [network-awareness design](../plan/network-awareness.md), with no place, network, or reach yet.

## Context

The owner decided the product knows the networks its machine is on ([decision 0222](0222-the-product-is-aware-of-the-network-its-machine-is-on.md)), and took the recommended answers to the network questions ([decision 0242](0242-the-owner-takes-the-recommended-answer-to-every-open-question.md), points 6 to 10): no sweep in the first design; on a network the person has not named, nothing is sent beyond the addresses named in a target, and the product reads only what the machine already knows; findings kept for the life of the run; the slices that send nothing come first. Research note [28](../research/28-how-a-network-can-be-seen-from-one-machine.md) found that most of what is worth knowing is already on the machine and readable by an ordinary user on all three systems, and that no maintained cross-platform crate reads the neighbour table or the owners of listening sockets.

## Decision

1. **What is built.** A kernel crate, `a2m-netstate`, with seven readers: the interfaces and their addresses (with the kind the system states: loopback, wired, wireless, virtual, tunnel, other; and up or down), the routes and each family's default routes, the name servers and search domains, the neighbour table as the system holds it, the listening sockets with their owners where this user may see them, the proxy setting as the system states it, and the standing: for each interface, the kind of place each of its addresses is, read with `AddressScope` from [decision 0240](0240-one-typed-reading-of-where-an-address-is-and-one-question-of-a-plain-link.md), and which interface carries each family's preferred default route. Each reader returns typed facts or one typed failure: `net_fact_refused` (`edge_blocked`), `net_reader_not_built` and `net_answer_unreadable` (`unknown_variant`), `net_read_failed` (`transient`). A field the system does not state is absent; a field left out on purpose is named with its reason. Every list is bounded, and a reading names what a bound cut.
2. **Nothing is sent, held three ways.** By construction: the crate's dependencies are `a2m-core`, `serde`, and, per system, `rustix` (its socket calls, for route-netlink), `libc`, and `windows-sys`; none is an HTTP, name-resolution, or socket library, and the design lists every system call the crate makes. By its source: a test reads every source file and refuses any call that connects, listens, binds, sends, or resolves, any Windows call that sends or changes a table, and any read of another process's command line or environment, and it holds the one send there is, on Linux, to a route-netlink request addressed to the kernel, of the four `GET` dump types. By a run: on Linux, a test runs every reader in a child process inside a new network namespace that holds only loopback, and gets that namespace's facts (one interface, down, no address, no route, no neighbour, no listener). The test passed here. Where a system refuses a new namespace, the test says so and passes, unless `A2M_REQUIRE_NAMESPACE=1` makes the refusal a failure.
3. **Where it lives.** Layer 2, Foundations, beside `a2m-vault`, which also reads per-system interfaces. The built-in actions that serve these facts are kernel actions in `a2m-actions` (layer 7), which may not depend on a pack, and the place derivation that follows (slice N2) belongs in `a2m-provider` (layer 5) and needs the machine's own subnets: layer 2 is below both. The crate depends on nothing but the shared types.
4. **Privacy.** A hardware address is serialized as its length and whether it is locally administered, never its octets; the typed value keeps the octets for the kernel's own later use (a network's fingerprint), and an action that serves the facts takes no input that reveals them. No host name is read: no reverse lookup, no hosts file, not the machine's own name. The wireless network's name is not read: it is absent, with the reason `needs_location_permission` on Windows and `not_read` elsewhere. A listening socket's owner is named by its process id and its program's file name, never its command line or environment (rule 4). A proxy value loses any user name, password, query, and fragment before it is kept. Interface names, addresses, routes, name servers, and search domains are returned whole: they are what the system's own settings show the person.
5. **The proxy is read, never applied.** [Decision 0197](0197-no-client-takes-a-proxy-from-the-environment-and-stand-only-protocols.md) stands: no client takes a proxy from its surroundings. Reading the setting to show it is a different act (note 28, finding 14). On Windows the reader reads the current user's stored setting and fetches no automatic-configuration script.
6. **No new outside crate.** `libc` 0.2.191 (MIT OR Apache-2.0) is added to the workspace's list of dependencies; it was already in the tree of `tokio`, `rustix`, and `getrandom`. `rustix` 1.1.6 gains its `net` feature in this crate, and `windows-sys` 0.61.2 gains `Win32_NetworkManagement_IpHelper`, `Win32_NetworkManagement_Ndis`, `Win32_Networking_WinSock`, `Win32_Networking_WinHttp`, and `Win32_System_Threading` in this crate. `cargo deny check licenses bans sources` passes. The lock file gained no package. Every `unsafe` block is a call into the system or a read of what it wrote, each with its reason; on Windows and macOS the tests that call every reader exercise them.

## What only CI can prove

The Windows and macOS readers were written on Linux, compiled, and linted for `x86_64-pc-windows-msvc` and `aarch64-apple-darwin`. Their first run is CI's: `tests/windows_and_macos.rs` holds loopback present and classed as this machine, each default route's interface in the interface list, a socket the test opened listed with this process as owner (Windows), the IPv4 neighbours `arp` lists present, and on macOS the interfaces `ifconfig -l` lists present and an IPv4 default gateway that `netstat -rn` lists. The layouts of the IP Helper records, the routing-socket messages, and the address rounding on macOS are as their headers and bindings give them, and are unproven until that run. That an ordinary user sees the same as root, and sees the owners of only their own sockets, is the systems' documented behaviour (note 28) and was not run here: the session runs as root.

## What this slice does not do

| It does not | Kind |
| --- | --- |
| Send anything to another machine, on any network | Rule: [decision 0242](0242-the-owner-takes-the-recommended-answer-to-every-open-question.md) point 7 for an unnamed network; for this crate, its purpose |
| Read the listening sockets' owners or the proxy setting on macOS | Not yet: `libc` carries no socket record for `proc_pidfdinfo`, and the system configuration's proxy dictionary needs its own bindings; each answers `net_reader_not_built` |
| Read the wireless network's name | Not yet: it needs the person's location permission on Windows and perhaps on macOS (note 28); asking is a later slice and the person's act |
| Say whether an Ethernet-framed interface on macOS is wired or wireless | Not yet: the link-layer type does not say; the system configuration does |
| Read a desktop's proxy setting on Linux, or systemd-resolved's per-link servers | Not yet |
| Read policy-routing tables or multipath next hops on Linux, or interface-scoped routes on macOS | Not yet |
| Recognize the network (a fingerprint), derive a place, or keep a reach | Not yet: slices N2 and N3 of the network-awareness design |
| Serve the facts as tools | Not yet: the action registry is wired by its own owner; the actions are proposed below |

## The actions proposed for the registry

Six reads and the standing, each a local user's, listed in no toolset, with no input, effect `read`, and the facts' serialized form as output: `net.interfaces`, `net.routes`, `net.resolvers`, `net.neighbours`, `net.listeners`, `net.proxy`, `net.standing`. The exact catalog lines are given to the owner of `a2m-actions`. Each serves the default serialized form, which leaves out what point 4 leaves out; none takes an input that reveals more.

## Alternatives weighed

- **A pack crate, a2m-pack-net, at layer 10, registering its reads as provider actions.** The plan's proposal for the later rungs. Refused for this rung: the built-in actions and the place derivation are kernel and would reach these facts only through the registry, and rung 0 knows no kind of system beyond the machine's own stack, which every networked pack shares. The pack is still the home of the rungs that send.
- **The readers inside `a2m-actions`.** Fewer crates. Refused: `a2m-provider` will need the same facts for the place of a destination, and a layer-7 crate cannot serve layer 5.
- **Outside crates for the readers** (`netdev` for interfaces and the gateway, `listeners` or `netstat2` for sockets, `hickory-resolver`'s system configuration for name servers). Fewer lines here. Refused: none reads the neighbour table; each brings a tree, and a resolver crate is a library made to send queries, which would weaken the first of the three holds. The system interfaces are few and already in the tree.
- **Reading `/sys/class/net` and `/proc/net` alone on Linux.** No netlink socket at all, so no send of any kind. Refused: `/proc` gives no IPv4 interface address in a plain form and no IPv6 neighbour, and `/sys/class/net` shows the namespace that mounted it, not this process's; the namespace test showed it naming the host's interfaces from inside a new namespace. Route-netlink answers for the process's own namespace. `/sys` is still read, for wired or wireless, only where it names the same interface by the same index.
