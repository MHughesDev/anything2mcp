# 0192. A served engine hands no root of the project that started it, and its clients start it and compare its settings

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-17

**Changes:** the designs of [`anything2mcp`](../architecture/crates/anything2mcp.md), [`a2m-local`](../architecture/crates/a2m-local.md), and [`a2m-auth`](../architecture/crates/a2m-auth.md), and the Python and Node clients. Settles S4, S5, and S6 of [decision 0181](0181-the-product-and-the-local-engine-take-up-what-the-kernel-now-offers.md); the open point of [decision 0165](0165-a-client-starts-the-engine-on-demand-detached-and-gives-it-the-passphrase-on-a-pipe.md) on the Python client; brings the OAuth providers into line with the loopback rule of [decision 0188](0188-credentials-over-plain-links-drafted-workbooks-and-published-device-maps.md); and shows on the approval page the bindings [decision 0185](0185-a-record-with-no-key-is-never-proved-absent-by-one-look.md) binds a write to.

## Decision

| Point | Built | Alternative weighed |
| --- | --- | --- |
| A name is never a loopback address, in `a2m-auth` | One function, `link::loopback`, judges an address as the HTTP client parses it: an IP address in `127.0.0.0/8` or `::1`, and nothing else. `localhost`, `localhost.`, any other name, `::ffff:127.0.0.1`, `0.0.0.0`, and `::` are not loopback; `127.1` is `127.0.0.1`, as it is when it is sent. The token and authorization endpoints of the OAuth providers use it; the TLS helper judges no address. A developer whose identity service on this machine was named `http://localhost:<port>/...` now writes `http://127.0.0.1:<port>/...` (or `http://[::1]:<port>/...`), or serves it over `https`; the old address is refused `auth_settings_invalid` with words that say so | Counting `localhost` as loopback: a hosts file or a resolver can send it anywhere, and the packs already refuse it |
| The roots a served engine hands the packs | Reproduced with the built binary: two copies of the `stockfiles` project, an engine started on demand from A, and a read of the stock file from B read A's file. An engine that serves every project's requests (`serve`, and one started on demand) now hands the packs no `files` root: a pack that took it from its roots resolved it against the folder the engine was started in. Its `project` root is kept: no pack resolves a path through it (the data and file packs resolve `project` against the checked project folder the kernel hands each run, decision 0176), and the file driver counts it as a root it has. An engine a command runs inside itself, or a host embeds, serves one project and keeps both. Proven through the binary, with one engine serving two projects: a surface in `project` reads each project's own file, whichever project started the engine; a surface in `files` is refused `policy`/`effect_not_declared` in both, and never reads A's | A registry per project, which one kernel cannot hold; refusing a request from another project than the engine's, which fails B because A started the engine; leaving it as it was, which reads another project's files |
| What the kernel's half is | Not built here: `files` (`<project>` in `files.allowed_roots`) resolved per request as `project` is. It needs a root of `a2m-provider` that stands for the request's project folder, which the file pack's driver resolves with the run's `CheckedPaths` and counts in its health, and which the dispatcher hands a provider action with the call's folder. Until then a `files` surface works only in an engine a command runs inside itself | |
| S5, blocking calls in start on demand | `Connector::connect_or_start` takes the `Launch` by value; the start (the output file, the process, the passphrase on its pipe) runs on a blocking thread that owns it. The bridge reads the settings files for its plan on a blocking thread too. The command line still makes its plan on its one async thread before it looks: it serves no one else meanwhile | An `Arc<Launch>` asked of every caller: the launch is made fresh for each start |
| S6, a later client's settings variables | The engine's hello names each settings variable it was started with (`A2M_<GROUP>__<KEY>`) by its name and a digest of its name and value, never the value (`Channel::with_start_variables`). A client compares its own (`Link::start_variables_differing`); when any differ, a command adds the warning `settings_differ`, naming each variable and no value, to the result's `warnings`, and the bridge says it on standard error. The engine serves with its own settings and is never restarted: it may have runs in hand. The fix tells the person to stop it with `engine stop` once nothing is in hand. Proven through the binary: a later command with another value, and one with none, are told by name; one with the same value is told nothing; one engine was started | Carrying the client's variables in each request for the engine to apply: settings are loaded once and gate the whole kernel; restarting the engine for a client: it may hold runs and approvals |
| S4, Windows | `prepare_dir` makes the runtime directory, or refuses one that is a link or that neither this user nor the Administrators group owns, and gives it a protected access list naming only this user, which the lock files inside take. The engine's output file is opened without following a link, refused when another owns it, and given a protected access list of its own naming only this user. Written in `os/windows.rs` beside the pipe's access list, from the same calls | A check without a change, as on Unix the folder is narrowed: a list another program can widen is narrowed again at every start |
| The clients on an engine that is not running | `connect` in Python and Node, on `engine_unreachable`, runs the installed program's `anything2mcp engine start --json` (with `--project` when given), which starts the engine on demand as any command does and waits for its hello within its own 30 seconds; the client waits at most 60 seconds for it, then connects once more. The program is the one the wheel installed (`binary_path()`) or the platform package holds (found as the launcher finds it), or the one `binary` names. `start=False` (Python) and `{ start: false }` (Node) start nothing, as before. A program that cannot be run, or that does not start one, is `engine_unreachable` or the program's own failure | Starting the engine from the client: a second implementation of the start lock, the detached start, and the passphrase's pipe |
| The approval page, after decision 0185 | Beside each record, after the words for a write that is not read back: the binding the approval binds it to, by its mode, and what its evidence means for whether the write is read back; for a record whose binding is chosen later, `BINDING_LATER` and every binding it could take, each with what its evidence means; `MAY_NOT_BE_READ_BACK` in its own sentence. Every word escaped | Showing the evidence's word alone: `response` and `acknowledged` do not say to a person whether anything is compared |

## Consequences

- Each point has a test that fails without it: `only_an_ip_address_in_the_loopback_range_is_loopback_and_never_a_name` and the OAuth endpoint test (`a2m-auth`); `a_served_engine_never_resolves_a_root_against_the_project_that_started_it` and `one_engine_serves_two_projects_and_each_read_resolves_its_files_in_its_own_project`, `a_client_whose_settings_variables_differ_from_the_engines_is_told_by_name` (`start_on_demand.rs`); `the_hello_names_the_engines_start_variables_by_digest_and_a_client_learns_which_differ` and `a_record_whose_binding_is_chosen_later_shows_every_binding_it_could_take_and_what_each_means` (`a2m-local`); the clients' `a client that finds no engine has the program start one and is answered`. S5 has no test of its own: the start-on-demand tests still pass.
- `two_pages_of_one_screen_are_drafted_into_reads_by_key_in_the_product` (`web_draft.rs`) proves decision 0187 through the product's registry, the one place both web crates meet.
- A `files` surface read through `serve` or an engine started on demand stops by name until the kernel's half is built.
- Not run on Windows: the next Windows CI run must show `kept_to_the_user::the_runtime_directory_and_the_output_file_are_kept_to_this_user` passing in `a2m-local`, with the start-on-demand and channel tests. The Windows code was compiled and linted for `x86_64-pc-windows-msvc` outside the workspace, because the crate's tree builds SQLite.
