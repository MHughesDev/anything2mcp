# 0250. One check of who may change a program, and the MCP pack's local server on Windows

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-18

**Changes:** the provider contract (a public function moves into it, and the supervisor gains a link), [section 304](../spec/3-packs/304-the-mcp-pack.md), [section 306](../spec/3-packs/306-the-command-pack.md), and the designs of [`a2m-provider`](../architecture/crates/a2m-provider.md), [`a2m-pack-mcp`](../architecture/crates/a2m-pack-mcp.md), and [`a2m-pack-command`](../architecture/crates/a2m-pack-command.md). **Builds on** [decision 0216](0216-the-command-pack-on-three-systems-the-administrators-group-and-a-script-the-target-keeps.md), whose check it moves, and [decision 0204](0204-one-plain-form-of-a-path-a-pipe-that-is-waited-for-and-a-socket-path-that-fits.md). **Answers** findings PR-1, PR-2, and PR-4 of the fifth safety audit, and its minor findings on the command pack and the supervisor.

## Context

The first release is for Windows, macOS, and Linux alike ([decision 0208](0208-the-first-release-reaches-what-the-persons-machine-reaches-and-serves-on-that-machine-only.md)). The MCP pack started a local server program on Linux and macOS only, and answered `not_built` on Windows, where most of the MCP servers a person has are local programs.

What the MCP pack checked before a start, found in the code:

- **On Linux and macOS:** that the plan declares the program for the surface with the digest the surface states, and that no variable it is given is one of the engine's or named for a credential; then the supervisor's own checks: an absolute path, the declared digest taken through one opened handle, the engine's variables never copied. **Nothing checked who may change the program's file or the folders on the way to it, and nothing refused a shell, an interpreter, or a `#!` script.** A program another user could replace was started as long as it had not been replaced yet. That was a weaker line than the command pack's, which walks the whole path ([decision 0216](0216-the-command-pack-on-three-systems-the-administrators-group-and-a-script-the-target-keeps.md)).
- **On Windows:** nothing was started.

The command pack's check lived in that pack, and a pack may not depend on another pack. The fifth safety audit then found three faults in the command pack's code around it.

## Decision

**1. The check moves into the provider contract.** `check_program(path, &ProgramTrust, ProgramRole) -> Result<(), ProgramRefused>` is public in `a2m-provider` (its Unix half in `src/supervisor/program.rs`, its Windows half in `src/supervisor/program/windows.rs`), with the typed refusals it had (`NotAbsolute`, `Missing`, `Script`, `Writable`, `Unreadable`, `Link`, `Elsewhere`), and its tests moved with it. The list of shells and interpreters moved with it (`is_shell_or_interpreter`), so the name list is kept once. The trusted groups are a value, `ProgramTrust::with_groups(ids)`; the setting `packs.command.admin_groups` stays the command pack's and is read where it was. The command pack calls the shared function through a thin module of its own names; its whole test suite passes unchanged, and a table test (`the_shared_check_gives_the_verdict_the_packs_own_gave`) gives a frozen copy of the old check and the new one every case the old tests held, for both roles and three sets of groups, and finds the same verdict. Two roles are added: `Script`, a file the engine wrote, and `Folder`, a folder it made; each is walked like a program's path, without the name and first-bytes checks.

**2. The MCP pack calls it before every start, on every system,** as a program (`ProgramRole::Program`), with no group named beyond the system's own (on macOS the group 80). A refusal is the pack's new code `policy`/`program_path_unsafe`; a program that is not there is the contract's `input`/`program_not_found`. The MCP pack gets no setting of its own for groups: a setting that loosens is something a person turns on deliberately, and a second one in a second pack is a second place to get wrong. If a person needs it, it is added then (Not yet).

**3. Batch files, scripts, and interpreters.** For the MCP pack a batch file, a command script, a `#!` script, and an interpreter by its name are refused on every system. The alternative weighed was the command pack's fixed pair: an interpreter in its one form, with the script pinned by digest. Without that pin the program the pack pins would be the interpreter, and what runs would be a script whose bytes nothing pins and which anyone who can write it chooses. Building the pair here needs a surface field for the script and the copy the command pack makes; it is the way to reach servers written as scripts, and is not built yet (Not yet). Most such servers are reached today by naming the program the language's packager builds, or over HTTP.

**4. A local server on Windows.** The supervisor gains `LinkKind::Standard` and `start_on_standard_streams`, on `Supervisor` and `ScopedSupervisor`. On Linux and macOS it is the foreign link with the pipes on descriptors 0 and 1, exactly what the MCP pack built before. On Windows the two named pipes the foreign link already makes are handed to the child as its standard input and output (the standard library hands the child a copy of each, made inheritable for that start alone, under the supervisor's one start lock), the child is started with `CREATE_NO_WINDOW` and `CREATE_SUSPENDED`, placed in its job object, and resumed, as every child is. The job ends every process in it when its handle closes, so the child and what it starts end when the run, the supervisor, or the engine ends; this is what the process group gives on Unix, where a group is signalled whole. Standard error goes to the null device on every system: that is what the Unix half did, so a program that writes without end to it is not held up and nothing of it is kept. The environment is the supervisor's on every system: cleared, then only what the surface sets and passes, the owner mark, and on Windows `SystemRoot`, which the MCP pack adds to what passes because a program there cannot load the system's libraries without it. Every read and write of the link is bounded by the step's deadline, as before. The arguments are handed to the standard library as a list; it writes them as the Microsoft C runtime parses them, so a program that parses its line by that rule, as the stand does, receives them element for element. No new dependency.

Alternatives weighed for the Windows link:

- **The standard library's own piped streams** (`Stdio::piped`). The runtime reads them on a blocking thread on Windows, and they would be a second kind of pipe beside the named pipes the supervisor already makes, proves, and tests. Rejected.
- **A process group without a job object** (`CREATE_NEW_PROCESS_GROUP`). It lets a console signal reach the tree, and ends nothing a child starts outside the group, and nothing when the engine dies. Rejected; the job object was already built and tested for every child.
- **Changing `ForeignPipe`.** A field would have broken every pack that builds one. A new link kind adds and breaks nothing.

**5. The stand on Windows.** The MCP stand's local form was already a Rust program built by Cargo, started by its path, so it runs on Windows as it is. It now writes down each start in its state folder, as it saw itself: its arguments element for element, the names of its environment, its process identifier, and that of a process it starts on purpose (`--grandchild`); `--stderr-megabyte` writes a megabyte to standard error, and `--silent` never answers. The harness asks the system whether a process still runs (`ps` on Linux and macOS, `tasklist` on Windows) and ends one from outside (`kill`, `taskkill`), each started by its path. One harness for the three systems.

## The fifth safety audit's findings

**PR-1 (verified).** A declared interpreter could be any program, shells included; the guard on its fixed arguments was a list of bad flags that missed the Windows command interpreter's `/k` and `/r` and read `/C` by case; an empty list passed; and the fix text offered "none at all". Rust's standard library escapes a batch-file name's arguments for the command interpreter, and not those given to `cmd.exe` itself. **Fix:** a closed table in the provider, `interpreter_form`: the POSIX shell (`sh`, `dash`, `bash`) with no fixed argument, Python with `-I`, Windows PowerShell with `-NoProfile -NonInteractive -ExecutionPolicy Bypass -File`, `osascript` with none. These are the interpreters whose form a test proves on a system that has them; every other interpreter, and every other form, is refused until such a test exists, because a deny list of flags is a guess about every interpreter there is (rule 7). The interpreters that read their whole command line as one string, `cmd`, `command`, `wscript`, `cscript`, `mshta`, and batch files, are refused as interpreters by name. The lint `command.shell_program` and the driver's `prepare` both hold the table, the driver by the declared path and by the file it leads to. `/c`, `/k`, and `/r` count as code flags in either case. The fix text names the forms. **Tests:** `only_an_interpreter_of_the_closed_table_in_its_own_form_is_started` and `an_interpreter_that_reads_its_line_as_code_is_refused_by_name_as_an_interpreter` in the provider; `an_interpreter_in_a_form_other_than_its_own_does_not_compile` in `tests/script.rs`; `the_command_interpreters_options_that_run_their_value_are_known_in_either_case` in `src/kind.rs`. Each failed before the fix: the forms compiled, and `/k` was no code flag.

**PR-2 (verified).** `env.set` and `env.pass` refused the engine's variables and credential names and nothing else, and the MCP pack the same. **Fix:** one closed list in the provider, `redirects_loading`: every variable beginning `LD_` or `DYLD_` (the dynamic loaders), `BASH_` and the names `ENV`, `SHELLOPTS`, `BASHOPTS`, `PS4` (the shells' start-up files, imported functions, and options), every variable beginning `PYTHON`, `PERL`, `RUBY`, `LUA_`, `COR_`, `CORECLR_`, and the names `GCONV_PATH`, `NODE_OPTIONS`, `NODE_PATH`, `NODE_REPL_EXTERNAL_MODULE`, `JAVA_TOOL_OPTIONS`, `_JAVA_OPTIONS`, `JDK_JAVA_OPTIONS`, `CLASSPATH`, `GEM_PATH`, `GEM_HOME`, `PHPRC`, `PHP_INI_SCAN_DIR`, `TCLLIBPATH`, `R_PROFILE`, `R_PROFILE_USER`, `PSMODULEPATH`, `DOTNET_STARTUP_HOOKS`, compared without regard to case. The command pack refuses them at compile time (`command.loader_variable`) and in the driver; the MCP pack at compile time (`mcp.environment_refused`) and in the driver; the supervisor refuses a launch that names one, `policy`/`variable_refused`, and never copies or sets one, for every pack. A pure allow list of names cannot work: programs take their own settings in variables of any name, and a pack cannot know them. The deny list is bounded by three things: the supervisor gives a child nothing of the engine's environment it does not list, the list is closed and kept in one place, and the publish review shows every variable a tool sets or passes (it does: `review.rs` of `a2m-files` lists them under each binding). `PATH` is not refused: programs need it to find their own helpers, and a target that sets it is shown at review. **Tests:** `a_variable_that_makes_a_program_load_other_code_is_known_by_its_name` in the provider; `a_launch_that_names_a_variable_that_loads_other_code_is_refused_and_nothing_starts` in `tests/supervisor.rs`; `a_variable_that_makes_the_program_load_other_code_does_not_compile` in the command pack; the MCP pack's variable tests, extended. Each failed before: the variables compiled and reached the child.

**PR-4 (verified).** `command_runs` and each run's folder were made with the process's defaults, and the copy of a script, checked by its digest, was opened by the interpreter afterwards. **Fix:** `CheckedPath::create_private_dir` and `create_private_dir_all` make a folder the engine's user's alone from the moment it exists: mode `0700` on Linux and macOS (the process's mask can only narrow it), and on Windows a protected access list granting the folder's owner, the local system account, and the Administrators group full control and nobody else anything. A folder that was there already is not changed. Then, after the copy is read back and immediately before the interpreter starts, the copy, its folder, and every folder on the way are held to `check_program` as a `Script`: if another user could change any of them, the run stops as `policy`/`program_path_unsafe` and nothing starts. The guarantee is the folders' privacy, checked at the start. Handing the interpreter the open, checked file was weighed: Linux and macOS offer `/dev/fd/N` for an inherited descriptor, which every interpreter in the table can read a script from; Windows offers no name for an open handle that an interpreter would open. One rule on every system was chosen; the descriptor route is the stronger one for Linux and macOS, and is the next step if the folder rule proves too strict. **Test:** `a_runs_folder_others_can_write_is_refused_before_the_script_starts` in `tests/script.rs` plants a `command_runs` everyone may write; before the fix the script ran. `a_private_folder_is_made_closed_to_other_users` in `tests/paths.rs` and `a_private_folder_passes_and_one_others_can_add_to_is_refused` on Windows.

**Minor findings.**

- **The interpreter's module path (M3): verified, closed by the table.** Python must be started with `-I`, which leaves the script's folder off its module path; the shell, PowerShell with `-File`, and `osascript` load nothing from beside the script. One folder per script was not made.
- **What the publish page says about a kept script: not fixed here.** The review summary of `a2m-files` is another package's; it should state that an interpreter surface runs the kept script as code, with the script's path and digest.
- **The code-flag gap (M4): fixed,** as PR-1.
- **`env.pass` copying engine variables (M7): verified and covered.** The engine's own variables were already never copied; a variable that loads other code is now refused in `pass` as in `set`.
- **`packs.command.admin_groups` under a moved home (M6): not changed.** That no layer may name a group there is the fail-closed behaviour decision 0241 is building; loosening it would weaken the protected setting.
- **Every interpreter run with the engine's rights:** a property of the pair, stated in decision 0216, and unchanged.

## What only a run on Windows or macOS can prove

The Windows and macOS code compiles and lints from Linux. None of it has run there; CI is its first run. These are the assumptions it rests on:

1. The standard library hands a `File` given as `Stdio` to the child as its standard handle, and a named pipe's client end opened for blocking use works as a console program's standard input and output.
2. `CREATE_NO_WINDOW | CREATE_SUSPENDED` together start a console program with no window and suspended, and the stand runs with no console.
3. A process the stand starts at once is in the job, and ending the job ends it, as the supervisor's own Windows tests already assume.
4. `tasklist /FI "PID eq N" /FO CSV /NH` lists a running process with its identifier as the second quoted field, and does not list one that has ended, even while a handle to it is open.
5. `taskkill /F /PID N` ends a process in a job, and the engine sees the end of its pipe.
6. `icacls <file> /grant *S-1-1-0:(W)` adds an entry the check reads as another identity's write.
7. The protected access list `D:P(A;OICI;FA;;;OW)(A;OICI;FA;;;SY)(A;OICI;FA;;;BA)` set with `PROTECTED_DACL_SECURITY_INFORMATION` passes the walk, the owner of a folder an elevated runner makes being the Administrators group.
8. The temporary folder of a Windows runner, and the folder Cargo builds the stand in, pass the walk, as the command pack's Windows tests already assume.
9. A path holding a space, an apostrophe, and letters beyond ASCII starts, and the stand receives the nine test arguments element for element, among them an empty one and two ending in backslashes.
10. On macOS, `ps -o stat= -p N` reports a process that has ended and is not reaped as `Z`, and the system adds no variable to a child's environment that the test reads as the engine's.

## Consequences

- The provider contract gains `check_program`, `ProgramRole`, `ProgramTrust`, `ProgramRefused`, `is_shell_or_interpreter`, `reads_its_line_as_code`, `interpreter_form`, `InterpreterRefused`, `redirects_loading`, `LinkKind::Standard`, `start_on_standard_streams`, `CheckedPath::create_private_dir` and `create_private_dir_all`, and the code `policy`/`variable_refused`. Nothing was removed or changed in it.
- The MCP pack gains the code `policy`/`program_path_unsafe`; its manifest digest changes. The command pack no longer depends on `windows-sys`.
- A server that an interpreter runs from a script is refused by the MCP pack on Linux and macOS, where it was started before. That is a tightening, by the line this record draws.
- The check of a script's copy walks every folder above `command_runs`. On a machine whose folders the user's group may write by default, a kept script is refused until they are closed or the group is named. The product crate makes `command_runs` with the process's defaults; it should make it private.
