# 0399. The desktop pack writes on Windows and macOS through a closed list of its own on each

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-24

**Changes:** the desktop pack's build order steps 6 and 7, its failure table, its invariants, and the statement in [its design](../architecture/crates/a2m-pack-desktop.md); [spec section 305](../spec/3-packs/305-the-desktop-pack.md) where it says writes stop as `writes_not_built` on Windows and macOS; the write half of the stand `targets/example-desk` on Windows and macOS, which [decision 0218](0218-the-desktop-pack-writes-on-linux-through-a-second-closed-list-and-reads-back-what-is-stored.md) built for Linux only. Carries out on Windows and macOS what decision 0218 settled for Linux, under the rule of [decision 0244](0244-the-desktop-pack-reads-macos-applications-and-proves-the-record-before-every-act.md), point 11.

## Context

On Windows and macOS the pack read applications (decisions 0209 and 0244, run in CI by decision 0278) and stopped every `set` and `invoke` as `busy`/`writes_not_built`. Decision 0244 put the proof that an act lands on the run's record, under no unnamed window, in the driver, above the back ends, for the two acting halves to inherit. Nothing here was run on Windows or macOS: the work was linted for `x86_64-pc-windows-msvc` and `aarch64-apple-darwin` from Linux, and its first run is CI's.

## Decision

1. **One acting half per system, apart from the look, as on Linux.** Each back end gives `Look::hands(&Proof)` a `Hands`, which only the driver's `set` and `invoke` make, with `prove`, `settable`, `set_text`, and `perform`, the same four the Linux half has. Each calls one function, `act`, which makes only the members of a second closed list: on Windows `ACT_MEMBERS` is the value pattern's `SetValue` and the invoke pattern's `Invoke`; on macOS `ACT_CALLS` is `AXUIElementSetAttributeValue` (of `AXValue` only) and `AXUIElementPerformAction` (of `AXPress` only). Tests hold each list against the members that act, and read each module's source: every call that acts is inside an `act` that names it, and every `act` is inside the acting half. The reads a set needs join each list of reads: on Windows `CurrentIsEnabled` and the value pattern's `CurrentIsReadOnly`; on macOS `AXUIElementIsAttributeSettable`, `AXUIElementCopyActionNames`, and the attribute `AXEnabled`. No member of any list sends a key or a pointer event. *Instead of* one acting interface the driver calls on all three systems through a trait: the three halves already share the driver's code, and a trait would be one more public shape for three private modules.
2. **The action a screen names is `click`, and only `click`.** AT-SPI names an element's actions, and a screen names one by `perform`. UI Automation and the accessibility interface have one press each: `Invoke`, and `AXPress`. On Windows and macOS the pack takes `perform: click`, the default, as that press; any other name is `unknown_variant`/`unexpected_control`, nothing sent. On macOS the element must also list `AXPress` among its actions exactly once. *Instead of* mapping more names (`press`, `activate`) to the same press: a name that means nothing more on these systems is a second spelling, and unknown means stop.
3. **Proof before every act.** At prepare the driver keeps a `Proof` on each system: the process, its start time (on Windows the process's creation time, on macOS the process table's), its program in the resolved form, and the digest the surface states. Before every act, on the back end's own thread, the acting half proves the process again by all four and, on Windows, that the element's process is it; a process that is no longer the one proven is `unknown_variant`/`application_not_proven`, nothing sent, as on Linux. The driver's `before_act` (decision 0244) then proves the record and the absence of an unnamed window on the walk the act uses; it now has a caller on all three systems.
4. **What is answered and what is in doubt.** A `SetValue` or `Invoke` that the system says failed because the element is not enabled is the application's answer, nothing done (`field_read_only` for a set, `unexpected_control` for a press). On macOS an answer that the attribute or the action is not supported is the same. Any other error after the call, and a job on the back end's thread whose answer did not come, is unknown: for a committing press, `possible_commit`/`no_confirmation`. The confirmation is waited for by events as on Linux; Windows hears no exit of the application, so there a walk that fails, or the deadline, ends the wait as `no_confirmation`.
5. **The stand learns to be written on Windows and macOS.** Each window gains the edit fields `New customer` (which cuts what is set to 24 characters) and `New status`, the read-only `Message`, and `Problem`, hidden but while Save refuses a value. A value a client sets (`WM_SETTEXT`, which the value pattern sends to a standard edit; `setAccessibilityValue:` on AppKit's field) is kept with its window and its label; a read-only or disabled field takes nothing and, on macOS, says its value may not be set. Save stores by the Linux stand's rule and words, now held once in the stand's library. The book of what is stored, the stores, the sets, the message, and the faults is shared by the two systems' windows (`child.rs`), and `Truth` reports it. The faults built there are a silent Save, a read-only field, a disabled field, another record after the key is read, and a dialog after the key is read; an application that exits after Save, a late confirmation, a second window, and a restart stay Linux's.
6. **The tests.** The tests of `tests/write.rs` that use only those faults run on all three systems; the three that need Linux's faults stay Linux's, and a test of a silent Save and its resume runs on Windows and macOS. They are gated as the read tests are: a machine that cannot give the stand a session skips them, and `A2M_REQUIRE_DESKTOP=1` makes that a failure. The test that a write stops as `writes_not_built` now runs only on a system with no back end.
7. **A management namespace of another machine is refused by the driver too.** The review already withdraws the statement of a binding whose surface names one. The driver's `schema` step now refuses one itself, before the management service is asked anything, as `policy`/`remote_namespace_refused`, a code of the pack's table and manifest. *Rule:* fail closed (spec section 224).

## Consequences

- `writes_not_built` is produced only on a system with no back end. Its meaning says so.
- Two things are from the bindings' documents and not run: that a standard Win32 edit's value pattern sets its text by `WM_SETTEXT` and a push button's invoke pattern clicks it, and that AppKit routes a client's set of `AXValue` and its question whether `AXValue` may be set to the field's `setAccessibilityValue:` and `isAccessibilitySelectorAllowed:`. CI's first run says.

## What would reopen it

A run on either system in which the stand records no set the driver made, or the press does not reach Save; an application whose press is not `Invoke` or `AXPress`; a need for a second action name.
