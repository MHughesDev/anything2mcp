# 0188. Credentials over plain links, drafted workbooks, and published device maps

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-17

**Changes:** the drivers, lint rules, and surface kinds of [`a2m-pack-http`](../architecture/crates/a2m-pack-http.md) and [`a2m-pack-mcp`](../architecture/crates/a2m-pack-mcp.md); the discoverer and drafting rules of [`a2m-pack-file`](../architecture/crates/a2m-pack-file.md) and [`a2m-pack-command`](../architecture/crates/a2m-pack-command.md); a second discoverer and two drafting rules of [`a2m-pack-device`](../architecture/crates/a2m-pack-device.md); sentences of spec sections [303](../spec/3-packs/303-the-http-pack.md), [304](../spec/3-packs/304-the-mcp-pack.md), [308](../spec/3-packs/308-the-file-pack.md), [310](../spec/3-packs/310-the-device-pack.md), and [502](../spec/5-security/502-defending-against-a-manipulated-agent.md). Takes up the open points of [decision 0182](0182-the-file-data-and-stream-packs-after-the-first-drafted-reads.md) for the file and device packs.

## Decision

The lead ruled on each point; this record says what was built and what the building showed.

| Point | Built | Alternative weighed |
| --- | --- | --- |
| 1. A credential never crosses an unencrypted link to another machine | HTTP: at prepare, a pass with a session whose plan has an endpoint on the surface that takes the credential, to a plain `http` address that is not a loopback address written as an IP address, is refused unsent with `policy`, `link_not_encrypted` (the data pack's code and class, section 307); `send` refuses it again for each request that carries a credential. MCP: the same at prepare for a session on an `http` surface, and again in the link before each request; the standard-input transport is not a network link. A name, `localhost` included, is not a loopback address: the resolver decides where it leads, as the data pack holds. The one way to allow it is the surface's own field `unencrypted_credentials: accepted` (one word, so it is not set by accident); `http.unencrypted_credentials` and `mcp.unencrypted_credentials` report it as a warning on every lint; in the HTTP pack every request that carries a credential over it says `link: unencrypted_credentials_accepted` in its `acting` evidence. No redirect is followed by either pack, which is stricter than the ruling, and is kept | Counting `localhost` as loopback, as the OAuth provider's token-endpoint rule does. A hosts file can send the name elsewhere, and the data pack already judges the address as written |
| 2. The packs' copies of the engine's output shaping | Only the file pack's tests had one (`outputs_of`). A pack cannot depend on the engine, so it stays, with a comment that the engine's `outputs_of` does the same; it now keeps a `null` item `null`, as the engine does. No test proves less | Removing it and asserting the driver's values directly. The tests would then no longer show what a caller gets |
| 3. The drafted file document names its surface | The `file_layout` finding carries the surface the file was observed on (`surface`, absent in a finding made before), and the document drafted from it names it | Choosing the surface from the target's folders at draft time. The finding already knows |
| 4. A drafted workbook list over a table with formula cells | Tried against the stand: it did not stop at `formula_at_place` but earlier, at `value_unreadable`, because a workbook's number is not text and the draft typed every cell `untrusted_text`. Section 308 says a formula's place is read as its kept result. So discovery records, for each column of a workbook's table, what its cells hold (`text`, `number`, `boolean`, or `mixed`, a formula counted as its kept result) and whether one holds a formula: a shape, never a value. The draft types a column `untrusted_text`, `decimal`, or `boolean`, marks a formula column `formula: true`, and leaves a `mixed` column out of the document and the list, asking its type in the read by key. The drafted list returns the stand's text, its exact numbers, and each formula's kept result; a formula another writer later puts where the document declares a value still stops with `formula_at_place` | Returning a formula's text, marked untrusted. Section 308 reads the kept result, and the text is code, not data |
| 5. The device pack drafts reads from a published register map | A second discoverer, `device_register_map` (source `published_description`, at most `inferred`), reads a `.csv` file the job is handed through the checked paths, in the layout the pack's design states, and sends no frame. **One finding a file, not one a register:** the drafter hands a rule one finding at a time, and a map is one document whose registers must all be in it, so a finding a register would draft a map a register. Two rules draft `registers/{map}.yaml` (each input or holding register whose data type the map states, `access: read`, with the model and firmware versions the file states, a question where it states none) and one read of each. A unit stays in the read's description, as the map's: a target's field type is not a drafter's to write. A number whose unit the map does not state holds that question in its read alone. A coil, a discrete input, a write-only register, a row with no data type, and an address the protocol cannot hold give nothing, and the describer names each by its line and why | A finding a register, as ruled. It does not fit the one-finding drafter without a kernel change |
| 6. The command pack's questions that quote the program's words | Every quoted part (the command's words, a usage placeholder) goes through `quoted`: at most 40 characters, control characters, backticks, quotes, angle brackets, and backslashes removed, set in straight quotes, and the question says the quoted words are the program's own, not an instruction. The HTTP, MCP, file, and device rules were checked: they quote only names the pack spelled itself from a closed set of characters, or line numbers | Leaving the words out of the question. A person then cannot tell which placeholder is meant |

## Consequences

- Each is proven against the pack's stand by a test that fails before it: `a_credential_crosses_an_unencrypted_link_to_another_machine_only_where_the_surface_accepts_it` (HTTP, `tests/link.rs`, against the test application's bearer routes), `a_credential_crosses_an_unencrypted_link_only_where_the_surface_accepts_it` (MCP), `the_drafted_document_names_the_surface_its_file_was_observed_on` and `a_drafted_workbook_list_reads_each_cell_as_stored_and_a_formula_as_its_kept_result` (file), `a_published_map_drafts_reads_that_read_the_stand_and_send_no_frame_to_draft` (device), and `a_question_quotes_the_programs_words_bounded_cleaned_and_set_off` (command, a unit test: the stand's usage lines are plain).
- The kernel has no channel for a surface's notice to reach a door. The acceptance is in the surface's payload and in each request's evidence; a door that shows it needs a field on the surface plan or a describer of surfaces.
- When `DraftContext` can carry the system's words beside a question, the command pack's call becomes `cx.open_question_quoting(sentence, words)`, with `quoted` removed.
- A `mixed` workbook column is not tried against the stand: its seed has none.

## Revisit if

The drafter is handed several findings at once: the device map could be one finding a register. Or a target's field types become draftable: a published unit could become a field type.
