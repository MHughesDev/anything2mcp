# 0168. The data pack reaches a server database with the guarantees of an embedded file

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-17

**Carries out:** build-order step 6 of the design of [`a2m-pack-data`](../architecture/crates/a2m-pack-data.md), with the client [research note 23](../research/23-server-database-clients.md) recommends. **Holds the server store to:** [decision 0141](0141-the-data-pack-holds-a-statement-to-one-read-or-one-keyed-write-and-a-connection-to-one-file.md), rule by rule. **Changes:** [spec section 307](../spec/3-packs/307-the-data-pack.md) where the code differs.

## Decision

1. **The client is `tokio-postgres` 0.7.18, with no default feature but `runtime`, behind the pack's feature `postgres`, off by default.** It brings `bytes` (already in the tree) and uses the workspace's `futures-core`. With the feature off the build, its manifest, its tests, and its size are what they were. Its tree passes `cargo-deny check advisories licenses bans sources` with no change to `deny.toml`. `tokio-postgres-rustls` 0.14.0 with `ring` was resolved in a throwaway project and passes the same check; it is not in the tree, because no encrypted link is built (point 4). *Instead of:* the blocking `postgres` crate, which would run a second runtime per connection. The pack's store interface blocks; a server connection waits on the engine's own runtime from the blocking thread the driver already uses, and the connection's task runs there, so that an ended link is seen at once.
2. **A server is its own surface kind, `database_server`, with the address key `host`.** A surface kind has one required address key, and `database` keeps `file`: a server surface cannot state a file, and changing the key would break every target that names a file. The surface states `store: postgres`, `host`, `port`, `database`, and optionally `schema` (`public` unless given). The statements file kind, its schema, the verbs, the lowering, and the plan's section are the same for both kinds; each kind has its own section. *Instead of:* one kind whose address means a file or a server by the store, which the kernel's one address key does not allow.
3. **The role and its password come from the session keeper's lease.** The only provider that holds exactly a user and a password is `http_basic`; the pack reads its basic-scheme value back into the two, and anything else a provider places stops the run as `input`, `credential_not_carried`. *Owed:* a provider or a placement for database identities in `a2m-auth`, which section 307 already asks for.
4. **The link is to a loopback address, written as an IP address, and to nothing else.** Off it, the run stops before anything is sent, as `policy`, `link_not_encrypted`. The workspace's TLS helper, the `tls` module of `a2m-auth`, gives an HTTP client builder and no rustls configuration, and its configuration offers the ALPN `http/1.1`, which a server that checks ALPN refuses. *Owed:* an accessor in `a2m-auth` for the configuration of a `Trust` with a caller's ALPN; then the encrypted link through `tokio-postgres-rustls`. There is no `sslmode`-like switch in a target file.
5. **One statement, of the declared form, by the server's words.** The form check has a second dialect. It quotes with `'` and `"` only, and refuses a text with escapes (`E'...'`, `U&'...'`) and a text in dollar quotes, because a reader that does not parse them can be made to read a word as quoted. It refuses `COPY`, `DO`, `CALL`, `LISTEN`, `NOTIFY`, `UNLISTEN`, `CREATE`, `ALTER`, `DROP`, `GRANT`, `REVOKE`, `TRUNCATE`, `VACUUM`, `LOCK`, `PREPARE`, `EXECUTE`, `DEALLOCATE`, `DISCARD`, `RESET`, `BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT`, `LOAD`, `SET` outside an update's assignments, the functions `set_config`, `current_setting`, `dblink`, and names beginning `pg_`, `lo_`, `query_to_`, `cursor_to_`, `dblink_`. Parameters are `$1`, `$2`, in order. A procedure (`CALL`) is not built.
6. **Every value is a parameter of the extended protocol, sent as text the server's input function reads, and read back from the binary form.** A decimal reaches `numeric` as its digits and comes back digit by digit at the column's scale; a date as `YYYY-MM-DD`; a `timestamptz` as the same moment in UTC, RFC 3339. A `timestamp` with no zone, a float, bytes, and every other type stop as `unknown_variant`, `value_kind_unsupported`. Binding a moment is still not built.
7. **The connection is held by the server's own settings, each read back.** At connect: `search_path` is the one schema, `standard_conforming_strings` is on, the server's text is UTF-8, a reader's transactions are read-only by default, the session and current role are the leased one, and idle transactions end after a minute. At every `begin`: `BEGIN ISOLATION LEVEL ... READ ONLY` or `READ WRITE`, then the transaction's access and the session's role are read back, so that a statement that changed either is found before the next one. A read that changes data with no word that says so (such as `nextval`) is refused by the read-only transaction and named `read_statement_wrote`. The server cannot describe a statement as read-only before it runs; the shape reports that it cannot say.
8. **The role is the last line, and the pack checks it.** At connect, a role that is a superuser, bypasses row security, may replicate, may make roles, or owns anything in the schema stops the run, as `policy`, `identity_is_administrator`, the code section 307 names. Before a write, the written table's owner is checked again.
9. **What a write reaches is asked of the one table, by its exact name.** One bounded query: the table in the schema, its triggers, rules, computed columns, tables that inherit from it, and keys of any schema that cascade from it. Every name the pack sends is quoted, and the server folds only names that are not quoted, so the name is compared exactly; a trigger written `ON CUSTOMERS` is on `customers`. The cap of 2000 tables does not apply; it still applies to discovery.
10. **A write.** One statement in a transaction; the server's own count of rows changed, exactly one, before `commit`; the version guard; the pack's read by key after it. A lock wait ends at nine tenths of the step's time, before the statement's own limit, so a held lock is named `busy`, `store_locked`. A serialization failure and a deadlock are also `busy`, `store_locked`: the server rolled back and nothing landed. Section 307 said `transient`.
11. **A lost answer to `commit`.** Found by the stand's relay: when the link ends after `COMMIT` was sent, `tokio-postgres` returns an error with no server code; that is `possible_commit`. When the server ends the session in answer to `COMMIT` (a terminated backend answers `57P01`, severity `FATAL`), the error carries a code; a code of the classes `08`, `57P`, `58`, or `XX` is also `possible_commit`, because the session's end says nothing about the commit. Any other code is the server's answer that it did not commit. A link the client already knows has ended sends no `COMMIT`, and is `connection_lost`, not sent.
12. **Limits.** The server's `statement_timeout` and `lock_timeout` are set for each transaction; the pack's own deadline interrupts by the server's cancel request. Rows past the limit are not kept, but the server still sends them until the statement ends: a portal with a row limit needs the client's transaction object, which the store interface does not hold. Bounded by the statement's time; written as an open point.
13. **A pool per surface and session.** Idle connections are kept by the driver under the surface, the session, and its epoch, at most two of each access. A connection is kept only when nothing in the run failed and no transaction is open; a new epoch closes the old ones. The embedded store keeps no pool.

## The stand

`targets/example-db` has a server side, `example_db::server`: the schema of `example` in PostgreSQL types, owned by `example_owner`, written by `example_app`, which owns nothing; a write log in the schema `stand` that a definer's function keeps; a relay on the loopback address that can lose the answer to a `COMMIT` or drop the `COMMIT`; a row lock held from another connection; ending a role's sessions; and control queries through the server's own client, `psql`, never through `tokio-postgres`. A test gets a server from `A2M_TEST_POSTGRES`, or starts its own on a Unix socket in a new folder, as the account `postgres` through `setpriv` when it runs as the administrator, and stops it when the test ends. With no server it says it skipped; with `A2M_REQUIRE_POSTGRES=1` it fails.

## Consequences

- Seventeen tests against the real server, each asking the server what it stored; five for the stand's server side; three of the server dialect's words; one of the server manifest.
- Section 307 is corrected where it differs: the surface kind, the role check's attributes, the class of a serialization failure, and the server stand as built.
- Not built: the encrypted link, a provider for database identities, procedures, binding a moment, a portal's row limit, the check of the server's version against the target's recorded identity.
- Not verified here: the Windows and macOS builds and runs. The tree has no C (no TLS); `cargo clippy --target` for both was run (see the design). macOS runners carry no server; the server tests there skip unless a server is installed.
