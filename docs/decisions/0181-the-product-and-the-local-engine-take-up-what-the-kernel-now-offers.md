# 0181. The product and the local engine take up what the kernel now offers

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-17

**Changes:** the designs of [`anything2mcp`](../architecture/crates/anything2mcp.md) and [`a2m-local`](../architecture/crates/a2m-local.md). Takes up the consequences of [decision 0176](0176-the-action-registry-takes-up-the-kernels-second-pass.md) for the command line and the approval page; flips the default of [decision 0157](0157-tls-is-switched-on-with-the-provider-stated-in-each-client.md) on the conditions [decision 0166](0166-https-in-the-product-trust-roots-at-engine-start-and-one-maker-of-clients.md) named; applies [section 224](../spec/2-kernel/224-when-the-engine-itself-fails.md) to an engine whose data directory is removed; and settles six findings of the second safety review of the two crates (S1, S2, S3, and L1 built; S4, S5, S6, L2, and L3 named below).

## Decision

| Point | Built | Instead of, and why |
| --- | --- | --- |
| What the system said, on the command line | The renderer prints `result.failure.said.text` on standard error on a line of its own, after the failure's message and fix, through `said_line`: `  The system said: "…"`, every control character, quote, and backslash shown as its escape, and every mark that turns the direction of text shown by the renderer's own escape. At a terminal the result's lines leave `said` out, so it is shown once; the JSON object carries it whole | Laying it out with the rest of the result. A newline in it would start a line that reads as the product's own |
| A write that will not be read back, on the approval page | After the record's heading and before its fields: "This write is accepted by the system, not read back. Nothing will read it back or compare it after it is sent.", in bold where it begins, from `PreviewRecord::not_read_back`, escaped | Words at the head of the page alone. The words belong to each record, and a change can hold both kinds |
| HTTPS by default | `default = ["tls"]` in the product crate. Decision 0157's four conditions hold: the TLS job passed on Windows, macOS, and Linux; every test of the product crate passes with the feature on; the product reads `network.trust_roots`; and the engine's shared test helper makes its client through the one maker. `--no-default-features` builds and tests the product without it, and an `https` surface is then refused `tls_not_enabled` as before | Keeping it off for the released build's flag alone. A default build that cannot reach `https` surprises every developer who builds from source |
| An engine whose data directory is gone | The engine lock in the data directory remembers which file it is (`LockPlace`: the device and file numbers on macOS and Linux). Before each request the product's layer asks whether that file still stands at its place; when not, the request is refused `busy`/`data_directory_gone`, nothing of it reaches the kernel, and the engine stops (`StopReason::DataGone`): `serve` ends with code 1 and that failure, and the next client starts a new engine. An idle engine asks the same when it looks at its holds, so an engine whose socket went with its data directory, and so gets no request, notices at its idle time; no timer of its own is added | A timer that polls the directory: a request is the next use the engine can see, and the idle look exists already. Going on with the store open: its file is unlinked, nothing a later engine opens would see what it writes, and a second engine could take a new lock and open a new store beside it |
| S1, a hello that is never answered | Every hello has a deadline, `HELLO_PATIENCE` (30 seconds); a look at the channel during start on demand also ends at the client's patience. An engine that bound its channel and stalls while opening ends the client with `busy`/`engine_unreachable`, naming the engine's output file | Raising the deadline only in start on demand. A bridge or a command that finds an engine stuck while opening would still wait for ever |
| S2, an engine that stops after it binds | A hello whose connection ends is `transient`/`connection_lost` with words that say the engine stopped while starting, and point at the output file. Start on demand takes it as "not answering yet" and looks on, so an engine it started that ends is told as one that ended before it answered, with the file | Telling the caller to run the command again. Each run would start another engine that fails the same way |
| S3, the started engine's output | Written to `engine-output.log` in the log directory, not to telemetry's redacted and rotated `engine.log`. On macOS and Linux a link at its name, a file another user owns, and a file swapped in while it is opened are refused (the start is then refused and the command runs the engine inside itself), and a file others may read is narrowed to the user | Sharing the one log: what a process writes on its standard error is not redacted, and a rename under an open handle takes the output with it |
| L1, an act whose input the page cannot show whole | The act page says so above the input, and a press of Carry out raises no prompt and carries nothing out (409); a decline still works. The page now says "If it is carried out, it is carried out with exactly this input" | Showing every value whole. A value has no bound the page could keep readable, and the approval page refuses a change it cannot show in full the same way |

**Plain `http` off the loopback address with a credential.** The documents: decision 0157 leaves a plain `http` surface off loopback in use, with its credentials, to the egress policy; [section 307](../spec/3-packs/307-the-data-pack.md) says the data pack never sends a credential over an unencrypted link to another machine; sections 303 and 502 say nothing of it for the HTTP and MCP packs. The code today: the HTTP pack accepts any `http` address and sends a session's bearer token or cookie over it; only an identity service's token address must be `https` or loopback. Not changed here; the packs' owner should weigh the data pack's rule for every pack.

## Not built, and what each needs

- **S4, Windows.** The runtime directory that holds `start.lock` and `engine.lock` is not checked on Windows, and the output file takes its folder's access list. It needs an access-list check of the directory, as `prepare_dir` does on Unix. CI on Windows must show the start-on-demand tests and the channel tests passing; nobody has run them there.
- **S5.** The start runs short blocking calls on an async thread (making the folder, opening the file, starting the process, writing the passphrase). Moving them onto a blocking thread needs `Launch` owned by the task.
- **S6.** An engine started on demand keeps the settings variables of the client that started it; a later client's own are not read, and it is not told. It needs a way for the hello to carry, or compare, a client's environment layer.
- **L2 and L3** are in `a2m-actions` (two identical asks at once give two acts; an act whose carrying-out task panics stays carrying). They are that crate's owner's.

## Consequences

- `PreviewRecord::not_read_back` and `failure.said` are shown where a person reads them.
- `cargo test --workspace` now builds every crate with TLS on, because the product's default turns on the features of the crates under it; the separate TLS job of CI now tests what the default build tests, and could test `--no-default-features` instead.
- A client that finds an engine stuck while opening ends in 30 seconds with exit code 4 and the file to read.
- On Windows a data directory that holds an open lock file can seldom be removed, so the check rarely has anything to see there; this build asks only that the lock file still stands at its place.
- Not run on Windows or macOS.
