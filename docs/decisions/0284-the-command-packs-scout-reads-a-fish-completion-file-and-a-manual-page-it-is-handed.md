# 0284. The command pack's scout reads a fish completion file and a manual page it is handed

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-18

**Carries out** point 2 of [decision 0276](0276-what-the-scout-may-learn-from-a-program-itself-and-by-which-means.md) for the command pack, as point 4 of [decision 0279](0279-what-the-three-surveys-left-open-against-decision-0276-is-settled.md) narrowed it: roadmap package X4, and the part of X1 that reads command metadata. **Changes** the command pack's manifest, its `command` finding, and its drafter; [section 306](../spec/3-packs/306-the-command-pack.md) and the [design of `a2m-pack-command`](../architecture/crates/a2m-pack-command.md) say the same. The evidence for reading these files as text is [research note 30](../research/30-what-can-tell-what-a-compiled-program-does.md).

## Context

The command pack's scout read only the help and version forms a target declares. A program whose help is thin stays a program the scout can hardly describe, while the same program often ships two text files that say more: a fish completion file, whose `complete` lines state each option, and a manual page. Research note 30 found no library under a licence this project takes that reads either, and decision 0279 settled that of completion files only fish's are data. What remained was how the pack reads them, where they come from, what a finding claims from them, and what the drafter may take.

## Decision

1. **Where the files come from.** The discoverer `help` declares two file names (decision 0263): `completions`, a fish completion file, and `manual`, a manual page. A person puts each in the project's `sources` folder and hands it with `scout run --files '{"completions": "sources/<file>", "manual": "sources/<file>"}'`. The registry takes the names from the manifest, so `a2m-actions` needed no change. The scout does not search the machine's own folders for either file.
2. **Nothing in a file runs, and the files are read first.** Both files are read before any help form starts. A file that cannot be read ends the discovery before any help form starts, as `input`, `command_file_unreadable`: it is not UTF-8 text, it is compressed in a form other than gzip, its gzip form is damaged, or it is no manual page in either macro family. Its whole text passes the redactor before it is read, and each description passes it again after its lines are joined, and is then cut to 400 characters.
3. **The fish reader** takes a line only when it is one `complete` call alone on its line, outside every block (`function`, `if`, `for`, `while`, `switch`, `begin`), with every argument literal text, `-c` naming the program by its file name, and at least one option named by `-s`, `-l`, or `-o`. The names on one line are one option. `-r` or `-x` says it takes a value; without either, the line does not say. `-d` is its description. A condition is read only as `__fish_use_subcommand`, which is the program as a whole, or as one or more `__fish_seen_subcommand_from` calls of literal command words joined by `; and` or `&&`. Every other line is counted as unread under one reason: `variable`, `command_substitution` (also inside an `-a` value, which fish works out when it completes), `condition`, `block`, `continued`, `more_than_one_command`, `other_command`, `another_command`, `names_no_option`, `not_literal`, `not_read_form`, `too_long`, `bound`. The values `-a` offers are checked to be literal and are not kept.
4. **The manual-page reader** reads the section `OPTIONS`; in an `mdoc` page without one, the tagged lists of `DESCRIPTION`. In the `man` macros an entry is a `.TP` whose tag line, plain or in a font request, begins with a flag, or an `.IP` whose tag does. In `mdoc` it is an `.It` of a `-tag` list whose head is `Fl`, with `Ar`, `Ns = Ns Ar`, and `,` between names. A tag such as `-f, --format FORM` or `--format=<form>` gives the names, a value, and its name; a tag with none says the option takes none. An optional value, an escape or a request the reader does not know, a nested list or block, and an entry of a list of another kind are counted as unread, by reason. A page named for the program lists the program's own options; a page named `<program>-<words>` lists those of the command with those words; a page named for anything else is read and every entry is counted `another_command`. A page compressed with gzip is inflated with `miniz_oxide`, which `a2m-sources` already brings, within the discoverer's byte bound, and its length and checksum are checked.
5. **What a finding claims.** Each handed file makes one `command_file` finding: its subject is the file, by its digest, as `fish_completion` or `manual_page`; it is `inferred` from `artifact`, the level [section 218](../spec/2-kernel/218-discovery-and-findings.md) gives what a system's files say and nobody has exercised; its coverage is `complete` only when nothing was left unread. It holds how many lines or entries were read, the unread ones by reason, the program's own options it states, and the words of commands it speaks of that the help does not list.
6. **A command's finding keeps every source apart.** Where a file states options of a listed command, that command's finding gains `options`: each option's names, what each source says of it (`help`, `completions`, `manual`: whether it takes a value, the value's name, the description), and `disagree` where one source says it takes a value and another that it takes none. Neither is chosen. Such a finding is `inferred` from `artifact` and derived from the file findings it used, because a finding is never stronger than the weakest thing it states. A command no file speaks of keeps the finding it had, at `discovered`, and its text is byte for byte what it was, so stored findings read as before.
7. **What the drafter may take.** A value's place that the usage line leaves untyped is typed `integer` when a file's value name or description says "whole number" or "integer". Otherwise its question quotes the file's description beside the place. A flag the sources disagree on is a question, never a parameter, and so is a flag that only a file states. `effect` is still never written (section 306).
8. **Bounds.** A file is read up to the discoverer's byte bound, 1 MiB, before and after it is inflated; a logical line of a fish file up to 4,096 bytes and 64 arguments; at most 2,000 options from one file, the rest counted `bound` and the finding marked `truncated`.

## Not built, and a possible next step

Not built: the values a completion line offers; the program's own options section of its help; options described outside `OPTIONS` in a `man` page; `.TQ`; a page compressed in a form other than gzip. **Reading the system's own completion and manual folders** for a program the person named is a possible next step. It needs first: which folders on each system, and whether a person names them or the pack's manifest does, as read roots, so that no input chooses a path ([section 502](../spec/5-security/502-defending-against-a-manipulated-agent.md)); how a program is matched to its page when two installed programs share a name, and to which installed copy a page belongs; and whether a page reached through a link out of those folders is read.

## Alternatives weighed

- **A second discoverer that reads only the files.** It would start nothing at all. But the comparison with the help needs the help's usage lines in the same pass, and a drafting rule sees one finding at a time, so the drafter could not use what the files say. Not taken.
- **A finding of its own for each option.** It would keep each claim apart as a finding. The drafter, which reads one `command` finding at a time, could then not type a parameter from it. Not taken; the `command_file` finding holds what fits no listed command.
- **Keep the command's finding at `discovered` with the files' options inside.** It would claim more than a file supports. Not taken.
- **Treat a fish option without `-r` as one that takes no value.** Many completion files leave `-r` out of options that do take one. Not taken: the line says nothing either way.
- **Type a value as a choice from the values `-a` offers.** A completion offers values; it does not say they are the only ones. Not taken.
