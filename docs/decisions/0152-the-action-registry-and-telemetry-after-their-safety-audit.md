## Context

A safety review read both crates against their designs and the ten rules, and ran nothing. It gave `a2m-actions` five serious and fourteen minor findings (A1 to A19) and `a2m-telemetry` one serious and four minor (T1 to T5). Each was checked against the code, with a test against the built-in test application wherever one could be written. Every finding was confirmed; one was confirmed in part.

## Decision

### The action registry

1. **A run is its person's alone** (A1, confirmed). `run.get`, `run.resume`, and `run.cancel` answer for a run only to the person who started it, or to a caller proved to act for that person; anyone else is told there is no such run, whatever role they hold. A run acts under its person's session, and a session is its person's alone. `trace.show` stays bound to the workspace: reading a run's evidence is what the auditor's role is for, the dispatcher's decision is that the caller holds it, and it resumes nothing. A resume no longer rewrites what was kept of the run's caller: the guard asks about the caller that started the run, and the handler asks the policy engine, and records the answer, whether whoever resumes may use the run's tool (section 212, step 9). *Instead of:* keeping the resumer's facts in place of the starter's, which let a resume change whether the caller counts as an agent.
2. **The protected policy settings are in force, or the kernel stops with the setting's name** (A2, confirmed). Whether something may happen is the policy engine's to decide, so a setting about it is in force only as far as the policy engine decides by it. The policy engine is opened with the built-in set of the profile (`BuiltIn::local(user, workspace)` or `BuiltIn::server()`) and nothing else: `a2m-policy` offers no way to open it with other settings, and a set published from the settings at start would stay in force after the setting is taken out, and could not be read by a later binary. So six settings have exactly one true value, the one that built-in set works by: `policy.approve_writes`, `policy.max_records_per_run`, `policy.approval_window_minutes`, `policy.agent_effect_ceiling`, `policy.writes_outside_tests`, `policy.two_person_irreversible`. Any other value impairs the policy part: the kernel is `stopped`, serves its status, `doctor.run`, and `config.show`, which marks the setting `in_force: false`, and nothing else. The built-in presets `cautious` and `ci` set such values and stop the kernel the same way until the policy engine carries them. Carried today: `policy.pre_approval` (with it off, the guard never begins a write on a pre-approval, whatever the set in force says), `policy.preview_freshness_seconds` (the engine's freshness window), and `files.allowed_roots` (point 3). The question "may this write proceed without a person" now carries the run's record count and the tool's hazard, without which no pre-approval rule could apply and the hazard guardrail could not see a hazard. *Instead of:* enforcing the limits in this crate beside the policy engine, which makes a second decider whose refusals `policy.explain` cannot explain; and instead of showing them and keeping none.
3. **A project folder is bounded** (A3 and A15, confirmed). It is stated by the client end of the local channel, which runs as the person; nothing in a tool's input, a path, a query, or a body can state one, so an MCP caller cannot. Whoever can run that client can state any folder, so the dispatcher takes one only when all of this holds, with every link followed: it exists; it neither holds nor lies inside one of the engine's own folders; it is not the home folder or a folder above it, not inside a hidden folder of the home folder, and not inside (or holding) a folder the operating system gives programs for their data, the folder for temporary files excepted; it holds a project file, `anything2mcp.toml`, that is a file and reads as a settings file; and it is inside what `files.allowed_roots` allows. The setting's default, `["<project>"]`, means any folder that holds a project file: the local engine serves commands run in several projects, so "the folder the engine was started in" would be wrong. A full path in the list allows the folders inside it; without the word, only those. The handler is handed the folder as resolved, not as stated. A source file is read only from the project's `sources` folder, with no hidden part, through the checked-path type, which follows a link only while it stays inside the project; what stands at the name must be a file, and it is at most the smaller of `files.max_upload_bytes` and the engine's source limit. *The route that remains:* a program that runs as the person and can write a project file into a folder of theirs can make that folder a project. It can also read the folder itself.
4. **A proof of presence is checked where it is used** (A4, confirmed). `PresenceProof` says which kind of check was passed, whose it is, when, and, with `naming`, which prompt answered. The desk refuses a proof that is not the approver's, is older than two minutes by the store's clock, or is ahead of it, and writes what the proof says to the audit log in the transaction that records the approval; a refusal is written too. The dispatcher checks a proof the same way against its caller. `PresenceProof::new` keeps its signature. Nothing in the type system stops another crate from making a proof: the crate that raises the prompt is above this one. What a proof is worth is decided by which person surface the product crate mounts. *Instead of:* a constructor private to this crate, which would put the prompt below the crates that own it.
5. **A run whose stored call is missing or cannot be read is not run** (A5, confirmed). It ends as `failed` with `busy`, `run_call_unreadable` (as `cancelled` where the ledger allows no other end from the state it rests in), or stops when a record of it is in doubt, so that the doubt stays in view. No reconcile is queued for it.
6. **The dispatcher asks for presence when an act loosens** (A6, confirmed). `PersonNeed::PresenceWhenLoosening` is enforced at step 5: releasing a kill switch asks; an action that has not said how its loosening is told asks on every call.
7. **Smaller changes.** The handler of `tool.call` refuses a tool whose effect is not the one the decision was made for (A7, `busy`, `tool_changed`). Any refusal of "write without a person", not the kill switch alone, stops the write (A8). Whether a record is in doubt is read from the ledger, and is yes when it cannot be read; a job that could not be carried through stops its run (A9). An action that changed something fails when its audit entry cannot be written, and a kill switch and its entry are one transaction (A10, A13: the switch is set in the policy engine first and released there last, so a failure between the two writes leaves the stricter state). `Request` and `Call` print field names only, and `secret.set` takes the value out of the call and overwrites the bytes it came in (A11). File work of the build actions runs off the async threads (A12). `status_only_caller` is a principal of no installation, which holds nothing (A14). The plan cache is keyed by target and hash and bounded, as are the notes of modes and budgets (A17, A18).
8. **Limits that stand, stated in the design** (A16, A18 in part, A19). With `A2M_HOME`, and on Windows without `PROGRAMDATA`, the installation's folder is one the user can write. `policy.explain` cannot check a decision's workspace until `a2m-policy` gives it. The runner's wait after a failed claim is an interval between tries, because the store gives no notice that it can be asked again.

### Telemetry

9. **A text artifact is checked as it is kept, cleaned, and with its character references written out, and dropped on a hit** (T1, confirmed). The kept bytes hold their markup, so they cannot be cleaned; the forms a reader would see are checked instead. Relied on from the redactor: that it finds a registered secret anywhere in the text it is handed. *Instead of:* keeping the cleaned text, which is no longer the snapshot.
10. **Smaller changes.** `check_trace` works the chain out again from the lines; `trace.show` reports the result and gives no signature for a broken trace (T2). `StepRecord`, `TracedValue`, and `Detail` print no value (T3). Log text loses hidden characters and is redacted again (T4). A log file is made with mode `0600` on Linux and macOS (T5).

### Taken up from other audits

11. A job of a writing tool names what it holds alone, from `Engine::exclusive_needs` and `ResourceKey::held_alone`. The in-process lease is at least ten minutes, which covers a binding of nineteen steps at the default limit. The desk shows a masked value as the mark alone. A system job handed to the in-process loop is never answered as done. `next_events` returns when a run comes to rest while it waits; `tool.search` filters by kind; `McpResultFace::of_in` names `a2m_action_run` where a toolset does not list the next action; `PersonSurface::presence` reports what the prompt can do, for `doctor.run`; `Kernel::second_person` exists behind the `testing` feature.

## Consequences

- A setting file that tightens a policy limit, and the presets `cautious` and `ci`, stop the engine until `a2m-policy` can be opened with the installation's settings and gains rules for an agent's ceiling, test records, and a second approver. The wanted change is `BuiltIn::with_settings`; when it exists, `bounds::held` drops the rows it covers.
- A folder with no project file is no longer a project, and a source file outside `sources` is refused.
- A proof of presence made with a time other than now is refused.
