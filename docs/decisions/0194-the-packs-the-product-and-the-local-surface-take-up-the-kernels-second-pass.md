# 0194. The packs, the product, and the local surface take up the kernel's second pass

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-17

**Changes:** the designs of [`a2m-pack-file`](../architecture/crates/a2m-pack-file.md), [`a2m-pack-command`](../architecture/crates/a2m-pack-command.md), [`a2m-pack-http`](../architecture/crates/a2m-pack-http.md), [`a2m-pack-mcp`](../architecture/crates/a2m-pack-mcp.md), [`anything2mcp`](../architecture/crates/anything2mcp.md), and [`a2m-local`](../architecture/crates/a2m-local.md); sentences of spec sections [303](../spec/3-packs/303-the-http-pack.md), [304](../spec/3-packs/304-the-mcp-pack.md), and [308](../spec/3-packs/308-the-file-pack.md); the Python client's binary finder. Adopts what [decision 0193](0193-the-core-the-contract-the-compiler-and-the-scheduler-after-the-second-pass.md) offers, and closes FI-1, FI-2, MC-1, PR-1, and PR-2 of the third safety audit and the local surface's half of AC-1. Supersedes the `files` row of [decision 0192](0192-a-served-engine-hands-no-root-of-the-project-that-started-it-and-clients-start-and-compare.md) and point 6 of [decision 0188](0188-credentials-over-plain-links-drafted-workbooks-and-published-device-maps.md).

## Decision

Most of this is adoption of what 0193 built. Each point has a test that fails without it.

| Point | Built and test | Alternative weighed |
| --- | --- | --- |
| A root of each request's project | The file driver resolves a surface's folder through `Roots::folder_in` and `check_in` with the run's checked paths. The product hands `project` and `files` through `Roots::add_project` in every engine, and the split by whom an engine serves is gone: a `files` surface read in project B through an engine A started reads B's file, and A's reads A's, whichever started it. `a_root_of_each_requests_project_resolves_in_that_project_and_never_another` (file pack: one registry, two projects, reads and a write, a link from one into the other refused); `a_served_engine_never_resolves_a_root_against_the_project_that_started_it` (the binary). Reproduced by hand with the built binary: two copies of `stockfiles`, one engine started on demand from A, reads from A, B, A gave A, B, A; a read from outside any project stopped `project_folder_missing` | Adding the two roots only where `files.allowed_roots` holds `<project>`: the dispatcher already refuses a project folder the setting does not allow, so a run only ever holds an allowed one, and a condition would add a second reading of one setting. Keeping `project` bound in an engine a command runs inside itself: every request of such an engine names its project, so it gains nothing |
| An acknowledged keyed binding in `a2m-local`'s page test | The test's plan is the acknowledged upsert of the engine's helper with its identity `none`: a keyed binding with no read-back cannot be previewed, and a keyed one with a read-back is refused by the plan check | Keeping the key and the read-back: refused since 0193 |
| The command pack's questions | `cx.open_question_quoting(sentence, words)` for every question; the sentence names no word of the program. `quoted`, `type_question`, and `MOST_QUOTED` are gone. The draft test reads each stored question back apart | None: 0188 named this as the change to make |
| The surface notice | The HTTP and MCP packs register `SurfaceNotice::UnencryptedCredentials` for `unencrypted_credentials: accepted` (`a_surface_that_accepts_an_unencrypted_link_carries_its_notice_and_no_other_does`, in each). `a2m-local` prints a record's notices, and for the publish page every surface's kind and address, its notices, and every lint warning with its code, all escaped (`the_publish_page_shows_where_each_surface_leads_its_notices_and_every_warning`). The action registry does not carry them in its preview yet: the printing is built and proven on values the test builds, and wired once the fields exist | Waiting for the registry's fields before writing the page: the page is the half a person reads, and its escaping is the part to prove |
| FI-2: the Windows save | The save stops with `metadata_not_kept`, unsent, wherever `keep_owner_and_mode` answers no, on Windows as on Unix. Not run here: the crate's tree compiles SQLite, so it cannot be linted for Windows from Linux; CI's Windows job must show the save tests passing, which means an ordinary file, holding its folder's list, is told as kept | None: the contract now tells the two cases apart |
| FI-1: the save's last looks and the rename in two folders | Confirmed: `a_folder_swapped_before_the_last_look_stops_the_save_unsent` reported the save done, with the write in the folder moved away. The target's identity, by path, is taken before the temporary file is made, through the folder the path leads to then, and must be the same just before the replace: a folder moved and a copy put at its name is a change, unsent. After the replace the path must lead to the file the save wrote, or the save is unknown and reconcile reads it | Doing the digest, the lock signal, and the flush through the temporary file's folder handle: the contract offers no call for them. Wanted of `a2m-provider`: `Temporary::target_digest(max_bytes)` and `Temporary::holds(name)` through its folder handle, and a flush of that handle's folder after `replace`. Until then a swap in the few calls between the last look and the replace is told by the identity after it |
| MC-1: user information in an MCP address | Confirmed: an `http://svc:pw@...` surface with no session was sent. Refused at prepare, unsent (`an_address_that_holds_a_user_name_or_a_password_is_refused_unsent`) | A lint rule alone: the driver is what sends it |
| PR-1: a panic's message in the output file | Every process of the program reports a panic by its place alone (`a_panic_is_reported_by_its_place_and_never_its_message`). No concrete panic route was found; the test is of the report, since no command panics on purpose | The redactor in the hook: the kernel's redactor is not reachable from a hook set before the kernel exists, and a place is what a report needs |
| PR-2: the Python client's binary | Only the distribution whose record holds the client's own module is trusted, and only a program in the scripts folder of the scheme it was installed into. `test_a_distribution_planted_in_the_working_folder_is_never_trusted` failed with the old finder; `test_the_installed_program_is_found_in_its_schemes_scripts_folder` installs a wheel of the client into a fresh virtual environment with pip, offline. The Node client already holds the program to its platform package | Searching `PATH` or the interpreter's scripts folder as before: neither is the installed package's own |
| The settings digests in the hello | Refuted as a defect: only a connection of the engine's own operating-system user is greeted, and that user can read the engine's environment already. Kept as it is | A salted digest: the same user is given the salt with the hello |
| `the lock let go` in `a2m-local` | The test waited on a moment: a process another test starts at that instant shares the lock file's open description until it runs its program. It now waits for the lock to be free, within the tests' patience | A sleep: never a wait |
| The `page_http` path in the product | `a_request_two_pages_make_is_drafted_into_a_page_http_read_by_key_in_the_product`: the probe's `web_capture` over two orders' totals pages, drafted and compiled, read for both orders through the registry's `page_http` driver in a look-only posture, compared with the control interface; a key that is not one plain segment refused with no request seen; nothing written | |

## Consequences

- A provider action is handed the registry's roots and no checked project folder: one that resolves `files` or `project` is refused `project_folder_missing`. None of the first-party packs has a provider action. `ActionContext.paths`, filled with the call's folder, ends it.
- The approval and publish pages print notices, surfaces, and warnings once the action registry's preview carries `PreviewRecord::notices` and `PersonActAsk::surfaces` and `warnings`.
- CI's Windows job must show the file pack's save tests passing with the stricter `metadata_not_kept`.

## Revisit if

The contract offers a digest and a flush through the temporary file's folder: the save's last looks then go through it, and the identity checks become a second line.
