# 0189. A developer's first hour runs without hand steps

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-17

**Changes:** the designs of [`a2m-engine`](../architecture/crates/a2m-engine.md) and [`a2m-actions`](../architecture/crates/a2m-actions.md) and its guides; one row of the [action catalog](../reference/action-catalog.md) added (`draft.delete`) and one changed (`binding.promote`); two failure codes of the [technical reference](../reference/technical-reference.md#failure-codes); sentences of spec sections [201](../spec/2-kernel/201-access-kinds-and-modes.md) and [219](../spec/2-kernel/219-the-evidence-ladder.md). Builds on [decision 0170](0170-the-scout-identifies-each-surface-with-one-discovery-job-and-stores-each-stage.md) and [decision 0179](0179-what-each-pack-drafts-so-that-a-scout-ends-with-reads-that-work.md); supersedes point 9 of [decision 0180](0180-a-targets-offline-tests-cover-writes-and-gate-the-publish.md) (a key from a list, not built) and the consent sentence of 0170's stage 0. Closes findings A3, A4, and A5 of the review of the product's local authoring.

## Context

`crates/anything2mcp/tests/first_hour.rs` went from `init` to a published, called tool only by hand steps: a read written before the scout could see anything, a try stage that never ended, a binding status edited to `verified`, drafts deleted in an editor. Each lifts here; the test now runs as the product does, in 7.5 seconds.

## Decision

| Point | Ruled and built | Alternative weighed |
| --- | --- | --- |
| 1. Discovery of a surface with no binding | The engine prepares the surface's own mode: of the modes the provider serving the surface's kind declares with the kind's archetype and whose driver the registry hands over, the one of the lowest `rank`, in `Posture::Discovery` (`Run::hold_on`). A tie of rank answers every step `busy`, `no_binding`, named. A surface whose kind has no discoverer was already reported by name (`no_discoverer`) | The first binding in the plan, as before: a new target has none. The plan's own choice of mode would need a field on a surface |
| 2. The try stage ends | Found: a trial that failed rested `stopped`, which the stage read as not ended; each call submitted every trial again, and rule 6 handed the resting one back for ever. Now each trial's digest names the scout, the plan, the try number, and the input, so a continuation finds it (`run_called_since`) and submits none again; a trial at rest is ended; one that did not complete ends its read's tries, and the read is `failed` with the failure's class and code; one not ended within two minutes of its submission is cancelled and named `not_ended` | A table of the trials in flight: the ledger's migration, for what the run's own digest already identifies |
| 3. An engine inside each command | A call of the scout waits for a trial it started to its end, and for a discovery to its manifests' bounds, whatever `wait_seconds`; `wait_seconds` is looked at between trials, after one new trial at least. No call leaves a run it started in hand, so nothing waits out a lease of a gone engine. Chosen as the safe and least surprising: a trial's plan is a draft kept in the memory of the engine that compiled it, so another engine cannot carry out a job of it, and taking over a job whose lease has not run out is never safe | Taking over a trial whose owner is gone by the lease rules: the in-process lease is at least ten minutes, and the plan is not in the next engine |
| 4. The first binding of an operation | `binding.promote` takes a `draft` binding that is its operation's first, when every offline test of the operation passes at the call (run there), and, for a read, the newest finished scout in this project proved it at `executed` or the caller names its completed trial; it rewrites the status alone through the checked write, checks by compiling that nothing else changed, and records an audit entry with the evidence. For a write it is a person's act. The publish page lists the bindings that act for the first time in the version. A shadow binding is refused as not built | Drafting a read proven at `executed` as `verified`: the scout would then decide what may act, and nobody would have looked at the operation's test |
| 5. A key from a list | The rule: a read that states no example of its one key input is tried, last, with the first item of the list output named exactly as that key, of the one read proven earlier in the same scout on the same surface whose declared output of that name is a list. Two such lists, or none, leave the read `not_tried`, by reason. The key is stored only in the trial's stored call; the report says `input_from` by tool and output | The binding's verb `list`: a pack's word, not every mode has it; resemblance of names: rule 7 |
| 6. A draft removed | `draft.delete`, one definition in the registry, its four faces generated: a file of a draft folder by its checked path, never a top-level file, an unclaimed name, a link, a folder, or a device. A published version's sources are in the store, and no path reaches them | — |
| 6. A publish of only what has tests | Not built, on the lead's ruling: the gate stays whole. An operation with no test refuses the publish, naming `test.run` and `draft.delete` as the fix; `test.run` lists it under `missing` with both | Publishing the tested part: a version would hold less than the drafts the person was shown |
| A3 | Confirmed (`a_scout_is_kept_by_its_project_and_records_no_consent_for_a_person` continued the other project's scout before). A scout is kept by the digest of its project folder, stored with stage 0, until `actions_scouts` has a column for it | A column now: the ledger's migration |
| A4 | Confirmed. Stage 0 recorded a consent nobody gave. It now says none is recorded, and who asked; the report carries it | Refusing the scout to an agent: discovery and trials are read-only in the sandbox, and section 213 names no consent for observing a declared surface |
| A5 | Confirmed: unbounded, a link swapped in after the listing followed by `std::fs::copy`, the copy left by a crash. The copy reads through checked paths, which open without following a link; at most 4,096 files and 64 MiB; the cache folder of the scout is removed when the next engine opens | Copying through `std::fs` with a check after: the same race |

## Consequences

- The first-hour test's one hand step left: the offline test and its fixture are written by the developer, until `fixture.record` scrubs an observed answer into one.
- A scout drafts many operations; each needs a test or `draft.delete` before a publish.
- A promoted drafted file is no longer the drafter's own: a later scout reports it as a difference.
- Through the product, the key from a list is shown with the test stand of `a2m-actions` only; the database stand's reads by key are owed a test in the product crate.
