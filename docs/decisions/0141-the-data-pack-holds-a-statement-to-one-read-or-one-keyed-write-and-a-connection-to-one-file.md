# 0141. The data pack holds a statement to one read or one keyed write, and a connection to one file

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-17

**Settles:** the findings of a safety audit of `a2m-pack-data` against its design, [spec section 307](../spec/3-packs/307-the-data-pack.md), and the ten rules. Four came from a reviewer (D1 to D4; the report was cut off inside D4). The others were found by finishing the audit with the reviewer's method. Each was checked against the code with a test that failed before the fix; the tests are named in the design of [`a2m-pack-data`](../architecture/crates/a2m-pack-data.md). It adds to [decision 0100](0100-the-mode-sql-and-the-data-packs-contract-as-building-it-settled-it.md) and [decision 0101](0101-what-the-data-pack-refuses-and-how-it-names-it.md) and takes nothing back from them, except that a hand-written read is no longer a read-back.

Looked at and found sound: every value reaches the store through the binding's parameter interface, and no input or system value reaches a statement's text; a failure between the write and `commit` rolls back and says so; a lost answer to `commit` is `possible_commit`, and the session sends nothing more; two runs on one record are serialized by the writer's lock, and the guard is a compare-and-set inside the statement; nothing is shared between sessions.

## Decision

1. **The compiler refuses a statement that is not one plain read or one keyed write, by its words.** A read is one statement whose first word is `SELECT` or `WITH`. A write is one statement whose first word is the one its verb states. No statement holds `ATTACH`, `DETACH`, `PRAGMA` or a name beginning `pragma_`, `VACUUM`, `CREATE`, `DROP`, `ALTER`, or `load_extension`; no read holds `INSERT`, `UPDATE`, `DELETE`, `INTO`, or `REPLACE` other than as the function. Quoted text and comments are not read, so a column with such a name is written in quotes. This reads words, not meaning: a read is still proved a read by the store. *Instead of:* a SQL parser, which is a large dependency or a large piece of code, differs by dialect, and would invite the pack to trust its own reading of a statement; and instead of the store's refusal alone, which is what let these statements through.
2. **The driver makes the same refusal again, and asks the store before it runs anything.** The first time a session uses a statement, its words are checked as the compiler checked them, whoever made the plan. Then the store describes it: a read that the store says is not read-only, and a read that returns no column, stop unsent. *Instead of:* trusting the plan, which is hashed and not signed by this pack.
3. **The connection refuses it whatever its words are.** The embedded store opens only an absolute path. It turns extension loading off, forbids direct change of the schema's own tables, makes a double-quoted name that is no column an error, sets the limit of attached files to none, and installs the engine's authorizer last. The authorizer lets a statement of a plan read, call a function other than `load_extension`, and, on the writer, change rows of tables that are not the engine's own; it denies attach, detach, every setting, every schema change, savepoints, and transaction control. The pack's own `BEGIN`, `COMMIT`, `ROLLBACK`, and catalog queries run under a mark that allows exactly those. A reader refuses before its first step a statement that is not read-only or returns no column. Every setting the engine can report is read back. This uses three features of `rusqlite`, the binding already in the tree: `hooks` (the authorizer; `a2m-ledger` uses it already), `limits` (reading and setting a limit), and `load_extension` (for the one safe function that turns loading off; the functions it adds that turn it on are `unsafe`, which the workspace forbids). No outside crate is added. *Instead of:* the authorizer alone, which would leave the limit and the settings as the engine's defaults; and instead of denying `query_only` by a list of settings, which a new engine version could outgrow.
4. **A write is read back only by the read the pack wrote.** `effect: read` with `form: table` is the read of one record by its key: the column of every field, the version, and the full key predicate, written by the pack as it writes a keyed write. A binding's `read_back` must name such a read of the same record on the same surface. The drafter writes this form, so a draft holds no statement text. When the read runs, the store's description must hold the key's columns, and the record returned must hold in them exactly the values bound; anything else is `drift`, `read_not_by_key`. *Instead of:* keeping hand-written read-backs and checking their parameters, which cannot show what the text selects or that a returned value is the stored one; and instead of the run-time check alone, which a text that returns its own parameter as the key would pass.
5. **What a write reaches is known or the write stops.** Names of tables are compared without regard to the case of ASCII letters, in the catalog query and in the pack. A catalog that was cut off stops a write that declares no hazard, as `unknown_variant`, `catalog_too_large`; a table the catalog does not hold stops it as `drift`, `schema_changed`. *Instead of:* reading the written table and the keys that point at it without a cap, which is the better answer for a very large store and is left as an open point: the stop is safe now, and its message says how to go on.
6. **A writing transaction is one statement and one row.** The driver refuses a second writing statement in a transaction, and an `expect_rows` for any count but one or outside a transaction that wrote.

## Consequences

- Three failure codes are new in the pack's manifest: `policy`/`statement_not_allowed`, `drift`/`read_not_by_key`, and `unknown_variant`/`catalog_too_large`. `read_statement_wrote` is now raised before the statement is sent.
- The pack's section of the plan is format 2: a statement carries its record and whether it is the pack's read by key.
- A target whose read-back was a hand-written read does not compile until the read is declared `form: table`. The example in section 307 is changed to match.
- A hand-written read that uses a double-quoted text, or an unquoted table or column named as one of the refused words, does not compile or stops as `drift`; the fix is to quote names and write texts in single quotes.
- The stand case "a statement declared `read` that writes" is now shown at three places: the compiler, the driver, and the connection.
- Limits stated in the design and not closed here: a hand-written read may compute what it returns; a key column whose collation folds case must be asked for as stored; the version guard trusts the store to change the version; a store of more than 2000 tables takes no write without a declared hazard.
