# 0140. The command pack after its safety audit

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-17

**Settles:** the ten findings of a safety audit of `a2m-pack-command` against the ten rules, [spec section 306](../spec/3-packs/306-the-command-pack.md), and the [crate's design](../architecture/crates/a2m-pack-command.md). Each finding was first shown by a test that failed, against the test stand where the stand can show it. All ten were confirmed. **Changes:** the rules on values and the refusals of section 306, and the pack's failure codes.

## The findings

| # | Finding | Fix | Instead of |
| --- | --- | --- | --- |
| C1, critical | Standard error was cut to 120 characters before it was redacted, so a secret the cut divided left a part in a failure | Redact the whole text, take out control characters, redact again, and cut last. The second pass is needed because taking out a control character can join two halves of a secret | Redacting once before the cut, which would let cleaning put a secret together after the redactor looked |
| C1, the same class elsewhere | A version was taken out of unredacted output and redacted afterwards. A JSON escape is decoded after the text was redacted, so a decoded value could hold a secret. A help or version form's output that the supervisor cut was redacted after the cut. Discovery cut lines out of help text before its own redactor saw them, and the describer joined parts of a finding into one line | The version is read from redacted text. Values are redacted again after a form is read. Output the supervisor cut is not shown at all. Discovery redacts the whole text first. The describer redacts each line it puts together | Trusting the handle to redact: it redacts a failure, and does not see a value or a capture |
| C2, serious | The driver started a command that writes from any step, and relied on the lowering to mark the commit point | `spawn` refuses, unsent, as `input`/`step_not_usable`: a command that writes on a step not marked `commits` or with no record; a command that reads on a step marked `commits`. An `expect` or `parse` that cannot be done as written is `possible_commit` when the last start was of a command that writes | Raising the step's own failure class, as before: for a write's `spawn` that is `possible_commit`, which says a write may have happened when nothing was started; for a read's it is `transient`, which invites a retry |
| C3, serious | The rule that no flag that runs its value carries a param was checked for `{flag, param}` only | Checked for every form that carries a value: `{flag, each}`, `{flag, stamp: true}`, the flag as a literal before `{param}`, the joining character written into the flag, one dash or two, a long name in any case, and a help form with `{command}` after the flag | Recognising a cluster of one-letter flags such as `-xc`: what a cluster means is the program's own, and a guess refuses flags such as `-ac` that take a number |
| C3, argument injection in general | A leading `-` was already refused for every value that is an element of its own. A leading `@` was not, and many programs read such an element as the name of a file of more arguments | A value that is an element of its own may not begin with `@`, before or after `--`, and on Windows may not begin with `/`. A `--` is still not required before a positional value: the driver refuses the value that would need it | Requiring `--` in every argument list with a positional param: a program that does not know `--` would take it as a value |
| C4, serious | The check of who can replace the program looked at the real file and its folders only, so a link in a folder another user can write passed, and that user could change where the declared path leads between the digest and the start | The declared path is walked name by name: each folder entered, each link, and the way to where each link leads must be closed to other users. The program is started by its declared path | Starting the real path that was checked. It closes the same window, but the program is then started under another name, and a program that reads its own name, as a program of many tools in one file does, would be another tool than the one declared and tried. With the chain closed nobody else can change what the declared path names, so starting it is as safe |
| C5, minor | A file or folder a group can write passed when the group was 0 | Refused whatever the group: who a group's members are is not known to the check | Looking the members up, which needs the system's name service on the path of a run |
| C6, minor | The list of shells and interpreters missed programs whose work is to start another | Thirty-nine names added: more interpreters, and programs that set a priority, a time limit, a root, a user, or a namespace for the program their arguments name. The list is said, in the design and in section 306, to be a net and not complete | A list claimed complete |
| C7, minor | Nothing refused a credential written into a `commands/` file or carried as an argument, and the crate's own test wrote a token under `env.set` | Three rules where a file is compiled. `command.secret_variable`: a variable named for a credential is neither set nor copied. `command.secret_literal`: no variable's value and no element looks like a credential. `command.secret_argument`: no flag named for a credential carries a value. The test stand has a fault, `Say`, that prints a chosen text, so a test plants a made-up secret without a target file holding it | A warning in a draft and an error at publish: the value would sit in the draft plan all the same |
| C8, minor | A program whose process group could not be ended was treated as finished | A write is `possible_commit`; a read, and a help or version form, is `busy`/`cleanup_incomplete` | Leaving it to the supervisor's block on new starts, which does not stop the read-back of this run |
| C9, minor | The run's folder was made with a call that succeeds on a folder that is already there | The folder is made only under a name that is not there, and is then seen to hold nothing; a name that is taken is passed over and never used, emptied, or removed. After 64 names the run is refused as `input`/`file_unavailable` | Refusing the run at the first name taken: what an engine that died left behind would then stop every resumed run with the same process number |
| C10, minor | `spawn` kept the earlier start until a new one succeeded | Every `spawn` forgets the start before it first | None |

A text param's pattern stays the guard for what a flag makes of a value joined to it, such as a flag that reads `@name` as a file.

## Wanted in other crates

| Crate | Change | Why |
| --- | --- | --- |
| `a2m-provider`, the supervisor's `launch` | Open the program's file once, take the digest through that handle, and start that handle where the system can (on Linux, the call that runs an open file), so that the bytes checked are the bytes started | With the chain closed to other users, the gap between digest and start is open only to the engine's own user and the administrator. Closing it for them too is the supervisor's, and is the open point of section 306 |
| `a2m-provider`, `CheckedPath` | A call that makes a folder only when nothing is there, and fails otherwise | The pack now looks and then makes, which is two steps |
| `a2m-provider`, the driver contract | Give a step the run's redactor, or state that `PrepareContext::redact` and the pack's are one | `PrepareContext::redact` is a borrow that ends with `prepare`, so a driver redacts in `act` with the pack's redactor only |
| `a2m-provider`, the handle | Pass a step's values and captures through the redactor on the way out, as it does a failure | A driver that forgets is then still held |

## What stays open

Access lists beyond the mode are not read. On Windows the check of who can write is not built. The lists of programs and of flags are nets. These are in the design's open points.
