# 0193. The core, the contract, the compiler, and the scheduler after the kernel's second pass

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-17

**Changes:** the designs of [`a2m-core`](../architecture/crates/a2m-core.md), [`a2m-provider`](../architecture/crates/a2m-provider.md), [`a2m-files`](../architecture/crates/a2m-files.md), and [`a2m-sched`](../architecture/crates/a2m-sched.md); sentences of spec sections [203](../spec/2-kernel/203-the-provider-contract.md), [208](../spec/2-kernel/208-runs-the-ledger-and-resume.md), [223](../spec/2-kernel/223-the-runner-protocol.md), and [502](../spec/5-security/502-defending-against-a-manipulated-agent.md). Adds to the provider contract, a public contract: `Prepared::recorded_elsewhere`, `OtherRecords`, `RecordedElsewhere`, `recorded_digest`, `DriverHandle::act_asking`, and `Roots::add_project`, `check_in`, `folder_in`, `holds`, `is_project`. Takes up the minor findings of the kernel's second safety pass in these crates (decision [0185](0185-a-record-with-no-key-is-never-proved-absent-by-one-look.md) took the critical and serious ones), what [0180](0180-a-targets-offline-tests-cover-writes-and-gate-the-publish.md), [0184](0184-the-data-and-stream-packs-after-their-second-safety-audit.md), [0185](0185-a-record-with-no-key-is-never-proved-absent-by-one-look.md), [0188](0188-credentials-over-plain-links-drafted-workbooks-and-published-device-maps.md), and [0192](0192-a-served-engine-hands-no-root-of-the-project-that-started-it-and-clients-start-and-compare.md) said these crates owe.

## Decision

Every change is an addition with a default that keeps the other crates as they were, or a tightening checked with a build of the whole workspace. Each finding was first shown by a test that fails without its fix.

| Point | Verdict and test | Built | Alternative weighed |
| --- | --- | --- | --- |
| C-2: direction and format characters reach `said` | Confirmed: `said_shown` escaped `Cc` alone. `every_character_that_can_reorder_hide_or_restyle_text_is_escaped_for_a_door`, one case per class | `said_hides(c)`, a closed list written out from Unicode's default-ignorable and format characters, with every control character: bidirectional marks, embeddings, overrides, and isolates; zero-width and invisible format characters; line and paragraph separators; variation selectors and tags; ESC, CSI, and the other controls. What the system said is stored and carried raw and escaped once, where a door shows it: `said_shown` (a line of its own), `said_quoted` (between quotes, quotes and backslashes too, for `said_line`), `said_neutral` (inside JSON, all but a line feed and a tab). `said_cut` stays raw, as before. A `Failure` read as data is held to `SAID_CEILING` (`a_failure_read_as_data_keeps_no_more_...`) | Escaping inside `said_cut`: the line a command prints escaped the text a second time; the stored text must stay what the redactor saw |
| P-1: `Temporary::replace` renames whatever stands at the temporary name | Confirmed. `a_file_or_link_swapped_in_at_the_temporary_name_is_never_put_in_place` | Before the rename the temporary name must hold the file the save made, by identity; after it, the target's name must. A swap in the calls between is answered as a failure, which the file pack's save already reads as in doubt when the file is neither the old nor the new one | Renaming by handle (`linkat` from the process's descriptor table): needs a privilege on Linux and does not exist on macOS or Windows |
| P-2: Windows identity and access | Confirmed by reading. `nobody_else_opens_the_temporary_file_while_it_is_written`, `a_target_with_an_access_list_of_its_own_is_told_apart_on_windows`: CI's Windows job must show both pass | The identity is `FileIdInfo`'s 128-bit identifier, the 64-bit index only where a file system answers no `FileIdInfo`. The temporary file is opened shared with nobody. `keep_owner_and_mode` answers `true` on Windows only where the target, opened itself, has the very owner and access list (byte for byte, protected alike) that the new file took from its folder, so a target with a list of its own is told apart. Compiled and linted for Windows from a copy; not run here | Copying the target's access list onto the new file: more unsafe calls, and a list that names another owner may not be copied by this user anyway; refusing is safe |
| P-3: a refused provider takes a registered provider's name | Confirmed. `a_refused_provider_never_takes_a_registered_providers_name` | A refused manifest whose name a listed provider, or a refused one named before it, holds is unnamed, with no version, and its problem is listed under no name | Listing it under the name with a mark: the doors would still print the name beside another's problem |
| F-1: an acknowledgement waives a read-back that could prove the record | Confirmed. `a_keyed_record_its_binding_reads_back_is_not_ended_on_an_acknowledgement` (the plan), the new case in `an_acknowledgement_is_evidence_only_for_an_irreversible_operation` (the compiler) | Section 208 names an acknowledgement as evidence "only for an operation declared irreversible", with examples of records that cannot be read again; it does not say that a record its binding reads back by a key may skip that read, and rule 3 says read it back. So one question, `acknowledgement_may_stand(strategy, read_back)`, true for identity `none` or a binding with no read-back step, is asked by the compiler (`kernel.acknowledged_where_read_back`) and by the plan's check alike. A keyed binding with no read-back step, such as a queue take whose message is gone once acknowledged, may still stand on the answer | Allowing `acknowledged` only for identity `none`: stricter, and it would refuse a take or a command that has a key and nothing to read it back by, which 208 lists. The plan's check now refuses hand-built test plans in three crates that set `acknowledged` on the keyed upsert and keep its read-back; they must clear the read-back |
| The scheduler spins on a run that rests | Confirmed: every stop that left a record in doubt queued a reconcile available at once. `a_reconcile_queued_again_for_one_run_waits_longer_each_time_and_a_person_stop_waits_for_a_person` (per failure class, a minute and two hours of a paused clock), `a_waiting_reconcile_is_woken_by_a_resume_or_a_settle_time_and_never_inside_a_quarantine` | Only `possible_commit`, `transient`, and `busy` stops are queued again on the scheduler's own. The `n`th reconcile in a row waits 5 s doubled `n - 1` times, at most 15 min (`SchedSettings::reconcile_wait`, `reconcile_wait_ceiling`); after a lost lease the longer of that and the quarantine. A minute sees at most four. `enqueue` (a resume) wakes a waiting reconcile at once; `wake_reconcile(run, at)` brings it to a settle time; neither crosses a quarantine | A fixed delay: a record that never settles is still read every few seconds for ever. Ending every stopped reconcile as resting: a lost answer that a later look settles would wait for a person |
| A question with the system's words apart | Built. `a_question_keeps_the_products_sentence_apart_from_the_systems_words` | `DraftContext::open_question_quoting(sentence, words)`; `DraftValue::OpenQuestionQuoting`, `Quoting`, `OpenQuestion::quoting`. The file holds one question; the report keeps the sentence and the words apart. The context had no redactor: `Drafter::with_redact` gives it one, and each word passes it whole before it is cleaned and bounded (4 parts, 64 characters). `OpenQuestion::stored` and `StoredQuestion::read` keep the two apart in the unknowns ledger's one text, and every older text reads whole | A column in the unknowns table: a migration in another crate for what one text can carry unambiguously |
| A surface's notice a door must show | Built. `a_surface_carries_the_notice_its_kind_registers_while_its_field_says_so` | `SurfaceNotice`, a closed list with fixed words, in `a2m-core`; `SurfaceKindSpec::with_notice(key, word, notice)`; `CompilerSet::surface_notices(&SurfacePlan)`, computed from the surface's own fields as the compiler kept them. Nothing a caller sends reaches a surface's fields. The plan's shape and pinned hash are unchanged | A field of `SurfacePlan`: four crates that may not be changed now build it field by field, and every one would break |
| Another record's recorded value | Built. `a_driver_learns_whether_another_record_holds_a_value_and_never_the_value` | `Prepared::recorded_elsewhere(name, value, deadline)`, answered by an `OtherRecords` the engine passes for one step through `DriverHandle::act_asking`: `Held(RecordRef)`, `NotHeld`, or `CannotTell`, compared by `recorded_digest`, never handing a value back. `CannotTell` by default, outside a step, for a name that is not a checked name of 64 characters, a null, a list, a record, a masked value, a late answer, and an answer that names the asking record. Not offered at prepare: `PrepareContext` is built field by field in every pack | A method on `PrepareContext`: breaks the packs |
| A root of each request's project | Built. `a_root_of_each_requests_project_resolves_in_that_project_and_never_another` | `Roots::add_project(name, access)`: a root bound to no folder; `check_in` and `folder_in` resolve it in the run's `CheckedPaths::project_folder()`, with every refusal of a root, a link out included; `check` and `folder` refuse it with `project_folder_missing`; `narrowed` keeps it; `holds` and `is_project` answer without a folder | A registry per project, which decision 0192 refused |

## Consequences

- The engine, the action registry, the product, the file, stream, command, HTTP, and MCP packs, and the scout have lines to adopt; the report of this package lists them. Until the engine's, the action registry's, and the local engine's test plans clear the read-back of their acknowledged keyed upsert, those tests are refused at `plan.encode()`.
- On Windows the file pack's save goes on when `keep_owner_and_mode` answers `false`; once it stops there, a file with an access list of its own is no longer replaced with a wider one.

## Revisit if

The crates that build `SurfacePlan` field by field build it through a constructor: then the notices belong in the plan, under its hash. Or the unknowns ledger gains a column for the system's words.
