# 0196. The engine and the registry after the acknowledgement ruling and the first hour

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-17

**Changes:** the designs of [`a2m-engine`](../architecture/crates/a2m-engine.md), [`a2m-actions`](../architecture/crates/a2m-actions.md), [`a2m-ledger`](../architecture/crates/a2m-ledger.md), and one line of [`a2m-provider`](../architecture/crates/a2m-provider.md); the guides on the order of work and on operations; the fixture section of the [file formats](../reference/file-formats.md#testsyaml-and-fixtures); the `fixture.record` row of the [action catalog](../reference/action-catalog.md) and its inputs; three failure codes of the [technical reference](../reference/technical-reference.md#failure-codes); the [ledger schema](../reference/ledger-schema.md); sentences of spec sections [208](../spec/2-kernel/208-runs-the-ledger-and-resume.md), [217](../spec/2-kernel/217-traces-evidence-and-repair.md), and [403](../spec/4-building-tools/403-testing-and-publish-gates.md). Takes up what decisions [0189](0189-a-developers-first-hour-runs-without-hand-steps.md) and [0193](0193-the-core-the-contract-the-compiler-and-the-scheduler-after-the-second-pass.md) left to these crates, and the findings of two reviews in them.

## Decision

Each point was first shown by a test that fails without it.

| Point | Ruled and built | Alternative weighed |
| --- | --- | --- |
| 1. A keyed record its binding cannot read | Decision 0193 lets a write end on an acknowledgement where the record cannot be read back: no key, or no read-back step. A keyed record with no read-back step (a write-only register, a message sent under a caller's key) was read before its write through `read_back`, which is empty, and stopped `no_read_back`. Now, for a binding whose evidence is `acknowledged` and that has no read-back step, the engine does not read the record before it writes: the diff's action is `write` (`DiffAction::Write`, counted apart), every field's current value is `None` and a door shows the fixed words `NOW_CANNOT_BE_READ`; nothing is compared after; the record ends `acted`, acknowledged. A lost answer leaves it in doubt, and reconcile treats it as a record with no key (decision 0185): only a lookup the mode's manifest states can prove absence returns it to `planned`, and one that finds it leaves it in doubt, because the ledger ends a record on an acknowledgement only under the lease that sent it. A lookup is never used as a read-back. Tests: the two in `a2m-engine/tests/contract.rs`, with the diff's "cannot be read" asserted, and `a_keyed_record_its_binding_cannot_read_whose_answer_was_lost_stays_in_doubt_and_is_not_sent_again`; `pass_two.rs`'s test now shows a lost answer staying in doubt and a run whose answers arrive completing with `write` records on the page | Reading through the binding's lookup: a lookup that returns the record's values would be a hidden read-back, which the compiler should have required |
| AC-2. A write's test that sends nothing | Confirmed: one object answered the preview's lookup with the values after the write, the record was unchanged, and the test passed with no save sent. A write's test with no `<name>.request.json` is `not_run`; a test that expects nothing sent says `sent: 0` (a new fact `expect` may name) and passes as a test of that path (`path: nothing_sent`), and the gate refuses a write none of whose passing tests sent its save (`no_save_sent`). The list form answers the look before and the read-back after differently; the repository's write fixtures use it already | Counting `unchanged` as proof: it proves the read, not the save |
| AC-3. The tested bytes | Confirmed by reading. The gate holds every fixture file it reads, loads the target once more after, and runs only when the load's digest is the plan's `sources` and every held file has the digest the load found (`tested_as_compiled`), else `stale`/`drafts_changed`. A pipeline's source is taken from the held bytes. The evidence names `plan` and `sources` | Running from the compiler's `Sources`: they hold digests and documents, not a fixture's bytes, and `a2m-files` is not this package's |
| AC-1. The publish page | Confirmed. `PersonActAsk::surfaces` (name, kind, the default environment's address, each environment's, and the notices the pack registers) and `warnings` (code and message); the same facts as lines in `details`, which the page already prints. `PreviewRecord::notices` on the approval page | Lines alone: a page could not lay the address and the notice out apart |
| AC-4 | Confirmed: the gate's line counts offline tests alone and says how many live tests the gate excused | — |
| AC-5, A-5 | Confirmed: what a fixture answered, a recorded request, and a fixture's file names are under `untrusted` in `test.run`'s result | — |
| LE-1 | Confirmed: migration 0017, a trigger that refuses a change of `gate_evidence` | — |
| EN-1 | Confirmed by reading: `Engine::run_offline` takes `Arc<Replay>`, so no other driver can be handed it. Proved by the type; no test can show the old call | — |
| 2. Another record's value | `Control::other_records(operation, asking)`, `None` by default; the engine hands its answer to each act through `act_asking`, or one that cannot tell. `InProcessControl` answers from `Ledger::recorded_before_commit`: the values recorded before the save of every other record of the operation in the workspace whose write may have landed (`RecordRow::may_have_landed`: verified, acted, in doubt), compared by `recorded_digest`, `CannotTell` where a candidate's value under the name is masked or cannot be read. A record planned again, never sent, or failed and settled holds nothing, so a message a take left is not held for ever | Every attempt of every record: a take settled as not taken would hold its message for ever |
| 3. A provider action's project | `ActionContext::paths`, the call's own checked project folder, built in `dispatch.rs`; `DiscoveryScope::paths` is the run's. `a_discovery_and_a_provider_action_resolve_the_project_of_their_own_call` | — |
| 4. `target.add` with a surface | **Not built.** A pack states its kind's address key (`SurfaceKindSpec::address_key`), but the compiler set gives no way to read it, and a registry that wrote the key would hold a pack's knowledge. The hand step stays | Guessing the key from the kind's name: rule 7 and rule 8 |
| 5. `fixture.record` | For reads. The read runs as a trial in the sandbox; `Control::step_observed` tells the registry what each reading step observed, held in memory for that trial alone. Each value passes the redactor, then is replaced by fixed rules (`Scrubber`): text by text of its length class made of characters the original does not hold, one original one synthetic text throughout the fixture and the input, two originals never one; a choice by another declared code; a whole number by `10^(d-1)+k`; an exact number by `1` and zeros of its scale; dates, moments, and lengths of time by fixed ones; `true`, `false`, `null` kept; lists cut to three. Text of a field type built on a number or a date has no rule and stops it. The test's expectation is the replay's own result; the test runs in memory, the files are written only if it passes and no original text is in any byte, and it runs again from the files. Nothing is written over. The first-hour test records its fixture this way | Recording from a stored trace: a trace keeps shapes and digests, never values |

| A-4 | Confirmed: the run's project folder is checked again at every lease and not handed where it no longer passes or now leads elsewhere | — |
| 7. A scout's project | Built: migration 0018 adds `actions_scouts.project`, written with the row; the lookup filters on it instead of reading every scout's first stage | The digest in stage 0 alone: a scout row could exist without it, and every row was read |

## Consequences

- `a2m-local` builds `PreviewRecord` field by field in a test: it needs `notices: Vec::new()` (the struct now has `Default`).
- `a2m-files` should give the compiler set's address key of a kind, so that `target.add` can write a surface; and should refuse an `acknowledged` binding of a keyed operation with no read-back and a lookup, or say why a lookup that returns values is not a read-back.
- The clients' generated actions change with `fixture.record`'s inputs.

## Revisit if

A write's fixture is to be recorded: it needs a test record and the write round trip.
