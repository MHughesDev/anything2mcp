# 0147. The engine after its safety audit

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-17

**Changes:** the design of [`a2m-engine`](../architecture/crates/a2m-engine.md) (the loop table, the lease, the sandbox, a new part on what is stored and shown, the failure codes, the invariants, the open points); one paragraph and one step of [spec section 208](../spec/2-kernel/208-runs-the-ledger-and-resume.md); one sentence of [spec section 401](../spec/4-building-tools/401-overlaying-tools-on-an-existing-system.md); two codes in the [technical reference](../reference/technical-reference.md). Builds on decisions [0091](0091-the-engine-loop-as-its-first-two-passes-settled-it.md) and [0092](0092-a-record-that-waits-for-an-earlier-record-is-planned-under-its-place-in-the-run.md); agrees with [0139](0139-a-write-that-was-sent-is-never-settled-by-an-answer-that-is-not-the-applications-verdict.md), which holds the same rule inside one pack.

## Context

A safety review read the engine against its design and the ten rules, and ran nothing. It gave ten findings: one critical, three serious, six minor. Three more items came from the agents fixing the packs. Each was checked against the code, with a test against the built-in test application wherever one could be written.

## Decision

1. **A write that was sent is in doubt until it is verified** (E1, critical, confirmed). After `acted`, the failure of a confirm step, a read-back step, or a later act step was recorded under that step's class. With `policy`, `stale`, or `input` the ledger released the record's lock and the run ended `failed`, with the write in the test application and nothing left to read it. The engine now holds the rule by itself: from the save until `verified`, a failure is `possible_commit`, `no_confirmation`, naming the class and code it stands in for. What stands: `possible_commit`; `session_expired`, which rests the run and keeps the lock; and the application's verdict. A pack marks the verdict by a failure the system answered with, of the class `rejected`, or, on the committing step, `stale` for the version sent. An answered `policy` or `input` on the committing step is no verdict. The same holds for the read of a record in doubt during reconcile: a class that would end the run becomes `possible_commit`, `cannot_reconcile`. *Instead of:* replacing only the three settling classes, which leaves the rule depending on a list the ledger owns; and instead of taking `rejected` from a confirm step as doubt too, which would hide the system's own message, when keeping it costs nothing: `rejected` never releases a lock.
2. **A binding is checked for its one save where it is chosen to write** (E1, second route, confirmed in the code; no longer reachable). `hold_for` could fall to another binding that was never checked. The check is repeated for the binding chosen, before the lock. The plan check in the core crate now refuses a binding whose committing steps are not the operation's commit points, so no plan it accepts reaches the second check; the test pins the refusal before anything is sent.
3. **The sandbox's posture is by driver context, not by environment** (E3, serious, confirmed). A `Try` job prepared every driver as `Sandbox` with test records when the environment declared any, which switched off every pack's own guard for the whole job. Every context of a try is now prepared with no test records. One more context is prepared, with test records, only to write a record whose key is a declared test record, checked again at that point, and only that record's steps run in it. A `Try` of a drafted write may read under the guard and may send one committing step to a declared test record after approval. *Instead of:* running the non-committing act steps in a guarded context and the save in another, which cannot work for a mode whose steps share a page or a connection. What the kernel cannot hold is stated in the design: what a step not marked `commits` does in the writing context, and whether a draft's request addresses the record its key names. Both are each pack's to hold.
4. **The lease is checked at the commit point, with real time limits** (E2, serious, confirmed). It was checked once, before the waits, and a step with the default limit counted as zero. It is now checked before the waits, after them and before the intent, and immediately before the save, and a retry of a save is sent only while the lease covers it. A lease that runs out after the intent leaves the record in `intent` with nothing sent. *Instead of:* marking that record failed, which would say more than is known.
5. **Everything stored or shown passes the redactor** (E4, serious, confirmed): the diff's normalized current values and its proposed values, the intended values, the values before and after, the normalized half of every piece of evidence, the values recorded before a commit point, an assigned key, and the tool's result. The values seen before a write are compared in their stored form. While this was built the provider's handle began to redact what a driver returns, so two more rules were needed. A write whose values hold a registered secret is refused, `input`, `input_invalid`, because what is read back is masked and could never be compared. And an argument that holds the redaction mark is never sent, `unknown_variant`, `argument_masked`; on resume a masked stored value is left out, and a record in doubt that could only be found by it stops with `possible_commit`, `cannot_reconcile`. *Instead of:* comparing under the mask and calling the record verified, which would verify a field up to its secret only; and instead of a keyed digest in place of the mask, which was built and removed, because the handle masks first and nothing closer can be compared. A step's captures are dropped and none is stored.
6. **A record goes back to `planned` unread only when nothing can have been sent** (E5, minor, confirmed). The code `blocked_by_parent` alone was trusted. The class must be `busy`, and the record must never have had an intent.
7. **A condition that is neither true nor false stops the call** (E6, minor, confirmed), with `unknown_variant`, `condition_not_boolean`.
8. **Outputs that cannot be stored with `acted` stop the job** (E7, minor, confirmed). The record is still marked `acted`, with its assigned key, and the job stops with `busy`, `evidence_not_stored`; a resume reads the record again.
9. **Discovery is bounded in what it hands over, and by the lease** (E8, minor, confirmed). Depth, and bytes read through the port, stay the discoverer's to keep.
10. **The settle time is the engine's one timed wait** (E9, minor, confirmed as a conflict of words). It waits on a condition the binding declares, and only when the lease covers it.
11. **A source is parsed off the async threads** (E10, minor, confirmed).
12. **A record is read again in the context that writes it** (from the HTTP pack). Freshness is by time and by context.
13. **A save is never abandoned** (from the data pack; the code was sound). The engine drops the future of no committing step. A job dropped by its caller leaves the record in `intent`; tests hold both.
14. **What a mode holds alone is named for the job's requirements, not taken by the engine** (from the file pack). `Engine::exclusive_needs` gives the kind and the surface for each binding that may write. *Instead of:* a new call on `Control` taken for each write, whose default refusal would stop every write until each implementation had it, and which needs an order with the record lock that is not designed.

## Consequences

- A record that showed a registered secret in a value its save takes as an argument cannot be written: the run stops with `argument_masked`.
- A try of a write prepares two driver contexts where it prepared one.
- A failure after the save now reads `possible_commit` where it read `transient`, `drift`, or `unknown_variant`; the step trace keeps the class and code of the step.
- Owed by other crates: the ledger should keep the lock of any record that reached `acted`, whatever the class of its failure, and keep the mode with the intent; each pack should, in `Sandbox` with test records, lift its guard only for the step marked `commits`; whoever submits a job should fill its exclusive requirements from `Engine::exclusive_needs`.

## Revisit if

- The ledger's list of settled classes changes.
- The handle stops redacting what a driver returns, or the provider contract gives a capture a place in the trace.
- A mode needs what it holds alone for one write and not for the whole job.
