# 0180. A target's offline tests cover writes, and nothing is published unless they pass

**Status:** Accepted. Design decision. The owner had not read this record when it was merged.

**Date:** 2026-11-17

**Changes:** the designs of [`a2m-actions`](../architecture/crates/a2m-actions.md), [`a2m-engine`](../architecture/crates/a2m-engine.md), [`a2m-ledger`](../architecture/crates/a2m-ledger.md), and [`a2m-provider`](../architecture/crates/a2m-provider.md); the fixture section of the [file formats](../reference/file-formats.md#testsyaml-and-fixtures); sentences of spec sections [208](../spec/2-kernel/208-runs-the-ledger-and-resume.md) and [403](../spec/4-building-tools/403-testing-and-publish-gates.md); the guides on operations and target files. Adds migration `0016-ledger-versions-keep-their-gate-evidence.sql`. Builds on [decision 0177](0177-a-targets-offline-tests-run-against-a-replay-of-their-fixtures.md), whose "a write's offline test is listed `not_run`", "the publish gate is not switched on", and "each answer once" it supersedes.

## Decision

| Point | Built | Alternative weighed |
| --- | --- | --- |
| 1. An offline test of a write | Run as an `Execute` job through `Engine::run_offline`, under a control plane of the test's own with a ledger of its own: a store made by `StoreConfig::throwaway()`, **in memory**, gone when the test ends, with the same migrations, triggers, and ledger code as every store. In memory because nothing of it is wanted after the test, a file would need a folder the engine owns and a removal that a crash can skip, and the triggers hold the nine rules in memory as on disk. Its clearance is `WriteClearance::OfflineTest`, which only a throwaway store takes: there the ledger records an allowed decision of the test's one rule (`policy_version` `offline_test`) in the same transaction, so rule 3's triggers hold unchanged, and every other store refuses it with `approval_missing`. A throwaway store keeps its own policy key, so no policy engine is ever opened over it. The control plane's rule allows exactly the test's own tool, and a write only with that ledger. The replay answers the preview's lookup, the save, and the read-back; `Replay::sent` keeps what the engine sent to each committing step, and the test compares it field by field with `<name>.request.json` after the same normalization as results (equal JSON, text, or exact number). `expect` may name the run's `state`, `records_verified`, and `failure` where the result holds no field of that name | Opening the real policy engine over the throwaway store with a pre-approval rule for the one tool: publishing such a rule needs a person's presence (it loosens a protected setting), which a test does not have and must not claim. A temporary file: no gain, and a removal to get right. Running the write's preview alone: proves less than the test states |
| A binding not yet verified | Against a replay a `draft` or `shadow` binding may act; a `retired` one never. Nothing acts there, and an offline test is how such a binding earns promotion | Testing verified bindings alone: the example target's write is `shadow`, and could never be tested |
| An answer that repeats | One object (or `null`) in `<name>.json` answers every step of that name; a list answers in order, each once. A read through the HTTP pack asks its endpoint three times (request, validate, extract), and a developer writes the answer once | Answers keyed by step kind: more names to learn for the same fixture |
| 2. A pipeline's source | The test's input `source` names a file of its fixture folder, read through the checked paths (`CheckedPath::join`, which refuses `..` and absolute names) and handed to the job as its source; the input keeps the name, as a call's does. A name that leads out of the folder fails the test, and nothing runs | Reading from the target's `sources` folder: a fixture is what a test is replayed from, and its scrubbed marker covers it |
| 3. The publish gate | Section 403: "A version is published only when every gate passes, and the evidence is stored with the version." Of its twelve gates two are built: schema and lint (the compiler in publish mode) and offline replay. `version.publish` and `publish.request` run both; a publish is refused with `input`/`publish_gates_not_passed` unless every offline test ran and passed, naming each test and its state, with `missing[].next` naming `test.run`. The gate excuses a live test only: it belongs to the write round trip, which is not built. An operation or pipeline with no offline test is refused by the compiler already (`kernel.operation_without_test`, an error at publish, section 206), so every operation, read or write, has a passing offline test before it is published. The evidence (each gate that ran with its result, and the ten that did not) is stored with the version in `target_versions.gate_evidence` and returned by the publish; the person's page lists each gate's result and says which did not run (audit finding A2) | Refusing until every gate of 403 is built: no version could be published at all. Publishing with a warning: 403 says "only when", and the evidence would be missing |
| 4. The repository's projects | `targets/example`: the upsert's and the pipeline's fixtures answer the lookup (absent), the save, and the read-back, and record the request. Under `crates/anything2mcp/tests/projects/`: `orders` (the upsert, with its request), `account`, `secured`, `inventory`, `storefile`, `pages` (an answer for the screen), `controller` (`controller.main.json`), `messages` (`orders.status.json`), `stockfiles` (`stock.json`, the document's entry; `stock.csv` stays as the file the pack reads), `upstream` as it was. All synthetic | Changing a product test: not needed |
| 5. An acknowledged record settled by reconcile under a new lease | Not built, on the lead's instruction: a review found the keyless reconcile unsound as built, and another agent redoes it | |
| 6. The fixture format | The file formats' section now states the files the replay reads | |

The try stage compiles what can compile | The draft stage records `held_back`, the files that hold an open question; the try stage compiles every file of the target but those (`compile_what_can`: the loader of `a2m-files`, the files filtered, then `Sources::from_files`: the same as `load_files` on the rest), and names them in `tried.left_out`, apart from `problems` of files that fail for another cause. `plan_to_observe`, which discovery and the scout's identify stage use, compiles the same way, leaving out any file whose only error is a drafter's open question: a second scout of a target holding such a draft observes its surfaces again | Compiling everything and trying nothing, as before |

### An engine fix asked for on the way

A list output is normalized one item at a time by the output's field type; a `null` item stays `null`; an item the normalizer refuses fails the read as `output_unexpected`, naming the output and the item's position, never the value.

## Consequences

- A product test that publishes a draft with no passing offline test is refused by name. Every project the product's tests publish passes.
- A fixture for an HTTP write lists the lookup's three answers, the save's two (request, validate), and the read-back's three, in order.
- The packs' test helpers `outputs_of`, which copied the engine's shaping with list items normalized, can be dropped.
- Each pack's drafting rule should carry the system's words in a field of their own beside its question (for example `cx.open_question_quoting(sentence, words)`), so that the report can mark only them.

## Revisit if

Another gate of section 403 is built: it joins `GATES` as built, and the refusal names it.
