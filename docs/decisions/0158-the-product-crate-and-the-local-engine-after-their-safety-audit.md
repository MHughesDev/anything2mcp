## Context

A safety audit of the doors, the product crate, and the bindings found nine points in the product crate (P1 to P9) and five in the local engine (L1 to L5). The product crate had also not been built for hours while every crate under it changed.

## Decision

First the product crate was brought to the crates below it. A proof of presence in a test is taken on the engine's own clock, because the desk refuses one older than two minutes. In one process a job's lease is at least ten minutes (the kernel's floor), so the test of a killed process restarts the machine twenty minutes later. A stopped engine's nobody (`status_only_caller`) is used only for the code `engine_degraded`, a store that never opened; any other refusal of the caller ends `Engine::open` with it. Then each finding was checked with a test that failed before its fix.

| Finding | Confirmed | Test | Fix | Alternative weighed |
| --- | --- | --- | --- | --- |
| P1, two engines on one store (serious) | Yes | `a_command_that_runs_the_engine_itself_holds_its_lock_and_no_second_engine_opens_the_store`, with three real processes | `client::find` takes the engine lock in the step that finds no engine and hands it to `Engine::open_holding`, which holds it until the kernel has closed. `Engine::open`, the facade, takes it too for a store on disk. A second command waits up to twenty seconds for the channel or the lock, then ends `busy`/`engine_unreachable`, code 4; `serve` is refused `engine_running` | Refusing the second command at once. Two commands of one shell often follow each other closely; a short wait lets them share the store in turn |
| L5, the lock is checked and let go (minor) | Yes, the root of P1 | The same | `EngineLock::held` is documented as a question for a report and never a guard; `take` is the guard | Removing `held`. A test and `doctor` want the question |
| P2, a lost answer said to be safe to retry (serious) | Yes | `an_answer_lost_through_the_served_engine_is_a_write_in_doubt_and_never_safe_to_retry` | `Link::send` answers `transient`/`connection_lost` only when the HTTP library handed the request back unwritten, and `possible_commit`/`answer_lost` once any of it may have reached the engine, or when the connection ends during the wait. An answer that cannot be read is `answer_lost` too. A failure of this end is `retry_safe: false` when its class is `possible_commit`; the fix says not to run the command again and to find the run first | Telling reads from writes in the client. The client holds no engine logic, and a read is never harmed by being called in doubt |
| L4, the lost answer's fix (minor) | Yes | The same | `connection_lost` now says that nothing was sent; nothing claims an engine starts on demand | |
| P3, a program can say it is a person (serious) | Yes | `a_program_that_says_it_is_a_person_at_a_terminal_is_an_agent_and_raises_no_prompt` | Every caller of the channel is an agent. The header `A2M-Person-At-Terminal` is gone and the label only names the door. What it changes, by the list in the `a2m-actions` design: a person's act asked through the channel is refused `person_required` and raises no presence prompt; `caller_is_agent` is true in every policy request about a run started through the channel, so a pre-approval rule that asks for a caller who is no agent is never met through it; the recorded decision names an agent. In one process the caller is the process itself and its own view of its terminal still sets the flag: no channel is crossed, and that process holds the store and the vault already | Reading the peer's controlling terminal. A program can give itself one, so it would be a second claim |
| P4, a planted project file (serious) | Yes | `a_project_file_that_others_can_change_is_never_taken_as_a_project` | The walk up looks only in folders that only the user or the administrator can change (`kept_by` of `a2m-local`): owned by one of the two, not writable by everyone, and writable by a group only when it is the user's own primary group; it stops at the first folder others can change. A project file found, or named with `--project`, that others can change is refused `input`/`path_not_allowed`. On Windows, where this build reads no owner, the walk looks in the working folder and above it only inside the user's profile folder | Stopping at the home folder on every system. A project outside the home folder is common on servers |
| P5, escape sequences reach the terminal (serious) | Yes | `text_a_system_returned_reaches_a_terminal_as_text_and_is_never_obeyed` | Text for a terminal and all of standard error pass `render::visible`: every control character but line end and tab, and every mark that turns the direction of text, is written as `\u{1b}`. JSON output escapes DEL, C1, and those marks too, which the encoder leaves as they are | Removing them. A person then could not see that a value held one |
| L1, a real press fails (minor) | Yes, in Chrome 153: `Origin: null` under `no-referrer` | `a_write_through_the_served_engine_rests_is_approved_on_its_page_and_is_written_once` presses with a real browser; the same test sends `Origin: null` and another origin and sees 403 | `Referrer-Policy: same-origin` | Accepting `null`. A sandboxed frame or a `data:` page sends it too |
| L2, a dialog with fixed text (minor) | Yes | `no_prompt_but_a_pages_is_raised_while_a_page_waits_for_its_person` | After P3 no channel caller reaches `confirm_presence`. It also refuses `prompt_busy` while any page waits. The page tells the person to answer a prompt only right after their own press, and where the prompt carries words it shows the page's twelve characters. The limit is written in section 503 | A notice on standard error for each prompt. Nobody reads the engine's error output while approving |
| L3, a late `Present` (minor) | Yes | `a_prompt_that_answers_after_the_window_records_nothing` | After `ask`, an answer at or after the deadline is a dismissal, for a press and for `confirm_presence` | Trusting each prompt's deadline |
| P6, the passphrase in the environment (minor) | Yes | Exercised by every run of the binary; no child is started with it today | `cli::run` copies the environment into the host and then removes `A2M_VAULT_PASSPHRASE` from the process, before any thread starts. `run` is therefore `unsafe` to call, and both `main`s say why it is sound there | Leaving it and relying on each pack's filter. The supervisor copies listed names from the process environment, so the removal closes every pack at once |
| P7, one key-store entry for every installation (minor) | Yes | By reading: `installation_name` | The entry is `local-` and sixteen hexadecimal characters of the digest of the data directory's resolved path | Keeping `local` and documenting it. ## Consequences

- Through a served engine no person's act can be done, on any system: a person stops the engine and acts in one process at a terminal, as on a machine with no presence prompt today. The way out is a page for a person's act, as for an approval: the dispatcher hands a person's act asked by an agent to the person surface for a link, and the press raises the prompt.
- What stays readable of the passphrase: on Linux `/proc/<pid>/environ` and on macOS the process's arguments area still hold the environment the process was started with, and a program of the same user can read them, and its memory. Removing the variable keeps it from children only.
- A new key-store entry name means a root sealed under `local` is not found; no release has shipped with it.
- Not run: anything on Windows and macOS. The next CI run must show `local_engine.rs` and `verified_write.rs` passing there, and on Windows that a project is found in the working folder and inside the profile folder only.
