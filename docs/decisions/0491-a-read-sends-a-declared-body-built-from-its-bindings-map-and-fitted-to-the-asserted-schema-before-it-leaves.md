# 0491. A read sends a declared body, built from its binding's map and fitted to the asserted schema before it leaves

**Status:** Accepted. Design decision, made by the worker who built package E8, under the lead's brief. The owner had not read this record when it was merged.

**Date:** 2026-11-25

**Changes:** the `http` lowering and driver in [`a2m-pack-http`](../architecture/crates/a2m-pack-http.md); the `page_http` lowering and driver in [`a2m-pack-web-ui`](../architecture/crates/a2m-pack-web-ui.md); a new call of the observing tab, `ObserveTab::ask_from_page`, and its request, `PageAsk`, in [`a2m-pack-web-browser`](../architecture/crates/a2m-pack-web-browser.md); the test application's `POST /api/cases/rows/count`; spec sections [301](../spec/3-packs/301-the-web-pack.md) and [303](../spec/3-packs/303-the-http-pack.md); the glossary's page request. Builds point 6 of [decision 0392](0392-a-page-that-reads-by-a-method-that-may-write-is-learned-from-a-persons-watched-use-and-read-through-an-asserted-request.md). Supersedes point 1 of [decision 0410](0410-an-asserted-page-request-is-never-sent-by-the-engine-and-is-handed-to-the-tab-only-from-a-published-version.md) for a `read`; its rule for a read-back stands. Leaves [decision 0475](0475-a-person-confirms-an-asserted-read-on-the-engines-page-and-a-try-of-the-drafts-may-then-send-it.md) and [decision 0488](0488-a-reads-observing-tab-is-kept-warm-for-the-next-read-of-its-surface-and-session-made-fresh-first.md) as they are.

## Context

A search that takes its filter in a body could not be called by a tool. In the `http` mode a read's `body` was accepted by the binding's schema and then dropped by the lowering: an asserted read by `POST` always went out as `{}`, whatever the binding said. In the `page_http` mode an asserted read did not compile (decision 0410, point 1), because the browser engine's read from inside the page sends `GET` alone. Decision 0392 asked for a map from each declared body field to an expression over the inputs, typed as an update's body is, and left how it is held to the person's assertion to the builder.

Three rules bound it. A read by a method that may write is sent only where the existing rules allow: in the `http` pack, decision 0270's (a live run; outside one, a published version against an environment of kind `test`); in the web pack, decisions 0410 and 0475's (a published version, live or in a `test` try or shadow; under the drafts, only an entry its person confirmed, in a `test` try). No input may add a field or change where the request goes ([spec section 502](../spec/5-security/502-defending-against-a-manipulated-agent.md)). Unknown means stop.

## Decision

1. **The body is the binding's map, field by declared field.** A `read`, `list`, or `search` binding of `http`, and a `read` of `page_http`, may write `body`: each key a field the endpoint's or page request's `request_schema` declares, each value an expression of the kind that field takes, every required field given. The lowering refuses an undeclared field (`http.body_undeclared`, `web.body_undeclared`), a missing required one (`http.body_field_missing`, `web.body_incomplete`), and a value of another kind (`http.position_type`, `web.value_type`). A field's name is the entry's, never a value's; the driver builds the request only from the step's named arguments, so an input reaches only the field it is bound to, as a value.
2. **Only to an asserted read with a closed schema.** In `http`, a read's `body` compiles only for an endpoint marked `read` with `read_asserted: true`, by `POST`, `PUT`, or `PATCH`, whose `request_schema` closes its top level with `additionalProperties: false`; otherwise `http.read_body_unasserted`. A read of such an endpoint whose schema requires fields and whose binding writes no body is refused `http.body_field_missing`: the `{}` it would send fits no assertion. In `page_http`, a `read` may name an asserted read, and writes `body` exactly when the entry asserts one; a `body` on any other read is `web.read_acts`, as before. A write's read-back still names a read by `GET` alone (`web.request_method_not_built`): what it reads decides whether a write is called verified, and that should rest on no person's word.
3. **The body is fitted to the schema before it leaves, in every posture.** The `enum` the person wrote is what tells a read from a write at one address (decision 0392, point 5), and an input can carry any text. So the `http` driver checks the body it built against the endpoint's `request_schema` before it is sent, live included; a misfit is `policy`, `body_not_asserted`, a new code, and nothing is sent. The `page_http` driver checks the same before it asks the page; a misfit is `policy`, `page_write_refused`. Neither message quotes a value.
4. **Where it may be sent is unchanged.** The `http` driver's read-only guard (decision 0270) runs first, so under the drafts outside a live run the read is `read_only_posture`, unsent. The `page_http` driver asks only for an entry the run hands its observing tab under `AssertedReads` (decisions 0410 and 0475); otherwise `page_write_refused`, unsent, with the next step that names the entry and says to confirm it or publish it.
5. **The page's guard judges the engine's request too.** `ObserveTab::ask_from_page` sends a `PageAsk`: a method of the closed list, a checked `PagePath`, and a JSON or form body of plain names and plain values, or none, with no header but the body's own type and no token. It is made from the tab's isolated world as a read from inside the page is, so the tab's interception judges it as it judges the page's own requests: it leaves only when it matches an asserted read the tab was opened with, by method, origin, path, and body. The driver's check is the first lock and the tab's is the second; neither knows the other.

## Alternatives

| Alternative | Why not |
| --- | --- |
| Keep a read's body to literals in the endpoint, with no map | A search whose filter is the caller's could still not be called, which is the point of 0392's sixth point |
| Leave the `enum` to the system: send whatever the input says, since the guard of a published version lets the endpoint through | The endpoint's method and path are asserted, not every body; a `delete` in the field the person pinned to `search` would be sent in a live run, unrecorded, as a read |
| Check the `enum` at compile time only | A literal can be checked then, an input cannot; the check at run time covers both, and costs one walk of a small object |
| In `page_http`, reuse the acting tab's `write_from_page` with no token | It is a write's call, made in a tab that may act; a read is made in the observing tab, under the guard that holds a read to its assertion |
| In `page_http`, trust the tab's guard alone, with no check in the driver | The guard would stop a misfit, but after the step began; the driver's own check says why, names the entry, and leaves the stand's log empty before any browser work |
| Let a write's read-back name an asserted read | The verified mark of a write would then rest on a request nobody but a person vouches for; no case has needed it |

## Proof

- `crates/a2m-pack-http/tests/read_body.rs`, against `POST /api/cases/rows/count`: a body on a read by `GET`, or to an endpoint whose schema is open or open by default, does not compile; nor an undeclared field, a missing required one, no body at all, or a value of another kind. From a published version, live in `test` and `production` and in a try or shadow in `test`, the count, the first key, and the keys of each status are what the control interface holds, the stand heard one `count` for each read and no `archive`, and after the stand archives a row the read follows it. Under the drafts in a try or a discovery, and from a published version in a try against `production` or in a discovery, the read stops `read_only_posture`, unsent, and the stand heard nothing. Live, a status outside the `enum`, a status that tries to close the JSON text and add `op`, and an `op` bound to an input that says `archive`, each stop `body_not_asserted`, unsent, and the stand heard and stored nothing.
- `crates/a2m-pack-web-ui/tests/read_body.rs`, from the quiet page `/cases/rows-count`: the same compile refusals in the web pack's words; the count through `page_http` equals the control interface's, from a published version live in `test` and `production`, in a `test` try, and under the drafts in a `test` try of the confirmed entry; under the drafts live or unconfirmed, confirmed but against `production` or in a discovery, and from a published version in a `production` try, it stops `page_write_refused`, unsent, naming `cases_rows_count` and `assertion.confirm` or the `test` rule, and the stand heard nothing; the three misfits stop unsent and the stand heard and stored nothing.
- `crates/a2m-pack-web-browser/src/tests/observing.rs`, `a_read_asked_from_inside_the_page_by_post_leaves_only_as_an_asserted_read_the_tab_holds`: with no asserted read the tab fails the request and reports it; with the count asserted it is answered by the stand; a body outside either `enum` is failed by the tab alone. The stand heard one `POST` and stored nothing.

## Revisit if

A read must send a nested or nullable body field, a header, or a query beside its body; a system tells a read from a write by a long text in its body (package E9); or a write's read-back is found that can be read only through an asserted request.
