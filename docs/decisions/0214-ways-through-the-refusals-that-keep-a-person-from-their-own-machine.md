# 0214. Ways through the refusals that keep a person from their own machine

**Status:** Proposed. Design decision: any agent may accept a part of it by building that part with the tests it names, in a record that says so. Written by the coverage review of 2026-11-18. Nothing here is in force, and the refusals it names hold as written until a part is built. No rule is changed by it.

**Date:** 2026-11-18

**Answers:** the consequence of [decision 0208](0208-the-first-release-reaches-what-the-persons-machine-reaches-and-serves-on-that-machine-only.md) that "limits that keep a person from something their machine can reach are to be looked at again, each on its merits", with "a way through that the person chooses and is shown" where a limit protects the person.

**Would change:** [section 306](../spec/3-packs/306-the-command-pack.md) and [decision 0140](0140-the-command-pack-after-its-safety-audit.md) (a folder a group can write); [decision 0195](0195-a-read-never-runs-where-the-page-may-write-and-a-page-keeps-only-its-structure.md) (an action word in a key); [decision 0197](0197-no-client-takes-a-proxy-from-the-environment-and-stand-only-protocols.md) and [decision 0188](0188-credentials-over-plain-links-drafted-workbooks-and-published-device-maps.md) (`localhost` and host names); the command pack's refusal of a program that starts another as another user.

## Context

The [coverage review](../plan/coverage-review-2026-11-18.md) looked at each limit decision 0208 names, and at two more that the [coverage map](../plan/coverage-map.md) shows keep a person from most of their own machine. Each limit was added for a real reason, shown by a test. Each part below keeps that reason and adds a way through that a person chooses, in a protected setting or in the target's files, and that the review summary and `doctor.run` show.

## The parts

| # | Limit today | What it costs | The way through | Proof owed |
| --- | --- | --- | --- | --- |
| 1 | A program, or a folder on the way to it, that a group can write is refused, whatever the group (decision 0140) | On macOS the folder of installed applications is believed to be writable by the administrators' group, which would refuse every program inside an application bundle; some Linux distributions give a staff group the local program folders (both research brief 35). On Windows the check is not built and passes everything ([crate design](../architecture/crates/a2m-pack-command.md), item 9) | A group whose write the system itself gives only to its administrators (a closed list per system, read from the system, not from a name a person types) counts as the system's own, as the superuser does: its members could replace the file as the superuser anyway. Any other group stays refused unless the person names it in a protected setting; the setting is shown. The digest check at start is unchanged. On Windows, the check is built before a program is started there at all | On each system, a program under the administrators' folder starts; one under a folder another group can write is refused unless named; a Windows program in a folder an ordinary user can write is refused |
| 2 | A key's value holding an action word (`ACTION_WORDS`) is refused in both web drivers (decision 0195) | A record whose key holds such a word, such as `PAY-100`, cannot be read by key | A screen's key field may declare an anchored pattern its values must match. A value that matches the declared pattern is taken whatever words it holds; one that does not is refused as `input`. The pattern is in the target, reviewed and hashed, and the review summary shows it beside the key. With no pattern, the refusal stands | A key with an action word matching its pattern is read and the stand counts no write; a value outside the pattern is refused unsent |
| 3 | A plain link that carries a credential must be a loopback address written as an IP address; `localhost` is refused (decisions 0188 and 0197) | A person's own settings, and most local services' documentation, name `localhost` | The exact name `localhost` is a fixed spelling of the loopback addresses, never handed to the system's resolver: the engine connects to `127.0.0.1`, then `::1`, as RFC 6761 allows an application to do. No other name is treated so | A surface at `localhost` connects to a loopback listener with a hosts file that maps `localhost` elsewhere, and nothing is sent to the other address |
| 4 | A device link refuses a host name (the device pack) | Devices a person knows by a local name | `target.add` resolves the name once, shows the address to the person, and writes the address into the target; a run never resolves a name | A drafted surface holds an address; a run with a name in it does not compile |
| 5 | A program that starts another as another user is refused (section 306) | Every change that needs an administrator: a system-wide install, a system service, a system setting | A declared program, by path and digest, may be started elevated through the system's own elevation prompt only (polkit, the macOS authorization prompt, the Windows consent prompt), as a fixed pair like the interpreter and script of section 306, with no input in the program's place. The operation is `irreversible` unless read back, and the person sees the system's prompt every time | The prompt appears for each run; a program not declared is refused; nothing elevates without it |
| 6 | Only "a script that the system ships" may run, as a fixed pair of interpreter and script (section 306); not built | The operating systems' scripting interfaces (Apple events, COM automation, WMI) and PowerShell, the main way Windows is administered, have no other route ([coverage map](../plan/coverage-map.md)) | A script the developer keeps in the target, named by path and digest, run by a declared interpreter by path and digest, with its arguments passed as data the interpreter does not evaluate (`-File` for PowerShell, a script file for `osascript`), is a fixed pair. Its effect is the developer's declaration, as a command's is; its read-back is a second declared script. Rule six asks a decision record for this new use of another language, and this part is that record when accepted | On each system, an argument holding the interpreter's own syntax reaches the script as literal text, element for element (research brief 35, as hypothesis H-32 asks of programs) |

## Consequences, if accepted

- Parts 1, 3, and 4 are small and change no interface. Part 2 adds a field to the web pack's `screens/` key. Parts 5 and 6 change what the command pack may start and need their own tests on three systems.
- Part 6 makes the scripting interfaces reachable in the first release without a new pack. A pack of their own, reading their dictionaries and type libraries as self-descriptions (hypothesis H-41), can follow.

## Alternatives weighed

- Looking up a group's members at run time (rejected in decision 0140 because it needs the system's name service on the path of a run). Part 1 reads only which groups the system gives administrators, once.
- A setting that switches each refusal off. Refused: a setting cannot loosen a guardrail ([section 226](../spec/2-kernel/226-configuration.md)), and a switch says nothing about which case is safe.
- A new pack for scripting interfaces before part 6. Kept for later: it is large on two systems, and part 6 gives the same reach now with the command pack's rules.
