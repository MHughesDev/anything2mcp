# The first-time user review, 2026-11-25

One design review round, by [lens 9](../plan/design-review-lenses.md), its first use: follow the path as someone who has never seen the project. Where do they get stuck?

**How it was run.** As a person who has just cloned the repository at the prepared 0.1.0 commit, on Linux, in a container with no desktop. Read first: the [README](../../README.md), [trying the preview on Windows](../plan/trying-the-preview-on-windows.md), [RELEASING.md](../../RELEASING.md)'s install notes, the [walkthrough](../reference/walkthrough.md), `anything2mcp --help`, and the help of `init`, `add`, `try`, `ready`, `call`, and `doctor`. Then `cargo build -p anything2mcp -p example-app`, and the README's "Try it from source" typed as written, at a terminal (under `script`, so that answers came in their text form, as a person sees them), from `example-app &` to the person's press. The press itself could not be made: this machine has no presence prompt, which is the design. Also tried: the passphrase left unset, a home on a long path, the test application stopped, a target added twice, `add` given an address alone, `--input order_id=A-100`, `status` with no target, `connect`, `engine status` and `engine stop`, and `publish request` in place of the second `ready`.

**What it showed, in one paragraph.** Every command the README gives exists and does what the README says, in about ten seconds of machine time from `init` to the link. The stop at the press is said plainly, in the same words, by the page ("No presence prompt is available on this machine, so nothing here can approve this write ... that is by design") and by `doctor`'s `presence` check. The errors a newcomer is likeliest to meet, a missing passphrase and a home too long for a socket, each say exactly what to set. What loses a person is in the words between the commands: answers that name steps as actions the command line refuses, three `next` lines that lead three ways from one place, and a first `ready` that looks like a failure. The walkthrough, which the README sends a reader to for "what it should feel like", gave seven commands that do not run as written.

## What was not found

- No command the README gives is missing or misspelled; `export PATH="$PWD/target/debug:$PATH"` is right for a person who did not set `CARGO_TARGET_DIR`.
- The page a person opens is clear and complete: what will be done, where each tool sends, the evidence, each gate as passed or not built, and why nothing here can approve.
- A newcomer who forgets the passphrase or puts the home on a long path is told what to set, in the error itself.

## Not checked

- The press, and everything after it: `ready` saying published, and `call` reading the order. They are the test `crates/anything2mcp/tests/ready.rs`, which stands in for the prompt.
- A Linux desktop with polkit, and Windows and macOS. The Windows guide was read against `ci.yml` and the Linux run, not followed on Windows.
- An MCP client started from the `connect` block.

## Returns

High for a first use of the lens: one walk found one high and six medium findings, none of them visible from the documents alone, and none a fault of safety. The documents are fixed. The rest is two packages of words and small answers, FU1 and FU2. The next gain is from a person, not another reading: the press on a desktop, and the Windows guide followed on Windows (packages 3.6, 5.6, OS5).
