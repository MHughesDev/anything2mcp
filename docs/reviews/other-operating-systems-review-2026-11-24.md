# The other operating systems review, 2026-11-24

One design review round, by [lens 13](../plan/design-review-lenses.md): what quietly assumes one operating system? The first release is for one person's machine on Windows, macOS, or Linux, and nearly all local building and testing happens on Linux. The round read what is newest and has run only on Linux, and the places where a system's rules differ most: decisions 0423 and 0425; the local engine's channel, locks, and lifecycle (`a2m-local`, section 222, `Paths` in `a2m-actions`); the on-disk layout; the field harness and decision 0310; the presence prompt on each system (section 503, decision 0146); the browser's profile and its downloads (decisions 0419 and 0362); the file pack's open and save; the desktop pack's design; and decision 0427. It read code only to check a claim, and changed none.

## Checked and found sound

- **The local channel.** The socket and the pipe each have both checks, the server's of the client and the client's of the server; a pipe always has one instance waiting; the socket's path length is checked against each system's own limit before anything is made; the engine stops on Unix signals and on Windows console events; on Windows the started engine leaves the caller's job where the job allows it, and the record says what happens where it does not.
- **Decision 0423.** The fault was found on Windows and the copied data folder test, which removes the folder, runs in Windows CI; the Linux check of open files is a second proof, not the only one.
- **Decision 0427.** The prepare time was set from the cold Windows start and is the pack's statement, not the kernel's.
- **The browser profile on Windows** is private by the access list the data folder is given at start and its children inherit (decision 0241). The doctor's check of it says `unknown` on Windows, and that is written down.
- **The file pack's text.** Line endings, the byte-order mark, a name held in another letter case, and a file another program locks each have a rule and a test.
- **The desktop pack.** Its design says, row by row, what is built on Linux and written for Windows and macOS, and CI has a job on each of the two against its own stand.

## What this round did not look at

The npm and pip launchers on each system beyond what CI already runs; the netstate readers' per-system gaps, which their crate design lists; the command pack's interpreters on Windows; the sign-in window on macOS and Windows; and long paths on Windows, which no finding here needed but which a deep `A2M_HOME` or a long target name in the browser's own folders could reach. The next gain under this lens is more likely from reading CI's logs on macOS and Windows (OS4 is the first such reading) than from reading more documents.
