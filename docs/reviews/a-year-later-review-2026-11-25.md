# The year-later review, 2026-11-25

One design review round, by [lens 14](../plan/design-review-lenses.md): what will be hardest to change once people depend on it, and is each of those things right? The first release is close, and what it publishes becomes a contract with people and their agents. The round read, with the code beside each to check what is built: the [file formats](../reference/file-formats.md) and the compiler's handling of `schema_version`; the provider manifest and its numbers; the tool naming rule and the lint that holds it; what section 221 says an agent sees in a tool and what `a2m-mcp` sends; the [action catalog](../reference/action-catalog.md), its four faces, and `x-sdk` ([decision 0420](../decisions/0420-the-api-description-says-which-actions-have-a-client-method.md)); the failure classes and codes; the [ledger schema](../reference/ledger-schema.md) and the store's migrations; the on-disk layout after [decision 0432](../decisions/0432-the-runtime-folder-does-not-follow-a-variable-that-differs-between-one-users-processes.md); the vault's envelope and the passphrase route's salt; and the vocabularies of `a2m-core`.

## Checked and found sound

- **The store.** Migrations are numbered, checksummed, and forward only; each crate owns its tables; a store written by migration 0028 opens and migrates (`older_store.rs`), and a half-migrated one is refused. Every column added since says what a row kept before it reads as.
- **The vault's envelope** carries a format number and a cipher id, and an unknown one is refused by name.
- **The provider manifest** carries its own format number and the contract number it was written for, and a build refuses a number it does not read. With every pack compiled in, no plug-in host, and no crate but the product published, the provider contract and the driver interfaces have no outside implementer in the first release; decision 0997 says so.
- **The compiled target's header** states its format and the minimum engine, and a format the engine does not read is refused by name.
- **The target files are strict.** Every map is closed and a word not listed is refused, so an addition is refused by an older compiler with a name, never read wrongly.
- **The REST and local interfaces** are `v1`, and the MCP revisions served are listed in settings.
- **The on-disk layout.** The runtime folder that decision 0432 moves holds only the locks and the socket, which an engine makes again at each start, so the move loses nothing a person kept.

## What this round did not look at

The settings file has no number of its own; its keys are kept by decision 0997 and an unknown key is already refused, which may be enough. A browser profile's folder is named by a digest, and a change to that digest would leave sign-ins behind (not data). The signed bundle of `version.bundle`, the plug-in protocol, and a server's pinned toolsets are not built, and each will need its own number when it is. The package and command names, `A2M_HOME`, and the environment variables are a contract too and were not read. In passing, section 704 said the `toolset.*` and `grant.*` actions answer `action_not_built`; they are built, and that line is corrected.

The next gain under this lens comes from building YL4: until a release is kept, every promise listed here holds only as long as each worker remembers it.
