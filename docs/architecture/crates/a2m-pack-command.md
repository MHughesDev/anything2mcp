# `a2m-pack-command`

The command pack: the `cli` driver over declared programs. A program is started by its absolute path, with an element list built from typed positions, through the kernel's supervisor; it runs to its end; its exit status is read against a declared table and its output is parsed by one declared form. It is never a shell. The pack is designed in [spec section 306](../../spec/3-packs/306-the-command-pack.md); this document says how its crate is put together and what is built.

## Owns

- The `cli` mode, real by [decision 0098](../../decisions/0098-the-cli-mode-is-real-and-a-program-is-a-surface.md), and the surface kind `program`.
- The `commands/` file kind: its schema, its rules, and its compilation into the pack's own section of the plan.
- The lowering of a `cli` binding into `spawn`, `expect`, and `parse` steps, with the pack's own step payload.
- Building the element list a program is started with, checking a program's file before it is started, reading its exit status, and parsing its output.
- The `command`, `command_file`, `powershell_command`, and `binary` finding kinds and the shape of their `found`; the discoverer `binary`, which reads the plain facts of a binary it is handed and starts nothing; the discoverer `help`, with its readers of a fish completion file and a manual page ([decision 0284](../../decisions/0284-the-command-packs-scout-reads-a-fish-completion-file-and-a-manual-page-it-is-handed.md)) and of a PowerShell XML help file and a module manifest ([decision 0290](../../decisions/0290-the-command-packs-scout-reads-a-powershell-help-file-and-a-module-manifest-as-data.md)) handed to it; the drafting rules from `command` findings and from `powershell_command` findings to `commands/` drafts.

It must never: start a program except through the supervisor it is handed; build a command line; let a value become an option, a program, a path, or the name of a file of arguments; start a shell, an interpreter, a script, or a program whose work is to start another, except as a fixed pair or in a command of the provider's closed list that runs no code but the program's own; start a command where nothing may be written; start a command that writes from a step that is no commit point; retry; parse standard error for values; give a program a variable its file does not list; put a secret in an argument; cut, join, or decode text a program printed and show the result without the redactor having seen it.

## What it registers

| Mode | `cli`, archetype command; one write holds the surface |
| Surface kind | `program`. Fields: `path` (the address; the program's absolute path) and `digest` (optional; one digest that holds on every machine). Both are declared as the surface's program, so the compiler puts the path of every environment in the plan's declared programs ([decision 0124](../../decisions/0124-the-plan-declares-a-surfaces-programs-and-a-schema-checks-run-time-values.md)) |
| Step kinds | `spawn`, `expect`, `parse` |
| Verbs | `read`, `list`, `search`, `create`, `update`, `delete`, `call` |
| File kind | `command`, in `commands/`, for `program` surfaces |
| What saves, for the compiler | `Lowering::commits`: `spawn` is `AsDeclared`, because the same kind starts a command that reads and one that writes, which is the command's declared `effect`; the lowering marks it `commits` exactly for a command that is not `read`, and the driver refuses either mismatch. `expect` and `parse` are `Never`. No kind always saves, so the manifest lists no `commit_steps`. `Lowering::least_effect`: `write` for `create` and `update`, `irreversible` for `delete`, `read` for the rest (a `call` is held to its command's declared effect) |
| What can describe a write | `FileKind::writes`: a file does when any command in it has an `effect` other than `read`. A JSON field that is not required; every named group of a pattern that holds an alternation, an optional or repeated part, or a counted repeat (a group is otherwise certain, and the rule says more than is so, never less). A table's columns are always certain. The lowering writes them into each step's payload as `absent`, left out of the text when empty, and the lowering reads them back from the `parse` steps. The driver is unchanged: it already returns `null` for such a value |
| Binding fields | `command` (a command's name), `args` (param to expression), `read_back` and `lookup` (each `command`, `args`, and `key`: the params that take the parts of the record's key, in order) |
| Finding kinds | `command`; `command_file`, one for each file handed to the discoverer, which no drafting rule covers; `powershell_command`, one for each command a handed PowerShell help file describes; `binary`, one for each binary handed to the discoverer `binary` |
| Discoverer, describer | `help`, sources `live_system` and `artifact`, reading the files `completions`, `manual`, `powershell_help`, and `module_manifest`; its describer counts the commands, the handed files, and the PowerShell commands, and keeps every word a program or a file said apart, as untrusted |
| Second discoverer | `binary`, source `artifact`, at most `inferred`, reading the one file `binary` with a bound of 256 MiB; it starts nothing, and its port is never asked for a step. Its describer says what kind of file each finding is, for which system, and how many imports and exports, and keeps the library names apart, as untrusted |
| Drafting rules | From `command` findings to `commands/` files; from `powershell_command` findings to `commands/` files that declare Windows PowerShell's fixed pair, one command for each parameter set |
| Lint rules | `command.shell_program` (error) and `command.write_exit_declared` (warning), as rules that look across files. The rules below are checked where a file is compiled, under the pack's own codes |
| Effects | `plan_programs = true` and no program of its own; one write root, `command_runs`; no network |
| Settings | `packs.command.max_timeout_ms` (default 600000) and `packs.command.max_output_bytes` (default 16 MiB): ceilings over what a target's files state. `packs.command.admin_groups` (protected, a list, safer with fewer; default empty): the numeric ids of Unix groups whose write counts as the administrator's. ### Rules checked when a file is compiled

| Code | Rule |
| --- | --- |

| `command.text_param_open` | A text param has an anchored pattern, or its field type is a `choice` |
| `command.param_type_unsupported` | A param is text, a whole number, an exact number, a truth value, or a date |

| `command.secret_variable`, `command.secret_literal`, `command.secret_argument` | No variable named for a credential is set or copied; no variable's value and no element looks like a credential; no flag named for a credential carries a value, as a literal or as a param. A name is one for a credential by its last word (`TOKEN`, `PASSWORD`, `SECRET`, and the like) or its last two (`API_KEY`) |
| `command.arg_malformed`, `command.param_unknown`, `command.param_unused` | An argument entry is one of the forms of section 306, holds no NUL character, names a declared param, and every declared param is carried |
| `command.exit_malformed`, `command.exit_changed`, `command.no_ok_exit` | An exit status is a whole number with a meaning; a command adds statuses and changes none; one status means `ok` |
| `command.output_malformed` | One output form, with its columns or fields named once; a JSON path (`at`) goes only with a document, not with `lines: true` |
| `command.absent_empty_needs_read`, `command.own_server_malformed` | Only a read declares `absent: empty_output`; an own server is a host name with no scheme, path, or space ([decision 0399](../../decisions/0399-the-command-pack-reads-silence-as-absent-a-path-into-nested-output-and-a-programs-own-server-as-no-hazard.md)) |
| `command.assigns_unknown` | `assigns` names one declared field of the output |
| `command.reaches_without_hazard`, `command.hazard_needs_irreversible` | A command that reaches outside declares a hazard, and a command with a hazard is `irreversible` |
| `command.env_malformed`, `command.limit_malformed` | A variable's name and value, and a limit, are well formed |
| `command.state_dir_not_built` | `{session.state_dir}` is refused until it is built |
| `command.script_malformed` | A file that declares `program.interpreter` declares no help form and every command names `script`, with a path inside the target's folder; a file that declares none names no script. A fixed argument of the interpreter is checked as `command.code_flag` and `command.arg_malformed`, a script's digest as `command.digest_invalid`. The lint `command.shell_program` holds the interpreter and its fixed arguments to the provider's closed table, `interpreter_form`: the POSIX shell (`sh`, `dash`, `bash`) with none, Python with `-I`, Windows PowerShell with `-NoProfile -NonInteractive -ExecutionPolicy Bypass -File`, `osascript` with none; every other interpreter, and every other form, is refused, and the command interpreters that read their whole line as code (`cmd`, `command`, `wscript`, `cscript`, `mshta`) and batch files are refused by name ([decision 0250](../../decisions/0250-one-check-of-who-may-change-a-program-and-the-mcp-packs-local-server-on-windows.md)) |
| `command.unknown_command`, `command.effect_mismatch`, `command.read_back_writes`, `command.param_unbound`, `command.stamp_missing` | A binding names a defined command whose effect fits its verb and its operation; a read-back or lookup command is `read`; every required param has a value; a `stamped` operation's command and lookup both carry the stamp |

**A parameter named as a secret is never drafted as an input.** The drafter asks the compiler's own test (`names_a_secret` in `a2m-files`) of each flag and each place of a usage line, and of each parameter a PowerShell help file shows, as the program writes it and as the param it becomes. An optional one is left out of the draft; a required one makes the arguments of that command (of that parameter set, for PowerShell) an open question. A command's file has no description and no output is drafted, so the left-out name is told nowhere in it. The compiler's refusal of a secret in a file does not change ([decision 0302](../../decisions/0302-a-field-named-as-a-secret-is-never-drafted-as-an-input-or-an-output.md)).

## Interface

```rust
/// The one call the product crate makes.
pub fn register(builder: &mut RegistryBuilder);

/// The pack itself, for a caller that builds a registry by hand.
pub struct CommandPack;                 // implements `Pack`
pub const MANIFEST: &str;               // the embedded manifest

/// The names and failure codes, for the crates that match on them.
pub mod codes {
    pub const PACK: &str = "command";
    pub fn mode() -> Mode;              // `cli`
    pub const SURFACE_KIND: SurfaceKind;  // `program`
    pub const FILE_KIND: FileKindName;    // `command`
    pub const SPAWN: StepKind;  pub const EXPECT: StepKind;  pub const PARSE: StepKind;
    pub const ALL: &[(FailureClass, &str)];   // every code the manifest declares
    pub const PROGRAM_MISSING: FailureCode;   // and one constant for each code below
    pub mod row { pub const PROGRAM_MISSING: CodeEntry; /* one row per code */ }   // what a failure is made from
}
```

Everything else is private. The driver is reached through `Registry::driver`, the discoverer through `Registry::discoverers_for`, and the compiler's parts through `Registry::compiler_set`.

**The compiled section** (format 1) holds one entry for each program block and every command by name. Two files that say the same of one program share one entry, so its version is asked once. **The step payload** is `{"step":"command","key_params":[...],"one":bool}` for a step of a command, whose name is the step's reference, and `{"step":"probe","program":n,"probe":{...}}` for a declared help or version form.

**How a binding lowers.**

| | `act` | `confirm` | `read_back`, `lookup` |
| --- | --- | --- | --- |
| A read (`read`, `list`, `search`, and `call` of a `read` command) | `spawn`, `expect`, `parse` | None | None |
| A write | `spawn`, marked `commits` | `expect`, `parse` | `spawn`, `expect`, `parse` of the named `read` command, with `expect` and `parse` marked `lookup` |

A step's time limit is its command's. A lookup's `parse` must find exactly one record: none is absent, more is `possible_commit`/`ambiguous_match`.

**What the driver checks again.** The lowering marks the `spawn` of a command that writes as the commit point, and no other step. The driver does not take its word: `spawn` starts a command that writes only when its step is marked `commits` and belongs to a record of the ledger, and a command that reads only when its step is not. The handle lets a `commits` step through only with the ledger's token, so the two checks together are "a write is started only with the ledger's token" ([decision 0140](../../decisions/0140-the-command-pack-after-its-safety-audit.md)).

**Who can replace the program.** `prepare` walks the declared path name by name, as the system does at a start: every folder entered, every link, the folder each link is in, and the way to where each link leads. On Unix a folder must belong to the engine's user or the administrator and be writable by nobody else; a group's write is allowed only for a group `Trust` holds (on macOS the group 80, and the groups `packs.command.admin_groups` names); where the sticky mark stands in for that, the entry itself must be theirs. Access lists beyond the mode are not read there. The walk is the provider's (`check_program`, in `a2m-provider`'s `src/supervisor/program.rs`), shared with the MCP pack since [decision 0250](../../decisions/0250-one-check-of-who-may-change-a-program-and-the-mcp-packs-local-server-on-windows.md); this pack calls it with the groups of its setting. On Windows (`src/supervisor/program/windows.rs` of the provider) the owner and the discretionary access list of the drive's root, of every folder, and of the file are read; only the engine's user, the local system account, the Administrators group, and the trusted installer service may own them or hold a right that changes what the path names, by the table of [decision 0216](../../decisions/0216-the-command-pack-on-three-systems-the-administrators-group-and-a-script-the-target-keeps.md); a reparse point on the way, a share, and an unreadable list are refusals. The program is then started by its declared path, so it sees the name it was declared by: with the whole chain closed, nobody else can change what that path names between the check and a start.

**A fixed pair.** A program whose every `commands/` file on its surface declares `program.interpreter` is checked as an interpreter: every check above holds, and the name list does not refuse it. At each `spawn` of a command, its `script` is read from `targets/<target>/` in the run's project folder (`CheckedPaths::project`), its digest checked, its bytes written to a fresh folder of the run's own under `command_runs`, read back, and checked again, and the copy, its folder, and every folder on the way to it are then held to the provider's check as a file the engine wrote (`ProgramRole::Script`): another user who could write any of them is refused as `program_path_unsafe` before the interpreter starts. `command_runs` and each run's folder are made the engine's user's alone (`CheckedPath::create_private_dir` and `create_private_dir_all`: mode `0700`, or a protected access list on Windows); one that was there already is not changed, and the check refuses it if others may write it. The interpreter and its fixed arguments must also be the one form of the closed table, by the declared path and by the file it leads to, or `prepare` refuses with `program_path_unsafe` ([decision 0250](../../decisions/0250-one-check-of-who-may-change-a-program-and-the-mcp-packs-local-server-on-windows.md)); the elements are the fixed arguments, the copy's path, and the command's typed elements. A command on an interpreter with no script, or a script on a program that is no interpreter, is refused as `step_not_usable` whatever the plan says. The compiled section holds `interpreter` on a program and `script` (`path`, `digest`) on a command, each written only when present.

**A program that runs only its own code** (`src/own_code.rs`, [decision 0349](../../decisions/0349-the-two-steps-of-decision-0299-as-built-a-closed-list-of-commands-and-the-javascript-runtime-as-a-launcher.md)). A program the name list refuses, whose declared path has a row of the provider's closed list (`runs_its_own_code` in `a2m-provider`) and whose files declare no interpreter, is started only in the forms of its row: every command's `args`, the version check's, and each help form's must be one of them, element for element, with values only after `--` where the form takes names; every command is `read` with no script; the file sets and passes no variable. `compile_file` reports a break as `command.shell_program`, and the lint of that name lets such a surface through only then. `prepare` checks the same against the row of the declared name and of the file the path leads to before it starts anything, as `program_path_unsafe`, then checks the program as `ProgramRole::OwnCode`.

**Text a program printed.** The redactor sees a stream whole before anything is cut from it, and sees the result again after anything is joined or decoded: the message a failure quotes from standard error is redacted whole, cleaned of control characters other than line breaks (and, where cleaning would put a secret together, flattened and redacted again), and only then cut, as whole lines, the last that fit the bound, with a line that says how many earlier lines were left out ([decision 0399](../../decisions/0399-the-command-pack-reads-silence-as-absent-a-path-into-nested-output-and-a-programs-own-server-as-no-hazard.md)); values are redacted after a form is read as well as before, because a JSON escape is not the secret until it is decoded; a stream the supervisor cut is never shown. The redactor matches a secret as the program printed it; a program that prints one in pieces that are never joined is beyond it.

**What `act` returns.** `spawn`: two captures, `stdout` and `stderr`, redacted whole. `expect`: nothing, or absent for a lookup whose exit status means `absent`. `parse`: the values of the declared output form, and the assigned key when the command declares `assigns`. Rows come back as the value `rows`, a list of records, and each declared field as a list of its values in row order, which is what an operation's list outputs are read from ([decision 0399](../../decisions/0399-the-command-pack-reads-silence-as-absent-a-path-into-nested-output-and-a-programs-own-server-as-no-hazard.md)). A command that declares `absent: empty_output` and printed nothing answers absent. A JSON field is typed by its declared kind; a table cell and a pattern group are text, for the engine to normalize by field type.

**What a `command` finding holds.** Canonical JSON: `name`, `about`, `usage`, `platform`, `digest`, `version`. The finding is at `discovered` with the limitation `not_exercised`: the help listing the command is what was observed. What the usage line's parts mean is read from it by the drafting rule and is not observed. Where a handed file states options of the command, the finding also holds `options` (each option's `flags`, `said`: one entry for each of `help`, `completions`, and `manual` that states it, with `takes` (`value`, `nothing`, or `not_stated`), `value`, and `about`, and `disagree`), and is then `inferred` from `artifact`, derived from the files' findings; without, `options` is left out and the text is what it was before.

**What a `command_file` finding holds.** Its subject is the handed file, by its digest, as `fish_completion` or `manual_page`; it is `inferred` from `artifact`, `complete` only when nothing was left unread. Canonical JSON: `name` (`completions` or `manual`), `form` (`fish`, `man`, or `mdoc`), `read`, `unread` (a count by reason), `program_options`, and `unlisted` (the words of commands it speaks of that the help does not list).

**Reading the files** (`src/fish.rs`, `src/manual.rs`, `src/metadata.rs`). Both are read before any help form starts, redacted whole, and never run; which lines and entries are read, and the bounds, are in decision 0284.

**The PowerShell files** (`src/maml.rs`, `src/psd1.rs`, `src/powershell.rs`). A help file handed as `powershell_help` and a manifest handed as `module_manifest` are read as data with the others, before any help form starts: no PowerShell is started, no module imported, nothing evaluated. The help file is parsed with `quick-xml` into a bounded tree, a document type is refused, and only characters and XML's five entities are read; an element, an attribute, or a value it does not know inside a part it reads leaves that command unread, counted by reason. The manifest is read as PowerShell's data language, and a key whose value is not literal is counted unread. Each makes a `command_file` finding (`form` `maml` or `psd1`; a manifest's also holds `exported` and `version`, left out of the text when empty). A `powershell_command` finding holds `name`, `synopsis`, and `sets`, each parameter with `name`, `type`, `switch`, `required`, `position`, `pipeline`, and `about`; it is `inferred` from `artifact`, its subject the help file with the command's name as the part, and derived from the help file's finding. Its draft names Windows PowerShell's one form under `program.interpreter`, gives each parameter by name, and leaves the script, the digests, the effect, and the output as questions. The bounds and every rule are in decision 0290.

**The plain facts of a binary** (`src/binary.rs`). A file handed as `binary` is read as bytes, redacted in every text it gives, and never run, loaded, or handed to the system's loader. A first look at the magic number sorts it into ELF, PE, Mach-O, or fat Mach-O; anything else is `binary_kind_unknown`. Then the headers are read as numbers by this crate, with no read past the end: the extent each header declares (program headers and segments, section headers and sections, the PE section table and the certificate table, the Mach-O load commands, segments, and signature, a fat file's slices) must lie inside the file, or the stop is `binary_truncated`. `object` then gives the processor, the kind, the needed libraries, and the imports and exports (each list cut at 2,000, with the total kept); a table it cannot read is counted in `unread`, never guessed. This crate reads what `object` does not: a PE file's version resource (`VS_VERSIONINFO`, the fixed versions and the first string table, at most 64 strings), its manifest (the assembly identity and the requested execution level, read with `quick-xml`, which refuses a document type), and the entitlements of a Mach-O signature (the keys of the top-level dictionary). The resource tree is walked three tables deep with the tables on the way kept: a table that is reached again from below itself is `binary_cyclic`, as is a fat slice that starts at the fat header or is itself fat; a tree deeper than three levels, a load command that is smaller than its header, and any other table `object` refuses are `binary_malformed`. A Mach-O signature gives the identifier, the team identifier, and whether it is ad hoc, from the code directory; a PE file's certificate table gives only that it is there and how large it is, because who signed it is inside a CMS structure this slice does not read, and the finding says so. A list cut at 2000 entries (libraries, imports, or exports) is reported in the report's `bounds_hit` as `listed`, never as `bytes`: `bytes` is the bound on the size of the file read, and this is a bound on what one finding holds. The finding is `inferred` from `artifact`, `not_exercised`, and with `unverified_component` where a signature was seen, because nothing was checked against anything.

### After the kernel's second pass (decisions 0161 and 0162)

- Every step input is built with `StepInput::new` and `for_record`. A `spawn` and a probe push the `acting` capture: `means` the command (or the probe) and how it ended (its status, or `signal`); `measured` the byte counts. Five runs of one read give the same `means`, held by a test.
- A program's error output is carried by `StepFailure::with_said`, redacted, cleaned of control characters, and redacted again before it is cut. The failure's sentence no longer quotes it.
- `Lowering::evidence` returns `acknowledged` for an operation declared `irreversible`, with identity `none`, whose binding names no `read_back`, and whose act saves: the fixture's `catalog_push`. An operation with an identity and no `read_back` is left to the compiler's refusal. A binding that names a `read_back` keeps it.
- `delete` is `irreversible` in `least_effect`. **Not done:** a command file's effect that is an open question still does not count as a write in `FileKind::writes`. Counting it makes the pack's own drafter refuse every draft it makes (each leaves `effect` as an open question), and the test of drafting expects the drafts to be written. See the report of the package.
- Keys: a param that takes a part of the record's key, given no key, is looked for among the step's own values, and when it is not there the step stops unsent, `input`, `schema_invalid`.

## Used by, and uses

| Used by | For |
| --- | --- |
| The product crate | `register`, once |
| `a2m-engine`, through the handle | The steps of a `cli` binding |
| `a2m-actions` | The compiler set and the discoverer, through the registry |

It uses the supervisor it is handed in `PrepareContext` for every start; the roots of its own manifest for the run's folder; the redactor of its `PackContext` on both streams; and nothing of the engine, the scheduler, the store, or another pack.

## State

A `Session` behind `Prepared`, for one run on one surface: the decoded section, the program's path and the digest it had when it was checked, the scoped supervisor, the posture, the run's folder, and how the last start ended, kept between `spawn`, `expect`, and `parse`. Every `spawn` forgets the start before it first, so a step never reads an earlier start. Nothing is kept between runs. The run's folder is made in `prepare` under a name that was not there, is seen to hold nothing, and is removed in `release`; a folder of that name left by an earlier engine is never used, emptied, or removed.

## Open points

- A value is written in one canonical form for its kind: a whole number in digits, an exact number as its plain text, a date as `YYYY-MM-DD`. Writing a value as its field type's `format` shows it is not built.
- An exit status that a developer declares to mean nothing changed is believed. The publish gates are to check it against the test stand, as section 306 says; nothing in this crate does.
- A stream that passes its ceiling does not end the program: the supervisor reads on and drops, and the driver names the failure when the program has ended.
- The version is asked once in every `prepare`, not once for a lease.
- The folder of a run is removed file by file and then as an empty folder; a folder a program made inside it is left, and reported as an incomplete cleanup.
- What the kernel could not give the pack is listed in [decision 0099](../../decisions/0099-the-command-pack-as-building-it-settled-it.md).
- The list of shells, interpreters, and programs that start another is a net for a mistake and is not complete: many programs can be told to run another through an option of their own. The same holds for the names of flags that run their value; a cluster of one-letter flags, such as `-xc`, is not recognised. The review of a target's files is what holds beyond the lists.
- A value joined to its flag is not checked for a leading `@`: whether a flag reads its value as the name of a file is the program's own, and the param's pattern is what guards it.
- A literal that looks like a credential is found by its look, a long run of letters and digits; a key written with other characters passes.
- A run's folder left by an engine that ended before `release` stays until a person removes it.
- The check of a script's copy walks every folder above `command_runs`, the engine's data folder's included. On a machine whose folders are made writable by the user's group by default, a kept script is refused until those folders are closed or the group is named in `packs.command.admin_groups`. The product crate makes `command_runs` with the process's defaults; it should make it private ([decision 0250](../../decisions/0250-one-check-of-who-may-change-a-program-and-the-mcp-packs-local-server-on-windows.md)).
- The driver redacts with the pack's redactor. The redactor of `PrepareContext` is a borrow that ends with `prepare`, so it cannot be used in `act`; if the two ever differ, the provider contract must hand a step its redactor.
- A script is found in `targets/<target>/` of the run's project folder: the action registry knows the same layout. The provider contract should hand a run its target's folder, so that the layout is known in one place. A run with no project folder cannot run a script.
- A program started by a path whose every folder and link is closed to other users can still be changed by the engine's own user between the supervisor's digest and the start. Starting the opened, checked file is the supervisor's to do, and is the open point of section 306.
