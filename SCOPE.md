# Scope: what Anything2MCP does, and what it does not

This page shows both sides: what the product does and answers for, and what it does not. It was last checked as a whole against the code and the decisions on 2026-11-18; the lines on web pages, drift, and what waits until after the first release were added on 2026-11-24.

**This page describes. It does not rule.** A line under "does not" says where the product stands today and why. It is never by itself a reason to turn an idea down, and it changes by being edited when the product grows ([decision 0230](docs/decisions/0230-the-scope-is-written-down-on-both-sides-and-describes-without-ruling.md)). The only things that bind are the ten rules in [AGENTS.md](AGENTS.md) and the owner's decisions.

Every "does not" carries its kind:

| Kind | Meaning | Who changes it |
| --- | --- | --- |
| **Rule** | It follows from one of the ten rules or an owner decision, named beside it | The owner |
| **Choice** | A design choice in force today | Any agent, with evidence and a decision record |
| **Not yet** | Nothing stands against it. It is not built, or not proven | Whoever builds it |

"Built" below means proven by tests against a test stand. One copy test has been run, on 2026-11-23: reads of one HTTP service of existing software that the project ran itself, which worked in part and made seven findings ([copy test results](docs/reviews/field-tests.md)). No write has been tried against existing software, nothing has been tried against a system the project does not run, and nothing is published to a package registry.

## What happens when a tool runs

| It does | It does not, today | Kind |
| --- | --- | --- |
| Runs a compiled target. The same input against the same system takes the same steps | Call a model, or improvise when a page or an answer has changed. It stops with a named failure | Rule 1 |
| Stops when something is not as described | Guess at an unknown control, platform, or response | Rule 7 |
| Records a write before making it, reads the value back, and compares. A lost answer is reconciled before anything is sent again | Call a write verified when nothing can be read back. It ends as "accepted by the system, not read back" | Rule 3 |
| Marks text that came from a wrapped system as untrusted data at every door | Filter or rewrite what a system said | Choice: a filter would be a guess and would hide data a person needs |
| Keeps to declared rates and retries nothing a declaration does not allow | Repair a tool at run time when the system changed. Redrafting is a build-time act | Rule 1 |
| Runs a binding in shadow beside the verified one on a live read, compares the two answers, reports the comparisons (`shadow report`), and lets a person at the machine promote the shadow binding once it has matched the verified binding on the threshold's count of distinct inputs, in each environment the evidence must come from (decision [0251](docs/decisions/0251-the-evidence-for-promoting-a-shadow-binding-says-what-it-covers-and-a-shadow-costs-what-it-says.md)) | Run a shadow of a write. Shadow more than the first call of an operation in a job: a choice, so that a shadow does not double the load on the person's system | Not yet for a write; Choice (decision 0251) for the first call only |
| Answers when it is asked: a call, its progress, and a run's events as a stream. An agent can ask for a watch (`watch.create`): a published read repeated at an interval, which its person confirms on the engine's page (`watch.confirm`). It reads what the watch recorded with `watch.changes`: digests only, each with its check's run. A watch ends at its end whatever its state; its share of a surface's budget is held at confirmation and at each check; and a check's records come from its run's own result (decisions 0247, 0262, [0283](docs/decisions/0283-watches-reach-an-agent-through-the-registry-and-their-person-confirms-each-on-the-page.md)). Two watches of one read and input share a run, and each compares its result against its own baseline: a check's run is cancelled only when a watch check opened it and no other check rests on it, so ending one watch never cancels the run another rests on, every watch on a shared run that waits for a sign-in pauses for it, and a run a check only joined, such as the person's own call, is never cancelled for a watch (decisions 0285, [0287](docs/decisions/0287-the-last-check-under-way-on-a-run-a-check-opened-cancels-it.md)). A watch may carry a condition over the read's result, shown to its person before they confirm; the first check on which it holds records `condition_met` and ends the watch, and a check on which it cannot be answered is a gap, never taken as false ([decision 0291](docs/decisions/0291-a-watch-ends-when-its-condition-holds-on-a-checks-own-result.md)). A read that declares its records over its list outputs, with a record key, is compared record by record: `added`, `changed` with the outputs that differ, `unseen` once when a record leaves the view, and `removed` only between two checks whose drivers stated they returned every record, which the data pack's list read does; an empty answer after records were seen removes nothing ([decision 0472](docs/decisions/0472-a-read-declares-its-records-over-its-list-outputs-and-a-driver-states-whether-it-returned-every-record.md)). Each watch is an MCP resource, read with `resources/read` and subscribed to with `subscriptions/listen`, which tells an agent by the resource's URI alone that the watch recorded a change; and a REST change stream, `GET /api/v1/watches/{watch_id}/changes` ([decision 0478](docs/decisions/0478-a-watch-is-an-mcp-resource-of-watch-changes-and-its-changes-are-followed-without-a-decision-for-each-wait.md)) | Keep a watch's history for less time than its runs: retention of watches waits on retention of runs. Report a removal from a read whose driver cannot tell whether the system held more, such as an HTTP read: its records are `unseen`, never `removed`. Start a run because something changed: a change is reported and never acted on. Leave alone the person's own identical call that was handed a run a watch check opened, when that watch ends or the run rests: the ledger keeps no mark that a call was handed an earlier run ([decision 0285](docs/decisions/0285-two-watches-of-the-same-read-for-one-person-share-a-run-and-ending-one-never-cancels-a-run-another-rests-on.md), point 5) | Not yet for the first, the second, and the fourth; a choice for the third (decision 0234) |
| Marks the knowledge a drift was seen in, and refuses every tool that relies on it before anything is sent; a canary finds a drift, on a schedule its person confirmed, or as a watch's check, and its pass lifts the mark (decisions [0380](docs/decisions/0380-a-drift-marks-the-knowledge-it-was-seen-in-and-stops-every-binding-that-relies-on-it.md) and [0482](docs/decisions/0482-a-canary-runs-on-a-schedule-its-person-confirmed-and-sends-only-a-published-read.md)); a stopped tool is listed as unavailable, and refused when called (package 9.1a) | Run a canary nobody confirmed, or one a publish or a target's `drift_risk` starts by itself. Propose a repair | Choice, for the first: a canary nobody confirmed sends requests to a person's system that nobody agreed to, so only the person it acts for starts one, and it sends only a published read (decision 0482). Not yet, for the second |
| | Compare what a system's description says with what a capture saw; tell an MCP client of a change it did not ask about; measure the split of a call's time. Each waits until after the first release, with its reason in [decision 0397](docs/decisions/0397-what-the-first-release-needs-of-the-packages-left-and-what-waits-until-after-it.md) | Not yet |
| Lists up front only the actions that are built; one that is not answers `action_not_built` by name | Roll a version back, compare two versions, set a setting, fetch a browser, export a trace, or any other of the 23 actions [decision 0397](docs/decisions/0397-what-the-first-release-needs-of-the-packages-left-and-what-waits-until-after-it.md) names | Not yet |
| Runs a call when it is made | Run at a set time, or start a run because something happened | Not yet |
| Runs a pipeline over many records of one target, with a checkpoint for each record | Join operations of two targets in one pipeline; undo the first when the second fails; carry on past a record the system refused | Not yet for the first; choice for the second and third (safe before easy) |
| Takes a file a pipeline reads, from a folder the person allows | Hand a file back as a result, or send one to a system | Not yet |
| Takes and gives times in UTC or at a fixed offset | Take a named time zone with daylight saving | Not yet |
| Requires, when a target is compiled, that every free-text output from a system has a field type marked untrusted; keeps a system's words in a failure apart, bounded, and made neutral | Bound and make neutral a marked field in a tool's result, or tell the calling agent in the tool's schema which fields hold a system's own words: nothing after the compiler reads the mark (section 502 states both; a known gap) | Not yet |
| Writes a folder's entries only through the folder held from the root down, and removes a file only while its name still holds the file that was read (decision [0272](docs/decisions/0272-the-file-packs-folder-writes-act-through-a-held-folder-after-a-second-reader.md)) | Stop a folder handle being moved away whole on Linux and macOS: it is seen and reported | Not yet |

## What it answers for, and what stays with others

| It answers for | It does not answer for | Who does |
| --- | --- | --- |
| That what it wrote is what the system then holds, or an honest statement that this could not be read back | Whether the wrapped system is right: its rules, its bugs, its data | The system's owner |
| Working only through access the person already has, and stopping at a block | Whether the person may use, inspect, or wrap a system, or look at a network | The person |
| Noticing that a system changed, and stopping | Keeping a tool working when the system changes | The developer |
| Never sending an irreversible operation twice, and saying it is irreversible before approval | Undoing what a system did | The person and the system's owner |
| A record of what it did and proved, kept on the person's machine | Being the record of the business: it is not a backup, an archive, or a copy of the system's data | The system's owner |
| A declared hazard and range, and a person's approval, on anything that can hurt someone or damage equipment | Being the only protection there. It is not a safety system | The device's maker and the person |
| Pinning other people's code by path and digest and holding it to the contract at the boundary | What that code does inside its own process: a plug-in, a kept script, a local program, an upstream server | Whoever wrote it, and the person who switched it on |
| Keeping data on the machine and giving an audit trail of its own acts | Whether the person's use complies with rules about personal data, finance, health, or records | The person and their organization |
| Treating what a network or a system announces as a claim, never a fact | Facts it cannot see: the machine's clock, a forged announcement, a name that resolves elsewhere tomorrow | The person and the network's owner |
| Stopping by name when a system refuses or is down | The wrapped system's availability, limits, and bills | The system's owner and the person |

All of the lines in this last table are **choices** unless a rule is named elsewhere on this page. They say where responsibility lies today. They are not a fence around what the product may become.

## Keeping this page true

When a change makes a line here untrue, the line is edited in the same change. When this page and another document disagree, one of them is out of date. An idea that a line here seems to rule out is weighed by its kind: a rule goes to the owner as a Proposed record; a choice or a "not yet" is open.
